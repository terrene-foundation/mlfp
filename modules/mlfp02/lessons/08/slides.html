FeatureEngineer


import polars as pl
from kailash_ml import FeatureEngineer, FeatureField, FeatureSchema
from shared.mlfp02.ex_8 import load_hdb_resale

df = (load_hdb_resale().with_row_index("id")
      .with_columns(pl.col("transaction_date").cast(pl.Datetime)))
schema = FeatureSchema(name="hdb", entity_id_column="id", features=[
    FeatureField("floor_area_sqm", "float64"),
    FeatureField("lease_commence_date", "int64"),
    FeatureField("transaction_date", "datetime")])

fe = FeatureEngineer(max_features=10)
gen = fe.generate(df, schema, strategies=["temporal", "interactions"])
# + transaction_date_month/_dow/_hour, floor_area_sqm_x_lease_commence_date
best = fe.select(gen.data, gen, target="resale_price", top_k=3)
print(best.selected_columns)
Pattern: domain knowledge decides which features. The engine handles how. select() ranks by tree importance: sanity-check it (an _hour column is constant for monthly dates).

FeatureStore: point-in-time correctness


import asyncio
from datetime import datetime
from shared.mlfp02.ex_8 import (build_schema_v1, compute_v1_features,
    create_feature_store, load_hdb_resale, materialize_features,
    validate_v1_features)

df, _ = validate_v1_features(compute_v1_features(load_hdb_resale()))
schema = build_schema_v1()   # a kailash_ml.features.FeatureSchema

async def store_then_read(when):
    fs = create_feature_store()   # FeatureStore(DataFlow(...))
    await materialize_features(fs, schema, df)
    return await fs.get_features(schema, timestamp=when)

# Features as of 1 Jan 2023: rows stamped later never come back
snap = asyncio.run(store_then_read(datetime(2023, 1, 1)))
🔵 Theory: Point-in-time correctness prevents data leakage in time-series problems.

Step 1: Load and profile

                                validate_v1_features)

Validation drops sentinel prices (SGD 10, SGD 9M) and impossible leases before any statistic is computed.

Step 2: EDA


import polars as pl

cols = ["floor_area_sqm", "storey_midpoint", "remaining_lease_years"]
for col in cols:
    r = df.select(pl.corr(col, "resale_price")).item()
    print(f"  {col}: r = {r:.3f}")
# → floor_area_sqm 0.910; storey_midpoint 0.009; remaining_lease_years -0.008

Shortlist predictors with a domain rationale; correlation is a first look, not the test.

Step 3: Engineer + store features


import asyncio
from shared.mlfp02.ex_8 import (build_schema_v1, create_feature_store,
                                materialize_features)

# storey_midpoint and remaining_lease_years were engineered in Step 1

result = asyncio.run(store_v1(df))

Step 4: Model


from shared.mlfp02.ex_8 import fit_ols, prepare_design_matrix

X, y, names = prepare_design_matrix(df, cols)   # [1, X], nulls dropped
fit = fit_ols(X, y)                              # Lesson 2.5 normal equations
print(f"R²: {fit['r2']:.3f}   adj R²: {fit['adj_r2']:.3f}")   # 0.828  0.828
print(f"F: {fit['f_stat']:,.0f}")                             # 75,042

Step 5: Hypothesis tests


from shared.mlfp02.ex_8 import format_p

for name, b, t, p in zip(names, fit["beta"], fit["t"], fit["p"]):
    print(f"  {name}: beta = {b:+,.0f}  t = {t:.1f}  p: {format_p(p)}")
# floor_area_sqm: +9,096  t = 474.4  p: < 1e-300
# storey_midpoint: -24 (p = 0.54); remaining_lease_years: +7 (p = 0.84)

Report effect sizes alongside p-values: "Each extra square metre adds about SGD 9,100 to the price (95% CI SGD 9,060–9,130)." Storey and lease show no effect once area is in the model.

Step 6: Report

  • Summary: what did you find? (2-3 sentences)
  • Key predictors: effect direction, magnitude, significance
  • Model fit: $R^2$, adjusted $R^2$, $F$-statistic
  • Limitations: missing data, selection bias, confounders
  • Recommendation: what should the stakeholder do?
🟢 Foundations: A non-technical reader should understand every sentence in the report.

Three mistakes to avoid

1. Feature leakage from the future
2. Features without domain rationale
3. p-values without effect sizes
