Lesson 5.2 CNNs and Computer Vision

Convolutional neural networks turned computer vision from a hand‑crafted feature‑engineering discipline into a learning problem. This lesson walks the architectural lineage — LeNet (1998), AlexNet (2012), VGG (2014), ResNet (2015), Squeeze‑and‑Excitation blocks (2017), and Vision Transformers (2020+) — and shows exactly how to build a modern residual CNN with SE blocks in PyTorch, then export it to ONNX with OnnxBridge.

Why Convolutions?

Suppose you want to classify a 224×224 colour image. Flattened it is a 150,528‑dimensional vector. A single fully‑connected layer mapping that to 1000 hidden units needs 150 million weights — and it would not generalise, because it treats a pixel in the top‑left corner as completely unrelated to the same pixel moved one column right.

Real images have two properties no MLP can exploit:

  1. Local structure. Adjacent pixels are strongly correlated; distant pixels are not. A good feature detector should only look at a small local window.
  2. Translation equivariance. A cat is a cat whether it is centred, shifted left, or shifted right. The same feature detector should work at every position.

A convolution enforces both by using the same small filter across every position in the image.

Convolution arithmetic

Given an input of width $W$, filter size $F$, padding $P$, and stride $S$, the output width is:

$$W_{\text{out}} \;=\; \left\lfloor \frac{W - F + 2P}{S} \right\rfloor + 1$$
$W$ — input width $F$ — filter size $P$ — padding $S$ — stride

Two common sanity checks you will run dozens of times in this module:

  • Same padding (stride 1, $P = (F-1)/2$) preserves the spatial size: 28×28 → 28×28.
  • Halving stride (stride 2, $P = 1$, $F = 3$) halves the spatial size: 28×28 → 14×14. You will see this over and over in ResNet and the convolutional autoencoder.
🔵 Theory — Parameter count

A Conv2d layer with $C_\text{in}$ input channels, $C_\text{out}$ output channels, and a $F \times F$ kernel has $C_\text{in} \cdot C_\text{out} \cdot F^2 + C_\text{out}$ parameters — independent of spatial size. An MLP on the same input would have parameters proportional to $H \cdot W$. This is why a CNN on a 224×224 image has ~10M parameters while the equivalent MLP would have ~150M.

ResNet: skip connections

Before ResNet, adding more layers to a CNN hurt accuracy after about 20 layers. The problem was not overfitting — the deeper networks had higher training error too, so they could not even fit the training data. He et al. (2015) call this the degradation problem and note it is "unlikely to be caused by vanishing gradients": their plain networks already used batch normalisation, and the gradient norms were healthy. Deep plain stacks are simply hard for the optimiser to drive to a good solution.

ResNet's fix is absurdly simple. Instead of learning an output $H(x)$ directly, each block learns the residual $F(x) = H(x) - x$ and adds the input back:

$$H(x) \;=\; F(x) + x$$
$x$ — block input (shortcut) $F(x)$ — residual (learned) $H(x)$ — block output

The skip connection gives the gradient a clear path from the loss back to early layers — there is always an additive route that does not go through the non‑linearity. And if $F$ learns to output zero the block becomes the identity, so an extra block is easy to make harmless — the optimiser only has to learn a small correction on top of $x$, which is why very deep residual networks train where plain ones degrade.

Squeeze‑and‑Excitation blocks

SE blocks are a 2017 drop‑in upgrade that make a CNN pay attention to which channels are informative for the current input. For each feature map, the block:

  1. Squeezes each channel to a single number with global average pooling: $s_c = \text{GAP}(x_c)$.
  2. Excites each channel with a tiny MLP that outputs a weight in $(0, 1)$: $w = \sigma(W_2 \, \text{ReLU}(W_1 s))$.
  3. Scales each channel by its weight: $x'_c = w_c \cdot x_c$.

With the paper's reduction ratio of 16, each SE block adds $2C^2/16 + C/16 + C$ parameters (two small linear layers with biases); across SE‑ResNet‑50 that is about 10% more parameters, for roughly 1.5 points lower top‑1 error on ImageNet (Hu et al., 2018). SE is an optional add‑on, not part of the standard ResNet — torchvision's ResNets, for example, do not include it.

The Kailash Engine: OnnxBridge

⚙ Kailash Engine

After you train a model, you need to ship it somewhere that is not a PyTorch process — a Rust service, a mobile app, a browser, an NVIDIA Triton server. OnnxBridge exports your trained model to ONNX, the portable format most production runtimes support. Export and parity checking are two separate calls: export(model, "torch", ...) traces and writes the file and returns a result object (it does not validate, and on failure it returns success=False instead of raising — so check it); validate(model, path, rows) runs the PyTorch model and ONNX Runtime on the same rows and reports the largest difference. 

from pathlib import Path
import torch
from kailash_ml import OnnxBridge
from shared.mlfp05.ex_2 import FlatImageAdapter

bridge = OnnxBridge()
serving = FlatImageAdapter(resnet_se).eval()  # Exercise 2's CIFAR-10 ResNetSE, flat pixel rows in
path = Path("resnet_se_cifar10.onnx")          # output_path must be a Path, not a str
x = torch.randn(2, 3 * 32 * 32)                # 2 rows: a batch of 1 can freeze the batch size

res = bridge.export(serving, "torch", output_path=path, sample_input=x)
assert res.success, res.error_message          # "torch", not "pytorch"; failure returns success=False

v = bridge.validate(serving, path, x.numpy(), tolerance=1e-3)
print(v.valid, v.max_diff)                     # PyTorch vs ONNX Runtime parity

validate calls model.predict(rows) on a NumPy array to get the PyTorch reference, so the model you pass needs a predict method. Worked Example: A ResNet block with SE, trained and exported

📝 Goal

Build a small CNN that starts as plain conv, then upgrades to a ResNet basic block, then adds an SE block. Train on a small synthetic shape‑classification dataset (three classes, generated below so the example runs in about a minute on a laptop) and export the final model to ONNX. Exercise 2 applies the same ideas to the real CIFAR‑10 dataset.

Step 1 — imports and the (synthetic) dataset. 
from pathlib import Path
import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import DataLoader, TensorDataset
from kailash_ml import OnnxBridge
from shared.kailash_helpers import get_device

torch.manual_seed(42)
rng = np.random.default_rng(42)
device = get_device()          # MPS / CUDA / CPU, picked automatically

def make_shapes(n=3000, size=28):
    """SYNTHETIC 28x28 shapes: 0 = circle, 1 = square, 2 = triangle."""
    yy, xx = np.mgrid[0:size, 0:size]
    X = np.zeros((n, 1, size, size), dtype=np.float32)
    y = rng.integers(0, 3, n)
    for i in range(n):
        r = rng.uniform(3, 7)                       # half-size in pixels
        cx, cy = rng.uniform(r + 1, size - r - 1, 2)
        if y[i] == 0:                               # circle
            mask = (xx - cx) ** 2 + (yy - cy) ** 2 <= r ** 2
        elif y[i] == 1:                             # axis-aligned square
            mask = (abs(xx - cx) <= r) & (abs(yy - cy) <= r)
        else:                                       # upward triangle
            top = cy - r
            mask = (yy >= top) & (yy <= cy + r) & (abs(xx - cx) <= (yy - top) / 2)
        X[i, 0] = mask
    X += rng.normal(0, 0.3, X.shape).astype(np.float32)   # sensor noise
    return X, y

X_np, y_np = make_shapes()
X = torch.from_numpy(X_np).to(device)
y = torch.from_numpy(y_np).long().to(device)
split = 2400                                         # 2,400 train / 600 validation
train_loader = DataLoader(TensorDataset(X[:split], y[:split]), batch_size=64, shuffle=True)
X_val, y_val = X[split:], y[split:]

The three classes are balanced (about 1,000 each). Shapes vary in size and position, and heavy Gaussian noise is added so the task is not trivial.

Step 2 — a basic residual block. 
class BasicBlock(nn.Module):
    def __init__(self, channels):
        super().__init__()
        self.conv1 = nn.Conv2d(channels, channels, 3, padding=1, bias=False)
        self.bn1   = nn.BatchNorm2d(channels)
        self.conv2 = nn.Conv2d(channels, channels, 3, padding=1, bias=False)
        self.bn2   = nn.BatchNorm2d(channels)

    def forward(self, x):
        identity = x
        out = F.relu(self.bn1(self.conv1(x)))
        out = self.bn2(self.conv2(out))
        out = out + identity            # ← the skip
        return F.relu(out)

Two 3×3 convs with batch norm, an identity shortcut, and a final ReLU. Same spatial size in and out (because of padding=1). This is the exact building block of ResNet‑18 and ResNet‑34.

Step 3 — a squeeze‑and‑excitation block. 
class SEBlock(nn.Module):
    def __init__(self, channels, reduction=8):   # paper uses 16; 8 suits our tiny 16/32-channel net
        super().__init__()
        hidden = max(channels // reduction, 4)
        self.fc1 = nn.Linear(channels, hidden)
        self.fc2 = nn.Linear(hidden, channels)

    def forward(self, x):
        b, c, _, _ = x.shape
        s = x.mean(dim=[2, 3])                 # squeeze: GAP
        s = F.relu(self.fc1(s))
        s = torch.sigmoid(self.fc2(s))         # excite: (0, 1)
        return x * s.view(b, c, 1, 1)          # scale each channel
Step 4 — stack them into a tiny network. 
class TinyResNetSE(nn.Module):
    def __init__(self, n_classes=3):
        super().__init__()
        self.stem = nn.Sequential(
            nn.Conv2d(1, 16, 3, padding=1), nn.BatchNorm2d(16), nn.ReLU(),
        )
        self.block1 = BasicBlock(16)
        self.se1    = SEBlock(16)
        self.down   = nn.Conv2d(16, 32, 3, stride=2, padding=1)
        self.block2 = BasicBlock(32)
        self.se2    = SEBlock(32)
        self.head   = nn.Sequential(
            nn.AdaptiveAvgPool2d(1), nn.Flatten(),
            nn.Linear(32, n_classes),
        )

    def forward(self, x):
        x = self.stem(x)
        x = self.se1(self.block1(x))
        x = F.relu(self.down(x))
        x = self.se2(self.block2(x))
        return self.head(x)
Step 5 — train with a plain loop. 
model = TinyResNetSE().to(device)
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
history = []

for epoch in range(15):
    model.train()
    running = 0.0
    for xb, yb in train_loader:
        logits = model(xb)
        loss = F.cross_entropy(logits, yb)
        opt.zero_grad(); loss.backward(); opt.step()
        running += loss.item() * xb.size(0)
    history.append(running / split)

    model.eval()                                  # BatchNorm → running stats
    with torch.no_grad():
        val_acc = (model(X_val).argmax(1) == y_val).float().mean().item()
    print(f"epoch {epoch+1:2d}: train loss {history[-1]:.4f}  val acc {val_acc:.3f}")

Standard PyTorch training loop. Same structure as Lesson 5.1 — the differences are cross‑entropy loss, the argmax to compute accuracy, and the switch to model.eval() before scoring the 600 held‑out shapes (BatchNorm must use its running statistics, not the batch's). On one run of this exact code (about a minute on a laptop), training loss fell steadily from 0.95 to 0.003, and validation accuracy passed 99% at epoch 5 — but then swung between 35% and 99.7% from epoch to epoch while the training loss kept falling. That is not overfitting: with only 38 batches per epoch and a fast‑moving network, BatchNorm's running averages lag behind the weights, so eval‑mode outputs jump around. Keeping the best validation checkpoint, lowering the learning rate late in training (the cosine schedule below), or recalibrating the BN statistics before evaluating all fix it. Your exact numbers will differ by device and seed.

Step 6 — export to ONNX and check parity. 
class Servable(nn.Module):
    """Adds the predict() method that OnnxBridge.validate calls."""
    def __init__(self, net):
        super().__init__()
        self.net = net
    def forward(self, x):
        return self.net(x)
    def predict(self, X):
        with torch.no_grad():
            return self.net(torch.as_tensor(X, dtype=torch.float32)).numpy()

serving = Servable(model.cpu()).eval()
onnx_path = Path("/tmp/tiny_resnet_se.onnx")       # any writable location
sample = X_val[:2].cpu()                            # 2 rows, not 1

bridge = OnnxBridge()
res = bridge.export(serving, "torch", output_path=onnx_path, sample_input=sample)
assert res.success, res.error_message

v = bridge.validate(serving, onnx_path, X_val[:100].cpu().numpy(), tolerance=1e-3)
print(f"valid={v.valid}  max_diff={v.max_diff:.1e}  over {v.n_samples} logits")

export traces the model with the two sample rows and writes the ONNX file; it reports failure through res.success rather than raising, so always assert it. validate then runs PyTorch (via predict) and ONNX Runtime on 100 validation images and reports the largest logit difference — on our run it was below $10^{-5}$ (300 logits compared: 100 images × 3 classes), far below the $10^{-3}$ tolerance. A large drift usually means an operator that ONNX does not support the same way, which you must rewrite before deployment. (The exporter may print an opset‑conversion traceback and fall back to opset 18; that is log noise — res.success is the real signal.)

🟣 Advanced — Why Kaiming init matters

With zero‑mean Gaussian weights and ReLU activations, half the outputs die at every layer. To keep the forward‑pass variance constant you need to initialise weights with variance $2 / n_{\text{in}}$ (He et al., 2015). Xavier/Glorot init (variance $2/(n_{\text{in}} + n_{\text{out}})$) and LeCun init (variance $1/n_{\text{in}}$) were derived for symmetric activations such as tanh and leave a ReLU network's activations shrinking layer by layer — use nn.init.kaiming_normal_(w, nonlinearity="relu") instead. (PyTorch's default Conv2d/Linear init is a Kaiming‑uniform variant with a smaller gain.)

Vision Transformers in One Page

CNNs dominated vision from 2012 until about 2020. Then the Vision Transformer (ViT) arrived and matched ResNet‑50 on ImageNet with no convolutions at all. ViT splits an image into, say, 16×16 patches, flattens each patch to a vector, adds a learned positional embedding, and feeds the sequence into a standard Transformer encoder (which you will meet in Lesson 5.4).

For large‑scale pre‑training on billions of images, ViTs are now competitive or ahead. For small datasets and compute budgets, CNNs are still often the better choice. Lesson 5.7 shows how to fine‑tune a pre‑trained ResNet for a new task; the same techniques apply to ViTs.

Common Mistakes

⚠ Mistake 1: Forgetting to put BN in eval mode

BatchNorm behaves differently at training vs eval time. At train time it uses batch statistics; at eval time it uses running averages. If you forget model.eval() before validation, your metrics will be noisy or just plain wrong. Same thing when exporting to ONNX.

⚠ Mistake 2: Spatial size mismatch in the skip

The identity shortcut only works when the block's input and output have the same shape. When you downsample (stride 2) or change the channel count, you need a 1×1 convolution on the shortcut to match shapes: identity = self.shortcut(x).

⚠ Mistake 3: Learning rate too high for deep nets

Deep CNNs are fragile to learning rate. Start with 1e‑3 (Adam) or 1e‑1 (SGD + momentum + cosine schedule). If loss explodes to NaN in the first 100 steps, halve the LR and retry. Mixed precision makes this worse — add a gradient scaler.

⚠ Mistake 4: view vs reshape after a conv stack

After adaptive average pooling, use torch.flatten(x, 1) or nn.Flatten. Using .view(b, -1) works when the memory is contiguous but breaks silently if a preceding operation returned a non‑contiguous tensor. flatten is always safe.
