Lesson 4.7 Recommender Systems — THE PIVOT

This is the single most important lesson in Module 4. We started the module with clustering and dimensionality reduction — unsupervised methods that discover features without any error signal. In 4.6 we saw NMF factorise a document-word matrix. Today we factorise a user-item matrix and watch the learned factors become embeddings — features discovered by optimisation. This is the Feature Engineering Spectrum pivot: the first time you see optimisation drive feature discovery. In Lesson 4.8, neural networks generalise this insight — hidden layer activations ARE embeddings, learned by minimising a loss function.

Why This Matters

Recommenders decide much of what online shoppers and viewers see: "customers also bought", "because you watched", a personalised home page. For a marketplace with thousands of products, choosing which handful to show each customer is a core commercial decision. But the business value is not the only reason they matter for this curriculum. Recommender systems sit at the exact transition between classical unsupervised ML and deep learning:

Core Concepts

Content-based filtering

The simplest recommender: represent each item as a feature vector (genre, price, description TF-IDF), represent each user as the average of the items they liked, and recommend items whose feature vectors are closest to the user vector. 

import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

# Toy item features (rows = items; columns = e.g. "gaming", "portable", "budget")
item_features = np.array([
    [0.9, 0.1, 0.2],   # item 0: gaming laptop
    [0.1, 0.9, 0.6],   # item 1: ultrabook
    [0.8, 0.2, 0.1],   # item 2: gaming monitor
    [0.2, 0.7, 0.9],   # item 3: budget tablet
])
purchased_indices = [0]                       # the user bought the gaming laptop

# User profile: average of the items they purchased
user_profile = item_features[purchased_indices].mean(axis=0)

# Recommend: unpurchased items ranked by similarity to the profile
sims = cosine_similarity(user_profile.reshape(1, -1), item_features)[0]
sims[purchased_indices] = -np.inf
print(np.argsort(sims)[::-1][:2])             # [2 3]: the gaming monitor comes first
🟢 Foundations

Content-based filtering does not need other users' data. It works for brand-new items (no item cold-start) as long as they have features. It does not solve the cold-start problem for a brand-new user: with no purchases there is no profile to compare against (the snippet above needs at least one purchased item). The other downside: it cannot discover surprising preferences — it only recommends more of what you already like.

Collaborative filtering

Collaborative filtering ignores item features entirely. It works with the user-item interaction matrix $R$ (ratings, purchases, clicks):

  • User-based CF: find users similar to you, recommend what they liked.
  • Item-based CF: find items similar to what you liked, recommend those.

Matrix factorisation — THE PIVOT

Factorise $R \approx U V^T$ where $U \in \mathbb{R}^{m \times k}$ (user embeddings) and $V \in \mathbb{R}^{n \times k}$ (item embeddings). The objective:

$$ \min_{U, V} \sum_{(u,i) \in \text{observed}} \bigl(r_{ui} - \mathbf{u}_u^T \mathbf{v}_i\bigr)^2 + \lambda\bigl(\|\mathbf{u}_u\|^2 + \|\mathbf{v}_i\|^2\bigr) $$
$r_{ui}$ — observed rating $\mathbf{u}_u^T \mathbf{v}_i$ — predicted rating $\lambda$ — regularisation

ALS (Alternating Least Squares) solves this by alternating: fix $V$, solve for every user vector in closed form; fix $U$, solve for every item vector. With $V_{\Omega_u}$ the rows of $V$ for the items user $u$ rated and $\mathbf{r}_{u,\Omega_u}$ those ratings, each user update is a ridge regression over the observed entries only: $\mathbf{u}_u = (V_{\Omega_u}^\top V_{\Omega_u} + \lambda I)^{-1} V_{\Omega_u}^\top \mathbf{r}_{u,\Omega_u}$, and symmetrically for items. Each half-step solves its sub-problem exactly, so the objective never increases. Repeat until it stops improving.

🔵 Theory — the connection

Compare to PCA (Lesson 4.3): PCA decomposes $X = U \Sigma V^T$. Matrix factorisation decomposes $R \approx U V^T$. Both find low-rank structure. The difference: PCA minimises reconstruction error on the full matrix; matrix factorisation minimises it only on observed entries. Both produce embeddings — PCA's are principal components; matrix factorisation's are user/item latent factors.

🟣 Advanced

SVD++ extends basic matrix factorisation with implicit feedback (views, clicks, time-on-page). The user embedding becomes $\mathbf{u}_u + |N(u)|^{-1/2} \sum_{j \in N(u)} \mathbf{y}_j$, where $N(u)$ is the set of items the user interacted with and $\mathbf{y}_j$ are implicit-factor vectors (Koren, 2008). A user with few ratings but many views is still placed sensibly, which is why adding implicit signals typically improves accuracy over explicit-only factorisation.

Implicit vs explicit feedback

Explicit feedback (star ratings) is what users deliberately tell you. Implicit feedback (clicks, views, purchases, dwell time) is what they show you through behaviour. Implicit data is usually far more abundant than ratings, but noisier: a click is not a like, and "not clicked" is not "disliked". The standard method for purely implicit data is weighted ALS on a binary preference matrix with confidence weights (Hu, Koren and Volinsky, 2008); many production recommenders rely mainly on implicit signals.

Hybrid systems

Combine content-based features (item descriptions, metadata) with collaborative signals (user-item interactions). Common patterns: a weighted hybrid ($\alpha \cdot \text{CF} + (1-\alpha) \cdot \text{content}$, with $\alpha$ tuned on a validation split — never on the test set); a switching hybrid (content for new items, CF otherwise); and feature-augmented factorisation. Hybrids mitigate the item cold-start problem (new items have features but no interactions) and improve coverage. A brand-new user still needs a few interactions — or a non-personalised fallback such as popularity.

The Pivot Insight

Pause and absorb this. Matrix factorisation learns user and item embeddings by minimising reconstruction error. The embeddings are not hand-crafted features — they are features discovered by optimisation. K-means, PCA and NMF also minimised objectives, but as summaries of a fully observed matrix. Matrix factorisation is the first time a model is fitted iteratively to a partially observed target — the ratings we have — judged by how well it predicts the ratings we do not have, with its learned factors reused as embeddings.

In Lesson 4.8, we will see that a neural network does the exact same thing: hidden layer activations are embeddings, learned by minimising a loss function. The difference: neural networks can learn non-linear combinations through activation functions. Matrix factorisation produces linear embeddings; neural networks produce non-linear ones. But the core insight is identical: optimisation drives feature discovery.

Worked Example: An Electronics Marketplace Recommender

Goal

The ratings are synthetic, generated by Exercise 7's build_rating_dataset() for a fictional Singapore electronics marketplace: 300 users, 120 products, explicit 1–5 star ratings, about 30% of user–item pairs observed. The generator follows a known model — global mean + user bias + item bias + (user taste · item traits) with 5 hidden taste dimensions, plus noise — so we can check whether the learned embeddings recover the truth. Thirty per cent of the observed ratings are held out, and 10 brand-new products have all their ratings in the holdout: cold-start items no collaborative method has seen. Every item also has 8 content features (a noisy view of its hidden traits, like a spec sheet).

Step 1.

Load the data and score the no-skill baselines every recommender must beat.

import numpy as np
from shared.mlfp04.ex_7 import build_rating_dataset, print_baselines, print_method_scores

data = build_rating_dataset()
R_obs, R_train = data["R_observed"], data["R_train"]
train_mask, holdout_mask = data["train_mask"], data["holdout_mask"]
cold_items, item_features = data["cold_items"], data["item_features"]
print(f"{R_train.shape[0]} users x {R_train.shape[1]} items; "
      f"{int(cold_items.sum())} cold-start products")

baselines = print_baselines(R_train, train_mask, R_obs, holdout_mask)

The scorecard reports holdout RMSE, coverage (the share of holdout pairs a method can score at all), precision@5 and mean average precision (MAP). The global mean scores RMSE 1.03, the item mean ("popularity") 0.97 with MAP 0.68, and random scores 1.60.

Step 2.

Content-based filtering from the item features.

def content_based(R, mask, features):
    """Score items by cosine similarity between item features and a user taste profile."""
    feats = features - features.mean(axis=0)
    unit = feats / np.linalg.norm(feats, axis=1, keepdims=True)
    preds = np.full(R.shape, np.nan)
    for u in range(R.shape[0]):
        rated = np.where(mask[u])[0]
        if len(rated) < 2:
            continue                                   # a brand-new USER has no profile
        dev = R[u, rated] - R[u, rated].mean()         # liked items pull, disliked items push
        profile = dev @ unit[rated]
        if np.linalg.norm(profile) < 1e-10:
            continue
        cos = unit @ (profile / np.linalg.norm(profile))
        preds[u] = R[u, rated].mean() + 2 * R[u, rated].std() * cos
    return np.clip(preds, 1, 5)

pred_cb = content_based(R_train, train_mask, item_features)
m_cb = print_method_scores("Content-based", pred_cb, R_obs, holdout_mask)

Content-based filtering covers every item with features, including the 10 new products (coverage 100%), and scores RMSE 0.95 and MAP 0.73 — a modest gain on popularity. It cannot help a brand-new user: with no ratings there is no profile. User-based and item-based collaborative filtering (Exercises 7.2 and 7.3) do much better on the pairs they can score (RMSE 0.77 and 0.82) but cannot score the cold products at all, so their coverage is only about 77%. Always read coverage next to accuracy.

Step 3.

Biased matrix factorisation with ALS, then check what the embeddings learned.

def als(R, mask, k=5, lam=5.0, n_iter=30, seed=42):
    """Biased ALS: R[u, j] ~ mu + b_u + b_j + U[u] . V[j], each half-step a ridge regression."""
    rng = np.random.default_rng(seed)
    mu = float(R[mask].mean())
    U, V = rng.normal(0, 0.1, (R.shape[0], k)), rng.normal(0, 0.1, (R.shape[1], k))
    b_u, b_i = np.zeros(R.shape[0]), np.zeros(R.shape[1])
    R0, penalty, losses = np.nan_to_num(R), lam * np.eye(k + 1), []
    for _ in range(n_iter):
        for u in range(R.shape[0]):                    # fix items, solve each user
            js = np.where(mask[u])[0]
            X = np.hstack([V[js], np.ones((len(js), 1))])
            sol = np.linalg.solve(X.T @ X + penalty, X.T @ (R0[u, js] - mu - b_i[js]))
            U[u], b_u[u] = sol[:k], sol[k]
        for j in range(R.shape[1]):                    # fix users, solve each item
            us = np.where(mask[:, j])[0]
            if len(us) == 0:
                continue                               # cold item: nothing to learn from
            X = np.hstack([U[us], np.ones((len(us), 1))])
            sol = np.linalg.solve(X.T @ X + penalty, X.T @ (R0[us, j] - mu - b_u[us]))
            V[j], b_i[j] = sol[:k], sol[k]
        fit = mu + b_u[:, None] + b_i[None, :] + U @ V.T
        losses.append(float(((R0 - fit)[mask] ** 2).sum()
                            + lam * ((U**2).sum() + (V**2).sum() + (b_u**2).sum() + (b_i**2).sum())))
    preds = np.clip(mu + b_u[:, None] + b_i[None, :] + U @ V.T, 1, 5)
    preds[:, mask.sum(axis=0) == 0] = np.nan
    return preds, U, V, losses

pred_als, U, V, losses = als(R_train, train_mask)
print(f"regularised loss: {losses[0]:,.0f} -> {losses[-1]:,.0f}")
m_als = print_method_scores("ALS (k=5)", pred_als, R_obs, holdout_mask)

# Do the learned item embeddings recover the hidden traits?  (R^2 of a linear map)
warm = ~cold_items
Xw = np.c_[V[warm], np.ones(warm.sum())]
coef, *_ = np.linalg.lstsq(Xw, data["V_true"][warm], rcond=None)
resid = data["V_true"][warm] - Xw @ coef
print(f"R^2 of true item traits explained by learned embeddings: "
      f"{1 - resid.var() / data['V_true'][warm].var():.2f}")

The mean and the user and item biases absorb "this user rates generously" and "this product is simply good", leaving the factors to capture taste. Each half-step is an exact ridge-regression solve over the observed entries only, so the regularised loss never increases (about 4,190 → 3,360). ALS reaches a holdout RMSE of 0.56 — far better than every baseline and both neighbourhood methods — but its coverage also stops at 77% because of the cold products. The last lines are the pivot made visible: a linear map from the 5 learned dimensions explains 96% of the variance of the 5 true trait dimensions. Nobody told ALS what the traits were; they emerged from minimising the reconstruction loss.

Step 4.

Who can score the brand-new products?

cold_pairs = holdout_mask & cold_items[None, :]
for name, preds in [("Content-based", pred_cb), ("ALS", pred_als)]:
    covered = cold_pairs & ~np.isnan(preds)
    print(f"{name:<14} can score {int(covered.sum())} of {int(cold_pairs.sum())} cold-product ratings")

Only content-based filtering can say anything about the new products. That is the case for a hybrid: collaborative signals where history exists, content where it does not. Exercise 7.5 tunes the blend weight on a validation split and measures its lift over each component on the test split.

Common Mistakes

  1. Training on the full matrix. You must hold out test interactions. Evaluate on unseen user-item pairs, not the ones used for training.
  2. Ignoring implicit data. Star ratings are rare; clicks are abundant. Weighting implicit feedback correctly is usually the biggest accuracy lever.
  3. Too many latent factors. Choose $k$ (and $\lambda$) on a validation split. Larger $k$ overfits sparse matrices and makes each ALS solve more expensive; in the worked example the generator has 5 hidden dimensions and $k = 5$ suffices.
  4. Reporting accuracy without coverage. A method that cannot score cold items can look accurate on the pairs it does score. Report coverage alongside RMSE and ranking metrics.
  5. Missing the pivot insight. The point is not just "build a recommender" — it is "optimisation discovers features". If you leave this lesson thinking it was about recommendations, go back and re-read the pivot section.
