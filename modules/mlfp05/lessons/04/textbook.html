Lesson 5.4 Transformers and Self-Attention

"Attention is all you need" — the 2017 paper by Vaswani et al. replaced recurrence with pure attention and kicked off the modern era of deep learning. In this lesson you derive scaled dot-product attention from scratch with torch.einsum, understand why we divide by $\sqrt{d_k}$, implement multi-head attention, add sinusoidal positional encoding, assemble a working Transformer encoder for sequence classification, then meet the decoder (masked self‑attention and cross‑attention) and the Vision Transformer. Exercise 4 applies all of this to real AG News headlines, ending with fine‑tuning a pre‑trained BERT.

The Big Shift

An LSTM processes a sequence one step at a time: to compute $h_5$ you must first compute $h_1, h_2, h_3, h_4$. The computation is sequential — you cannot parallelise it across time. For long sequences on modern GPUs this is a tremendous waste of compute.

The Transformer asks: what if every token could look at every other token directly, in parallel, using an attention mechanism? No hidden state passed forward; no sequential recurrence; all positions computed at once. The answer is the self-attention layer, and it dominates modern NLP (BERT, GPT, T5), speech (Whisper), vision (ViT, DeiT), protein structure (AlphaFold), and more.

Scaled Dot-Product Attention — From Scratch

Each token in the sequence is first projected into three vectors — a query $q$, a key $k$, and a value $v$ — by three learnable linear maps.

🟢 The metaphor

Think of a database lookup. Each token emits a question (query), each token emits a key describing what it contains, and each token emits a value to return. A token's query is compared against every key (via dot product) to produce a similarity score. The scores are softmaxed into weights; the output is a weighted sum of the values.

Stack all the queries, keys, and values into matrices $Q, K, V \in \mathbb{R}^{L \times d_k}$ (one row per token, $L$ the sequence length). The attention output for all positions is computed in one shot:

$$\text{Attention}(Q, K, V) \;=\; \text{softmax}\!\left(\frac{Q K^{\top}}{\sqrt{d_k}}\right) V$$
$Q K^\top$ — raw similarity scores ($L \times L$) $\sqrt{d_k}$ — variance rescaling softmax — row-wise

Read the formula right to left:

  1. $Q K^\top$ is an $L \times L$ matrix. Entry $(i, j)$ is the dot product of query $i$ and key $j$ — a raw similarity score.
  2. Divide every entry by $\sqrt{d_k}$. We explain why next.
  3. Softmax each row, so row $i$ becomes a probability distribution over the sequence: "how much should token $i$ pay attention to each other token?"
  4. Multiply by $V$: token $i$'s output is the weighted sum of value vectors according to its attention distribution.

Why divide by $\sqrt{d_k}$?

If $q$ and $k$ are random vectors of dimension $d_k$ with unit-variance entries, the dot product $q^\top k$ is a sum of $d_k$ products of unit-variance numbers — so its variance is $d_k$ and its typical magnitude is $\sqrt{d_k}$. Feed $\sqrt{d_k}$-magnitude scores into a softmax and the softmax saturates: one entry gets essentially all the weight, the rest get nothing, and the gradient with respect to all the other entries is zero. Training stalls.

Dividing by $\sqrt{d_k}$ brings the scores back to unit variance, keeps the softmax in its useful region, and lets gradients flow. It is a single character in code but absolutely load-bearing for training stability. Transformers without the scaling factor do not work.

🔵 Theory — The variance calculation

Let $q, k \in \mathbb{R}^{d_k}$ with independent zero-mean unit-variance entries. Then $q^\top k = \sum_{i=1}^{d_k} q_i k_i$. Each term has variance $\text{Var}(q_i)\text{Var}(k_i) = 1$. Independent sum gives variance $d_k$, so standard deviation $\sqrt{d_k}$. Dividing the dot product by $\sqrt{d_k}$ normalises it back to unit variance.

Attention from scratch with einsum

import math
import torch
import torch.nn.functional as F

def scaled_dot_product_attention(q, k, v, mask=None):
    """q, k, v: (B, L, d_k) — queries, keys, values per sample/position"""
    d_k = q.size(-1)
    # (B, L, L) — one similarity matrix per sample in the batch
    scores = torch.einsum("bld,bmd->blm", q, k) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    attn = F.softmax(scores, dim=-1)        # row-wise over key positions
    out = torch.einsum("blm,bmd->bld", attn, v)
    return out, attn

Two einsum calls and a softmax — that is the entire attention computation. The mask argument is how we handle padding (ignore positions beyond the true sequence length) and causal generation (each position only attends to earlier positions).

Multi-Head Attention

A single attention head gives every token one "viewpoint" on the rest of the sequence. Different linguistic phenomena (syntactic agreement, coreference, topic relevance) live on different viewpoints. Multi-head attention runs $h$ separate attention computations in parallel on smaller subspaces and concatenates the results:

$$\text{MultiHead}(Q, K, V) \;=\; \text{Concat}(\text{head}_1, \ldots, \text{head}_h)\, W^O$$
$\text{head}_i = \text{Attention}(QW_i^Q, KW_i^K, VW_i^V)$ $W^O$ — output projection

If the full model dimension is $d_{\text{model}} = 512$ and we have $h = 8$ heads, each head operates in a $d_k = 64$-dimensional subspace. Total parameter count is roughly the same as a single-head $d_k = 512$ attention, but the model can attend to eight different relationships simultaneously.

Positional Encoding

Self-attention is permutation‑equivariant (order‑blind) — shuffle the input tokens and the outputs are shuffled the same way; nothing else changes. After mean‑pooling, the result is fully order‑invariant. But in language, order matters: "dog bites man" is not "man bites dog". The Transformer injects position information by adding a position vector to each token embedding.

The original paper uses sinusoidal positional encodings with different frequencies per dimension:

$$\text{PE}(\text{pos}, 2i) = \sin\!\left(\frac{\text{pos}}{10000^{2i/d}}\right), \quad \text{PE}(\text{pos}, 2i+1) = \cos\!\left(\frac{\text{pos}}{10000^{2i/d}}\right)$$
pos — position index in sequence $i$ — feature dimension $d$ — model dimension

The frequency of dimension pair $i$ is $10000^{-2i/d}$: at $i = 0$ it is 1 radian per position, the fastest, and it falls towards $10^{-4}$ as $i \to d/2$. So the low dimensions oscillate fastest and encode fine, local position, while the high dimensions oscillate slowly and encode coarse, global position.

The particular choice gives every position a unique fingerprint that can be computed deterministically (no parameters), extrapolated beyond training sequence lengths, and lets the model learn relative position via trigonometric identities. Later Transformers (BERT, GPT) use learned positional embeddings instead — one vector per position, trained from scratch. 

class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=5000):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len).unsqueeze(1).float()
        div_term = torch.exp(
            torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model)
        )
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        self.register_buffer("pe", pe)

    def forward(self, x):
        return x + self.pe[:x.size(1)]   # broadcast-add (L, d) to (B, L, d)

The Encoder Block and Full Encoder

One Transformer encoder block has six components:

  1. Multi-head self-attention
  2. Residual connection (add input to attention output)
  3. Layer normalisation
  4. Feed-forward network (two linear layers with ReLU)
  5. Residual connection (add to FFN output)
  6. Layer normalisation again

The full encoder stacks $N$ identical blocks. PyTorch provides nn.TransformerEncoderLayer and nn.TransformerEncoder which implement this exactly, with the option of norm_first=True to apply layer norm before attention (the "pre-norm" variant, which trains more stably). 

class TinyTransformer(nn.Module):
    def __init__(self, n_tokens=10, d_model=64, n_heads=4, n_layers=2,
                 max_len=50, n_classes=2):
        super().__init__()
        self.embed = nn.Embedding(n_tokens, d_model)
        self.pos   = PositionalEncoding(d_model, max_len)
        enc_layer  = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=n_heads, dim_feedforward=128,
            batch_first=True, norm_first=True,
        )
        # enable_nested_tensor=False: the fast path does not support
        # norm_first=True and would only warn about it
        self.encoder = nn.TransformerEncoder(enc_layer, num_layers=n_layers,
                                             enable_nested_tensor=False)
        self.head = nn.Linear(d_model, n_classes)

    def forward(self, tokens):
        x = self.embed(tokens)               # (B, L, d)
        x = self.pos(x)                      # add position info
        x = self.encoder(x)                  # (B, L, d)
        pooled = x.mean(dim=1)               # mean-pool over sequence
        return self.head(pooled)
🔵 Theory — Layer norm, not batch norm

Transformers use layer norm (normalise across the feature dimension per token) rather than batch norm (normalise across the batch dimension per feature). Why? Because sequence lengths vary across batches, and batch statistics become noisy or meaningless when the effective batch size at each position varies. Layer norm has no dependency on batch shape, so it is robust.

The Decoder: Masked Self-Attention and Cross-Attention

The encoder reads a whole sequence at once. A decoder generates a sequence one token at a time, so it must never peek at tokens it has not produced yet. The original Transformer decoder block has three sub‑layers, each wrapped in a residual connection and layer norm:

  1. Masked (causal) self‑attention over the target tokens generated so far. A lower‑triangular mask sets every score for a future position to $-\infty$ before the softmax, so position $t$ attends only to positions $\le t$. This is what lets the decoder train on all positions in parallel (teacher forcing) while behaving exactly as it will at generation time.
  2. Cross‑attention: the queries come from the decoder, the keys and values from the encoder's output. Each target position asks "which source positions matter for me now?" — in translation, which input words to translate next.
  3. The same position‑wise feed‑forward network as the encoder.

Both kinds of attention are the scaled_dot_product_attention function from earlier — only the mask and the source of $K, V$ change: 

torch.manual_seed(0)
B, L_src, L_tgt, d = 2, 6, 4, 8
enc_out = torch.randn(B, L_src, d)          # encoder output ("memory")
dec_in  = torch.randn(B, L_tgt, d)          # target tokens so far

causal = torch.tril(torch.ones(L_tgt, L_tgt))          # 1 = may attend
_, w_self = scaled_dot_product_attention(dec_in, dec_in, dec_in, mask=causal)
print(w_self[0].round(decimals=2))                     # upper triangle is exactly 0

out, w_cross = scaled_dot_product_attention(dec_in, enc_out, enc_out)  # Q: decoder; K, V: encoder
print(w_cross.shape)                                   # torch.Size([2, 4, 6])

Row $t$ of w_self spreads its weight over positions $0 \ldots t$ only (row 0 puts all its weight on itself). The cross‑attention matrix is $L_\text{tgt} \times L_\text{src}$ — one distribution over the source sentence for each target position. PyTorch packages the whole block as nn.TransformerDecoderLayer; note that its masks use the opposite convention from ours ($-\infty$ or True marks a blocked position): 

import torch.nn as nn

layer = nn.TransformerDecoderLayer(d_model=d, nhead=2, dim_feedforward=16, batch_first=True)
tgt_mask = nn.Transformer.generate_square_subsequent_mask(L_tgt)   # 0 on/below diagonal, -inf above
print(layer(dec_in, enc_out, tgt_mask=tgt_mask).shape)            # torch.Size([2, 4, 8])

A decoder‑only model (GPT) simply drops the cross‑attention sub‑layer: masked self‑attention plus FFN, stacked, trained to predict the next token. An encoder–decoder model (T5, Whisper) keeps all three.

Vision Transformers (ViT)

ViT (Dosovitskiy et al., 2020) asks: what if an image were just a sequence? Cut it into fixed‑size patches, flatten and linearly embed each patch into a token, prepend a learned [CLS] token, add learned position embeddings, and run a standard Transformer encoder. The class is read from the final [CLS] vector. A convolution whose kernel size and stride both equal the patch size is exactly "cut into patches and apply the same linear map to each": 

class PatchEmbed(nn.Module):
    def __init__(self, img=32, patch=8, in_ch=3, d=64):
        super().__init__()
        self.proj = nn.Conv2d(in_ch, d, kernel_size=patch, stride=patch)  # one token per patch
        n = (img // patch) ** 2                                           # 16 patches
        self.cls = nn.Parameter(torch.zeros(1, 1, d))
        self.pos = nn.Parameter(torch.randn(1, n + 1, d) * 0.02)          # learned positions

    def forward(self, x):                                  # (B, 3, 32, 32)
        t = self.proj(x).flatten(2).transpose(1, 2)        # (B, 16, d)
        cls = self.cls.expand(x.size(0), -1, -1)           # (B, 1, d)
        return torch.cat([cls, t], dim=1) + self.pos       # (B, 17, d)

class TinyViT(nn.Module):
    def __init__(self, n_classes=10, d=64):
        super().__init__()
        self.patches = PatchEmbed(d=d)
        layer = nn.TransformerEncoderLayer(d, nhead=4, dim_feedforward=128,
                                           batch_first=True, norm_first=True)
        self.encoder = nn.TransformerEncoder(layer, num_layers=2, enable_nested_tensor=False)
        self.head = nn.Linear(d, n_classes)

    def forward(self, x):
        h = self.encoder(self.patches(x))
        return self.head(h[:, 0])                          # classify from [CLS]

imgs = torch.randn(4, 3, 32, 32)                           # e.g. a CIFAR-10-sized batch
print(PatchEmbed()(imgs).shape)                            # torch.Size([4, 17, 64])
print(TinyViT()(imgs).shape)                               # torch.Size([4, 10])

Everything after the patch embedding is the encoder you already built. The trade‑off with CNNs is inductive bias: a CNN hard‑codes locality and translation equivariance, so it learns well from small datasets; a ViT must learn those regularities from data, so it typically needs large‑scale pre‑training (the original ViT used ImageNet‑21k or a 300M‑image dataset) before it matches or beats ResNets. For a small dataset like CIFAR‑10 trained from scratch, the ResNet‑SE of Exercise 2 is the better choice; fine‑tuning a pre‑trained ViT is how ViTs are used in practice (Lesson 5.7's transfer recipe).

🎯 Drill — ViT sequence length

A standard ViT‑B/16 takes 224×224 images with 16×16 patches. How many tokens does the encoder see, and how many entries does one head's attention matrix have? What happens if you switch to 8×8 patches?

Solution

$(224/16)^2 = 14^2 = 196$ patches, plus [CLS] = 197 tokens, so each head's attention matrix is $197^2 = 38{,}809$ entries. With 8×8 patches: $28^2 + 1 = 785$ tokens and $785^2 = 616{,}225$ entries — about 16× more, because attention cost is quadratic in sequence length (Mistake 4 below). Halving the patch size buys finer detail at roughly 16× the attention cost.

Worked Example: A Tiny Transformer Sequence Classifier

📝 Goal

Train a small Transformer encoder on a synthetic order‑dependent bit task: given 20 random bits, output 1 if the first half holds more ones than the second half. The label depends on where the ones are, not just how many, so a model without positional encoding cannot solve it — we will measure that.

Step 1 — data, with a held‑out test set. 
import torch, math
import torch.nn as nn, torch.nn.functional as F
from torch.utils.data import DataLoader, TensorDataset
from shared.kailash_helpers import get_device

torch.manual_seed(42)
device = get_device()            # MPS / CUDA / CPU, picked automatically

def make_dataset(n=4000, L=20):
    X = torch.randint(0, 2, (n, L))
    # 1 if the FIRST half holds more ones than the second half (ties -> 0)
    y = (X[:, :L // 2].sum(1) > X[:, L // 2:].sum(1)).long()
    return X, y

X, y = make_dataset()
X, y = X.to(device), y.to(device)
X_tr, y_tr, X_te, y_te = X[:3000], y[:3000], X[3000:], y[3000:]
loader = DataLoader(TensorDataset(X_tr, y_tr), batch_size=64, shuffle=True)

Ties (equal counts in both halves) are labelled 0, which happens with probability $\binom{20}{10}/2^{20} \approx 0.18$, so class 1 is about 41% of the data and always predicting 0 scores about 59%. That majority‑class rate is the bar to beat.

Step 2 — assemble the model.

Use the TinyTransformer class defined earlier. With n_tokens=2 the embedding is a 2-entry lookup.

model = TinyTransformer(n_tokens=2, d_model=32, n_heads=4,
                        n_layers=2, max_len=20, n_classes=2).to(device)
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
Step 3 — train and test. 
for epoch in range(20):
    model.train()
    for xb, yb in loader:
        logits = model(xb)
        loss = F.cross_entropy(logits, yb)
        opt.zero_grad()
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        opt.step()

model.eval()
with torch.no_grad():
    acc = (model(X_te).argmax(1) == y_te).float().mean().item()
print(f"test accuracy: {acc:.3f}")

Same gradient clipping as for RNNs — Transformers explode in exactly the same way if you forget. On one run (about two minutes on a laptop) this reached 100% test accuracy. The identical model with the self.pos(...) step removed reached 60.8% — exactly the majority‑class rate of this test set: without positions, the mean‑pooled encoder sees only how many ones there are, not which half they are in.

Step 4 — inspect attention weights. 
layer = model.encoder.layers[0]
with torch.no_grad():
    h = model.pos(model.embed(X_te[:4]))
    h = layer.norm1(h)               # pre-norm layer: attention sees the normed input
    _, w = layer.self_attn(h, h, h, need_weights=True,
                           average_attn_weights=False)
print(w.shape)                       # torch.Size([4, 4, 20, 20]) — (batch, head, query, key)

A forward hook on self_attn does not work here: nn.TransformerEncoderLayer calls its attention with need_weights=False for speed, so the hooked output holds None instead of weights. Instead, rebuild the layer's input (embedding + position, then norm1 because of norm_first=True) and call the trained attention module yourself with need_weights=True. Every row of w sums to 1. Common Mistakes

⚠ Mistake 1: Forgetting positional encoding

Without PE, a Transformer is a set classifier — it cannot distinguish "dog bites man" from "man bites dog". Symptom: on an order‑dependent task the model is stuck at the majority‑class rate (60.8% on the worked example's test set, versus 100% with PE). Fix: add sinusoidal or learned positional encoding to the embedding before the first encoder layer.

⚠ Mistake 2: Missing / sqrt(d_k)

Without the scaling, the softmax saturates almost immediately and training stalls. Symptom: loss drops for one epoch and then flatlines at a high value. Double-check the scaling before anything else.

⚠ Mistake 3: Wrong mask shape or type

nn.MultiheadAttention expects attn_mask (per-position, broadcast) and key_padding_mask (per-sample, padding indicators) as separate arguments. Mixing them up is the #1 source of "my Transformer ignores the last half of the sentence" bugs. For causal masking, use an upper-triangular boolean matrix with True where positions should be masked.

⚠ Mistake 4: Quadratic memory surprise

Self-attention is $\mathcal{O}(L^2)$ in memory. Double the sequence length and memory quadruples. Token sequences of 4096 are painful on a consumer GPU. This is why you see "efficient attention" variants (Longformer, Performer, FlashAttention) in the literature.

🎯 Exercise C — Count the parameters

For d_model=64, n_heads=4, n_layers=2, dim_feedforward=128, compute the parameter count by hand (QKV projections per head, output projection, two FFN layers, layer norms). Compare with sum(p.numel() for p in model.encoder.parameters()).

Solution

Per layer: the fused Q, K, V projections $3(64 \cdot 64 + 64) = 12{,}480$ (the heads split $d_\text{model}$, so the head count does not change this); output projection $64 \cdot 64 + 64 = 4{,}160$; FFN $64 \cdot 128 + 128 + 128 \cdot 64 + 64 = 16{,}576$; two layer norms $2 \cdot 2 \cdot 64 = 256$. Total $33{,}472$ per layer, so 66,944 for two layers — exactly what model.encoder.parameters() reports. (The embedding and classification head are extra.)

Reflection — The Four Paradigms Consolidated

You have now seen all four core deep-learning paradigms:

  • Autoencoders (5.1) — representation learning via compress-and-reconstruct.
  • CNNs (5.2) — spatial feature extraction via weight sharing.
  • RNNs / LSTMs (5.3) — temporal feature extraction via gated memory.
  • Transformers (5.4) — direct attention between all positions, in parallel.

The remaining four lessons combine these paradigms: GANs and diffusion (5.5) pair a decoder/generator with an adversarial or noise-based training signal; GNNs (5.6) generalise convolutions and attention to graph-structured data; transfer learning (5.7) reuses pre-trained backbones from any of the four; and reinforcement learning (5.8) changes the game entirely by learning from interaction.

You derived scaled dot-product attention from scratch, understood why $\sqrt{d_k}$ matters, implemented multi-head attention, added positional encoding, trained a working Transformer encoder (and measured what happens without positions), and saw how masked self‑attention, cross‑attention and patch embeddings turn the same block into GPT‑style decoders, encoder–decoders and ViTs. That is the single most important architecture in modern AI and you now know how it works end to end.
