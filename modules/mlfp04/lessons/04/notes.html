Speaker Notes — Lesson 4.4 Anomaly Detection and Ensembles

Total time: ~75 minutes  ·  18 slides  ·  ~4 min per slide average

Screening without labels — the unsupervised counterpart to M3's credit model. The lesson's spine is the worked example: 20,000 real credit applications with 200 injected, labelled anomalies, so students can watch each method succeed and fail by type. The two findings to land: LOF's masking trap (a tight fraud ring is invisible at small k — AUC 0.22 at k=20 vs 0.89 at k=50), and the division of labour between AnomalyDetectionEngine (unsupervised screening) and EnsembleEngine (supervised second stage, only once analysts label a review sample).

Slide 1~1 minTitle

Anomaly Detection and Ensembles

Open with the outcome: "Today you'll screen credit applications for anomalies without labels — Z-score, IQR, Isolation Forest, LOF, and how to blend them. No ground truth to train on; that's what makes this lesson different from everything in M3."

→ "The opposite question."
Slide 2~3 minOpposite question

The opposite question

Invert 4.1: clustering asked "which group does this point belong to?"; anomaly detection asks "which points don't belong to any group?" Use cases: fraud, defects, sensor faults, intrusions, churn precursors.

Read the green box — it sets the problem's shape: "Anomalies are rare. If 'anomalies' are 20% of your data, you have a classification problem, not an anomaly detection one — go back to M3 and label some rows."

→ "Not all outliers look alike."
Slide 3~3 minOutlier types

Three types of outliers

Walk the three red points. "Far from all" — globally distant from every cluster; easy. "Rare direction" — inside the range of each feature but along a combination the data never takes. "In a gap" — between clusters, locally sparse.

Read the caption: "Different methods catch different types. Keep this picture in mind — the method matrix later maps directly onto it."

→ "The classical one-liner."
Slide 4~3 minZ-score

Z-score: univariate, assumes normality

Walk the formula: standardise, flag $|z| > 3$. Simple, fast, one line.

Then the two failure modes. "It breaks on right-skewed data — revenue, session length — where the tail is the norm, not the exception. Log-transform first. And outliers inflate $\bar{x}$ and $s$, hiding each other: one extreme value stretches the ruler it's measured with."

→ "The robust version."
Slide 5~3 minIQR

IQR: robust to skew

Walk the rule: flag below $Q_1 - 1.5\,\text{IQR}$ or above $Q_3 + 1.5\,\text{IQR}$. "Quartiles barely notice a few extreme values — the masking problem from the z-score is gone. This is what box-plot whiskers have been showing you since M1."

Read the blue box: "Winsorisation — cap at the IQR bounds instead of dropping rows. You keep the sample size for downstream stats while taming the tails." Default univariate detector for business data.

→ "Where univariate methods go blind."
Slide 6~3 minCombinations

Univariate methods miss combinations

Walk the escalation: a small transaction — normal. A midnight transaction — normal. Small + midnight + new device + unusual location — suspicious.

"Every univariate check passes; the combination is the crime. That's the 'rare direction' from the types picture, and it needs a multivariate method. Enter Isolation Forest."

→ "Isolation Forest."
Slide 7~4 minIsoForest picture

Isolation Forest — few splits isolate anomalies

Walk the figure: random axis-aligned splits carve the space. The lone red point is cut off by the first split — one partition and it's alone. The dense blue cluster needs split after split to isolate any member.

"Anomalies are few and different, so random partitioning isolates them quickly. Path length to isolation is the signal — short paths mean anomalous. And notice: no distances, no densities — which is why it survives high dimensions."

→ "The score."
Slide 8~3 minIsoForest score

Isolation Forest score

Walk the formula: $s = 2^{-E(h(x))/c(n)}$ — average path length across the trees, normalised by the expected path in a random binary tree. "$s \approx 1$: strong anomaly. $s \approx 0.5$: normal. Threshold typically around $s > 0.6$ — or use contamination, coming later."

→ "The density-based rival."
Slide 9~4 minLOF

LOF — local density matters

Walk the idea: compare each point's local density to its neighbours' densities. LOF ≈ 1 — same density as the neighbourhood, normal. LOF > 1.5 — anomalous relative to local context. "This is the right choice when clusters have different densities — a point can be normal for a sparse cluster and anomalous next to a dense one."

Then the blind spot — the lesson's key warning: "Masking. A tight group of $\geq k$ anomalies are each other's nearest neighbours — locally, the fraud ring is the dense region, and every member scores LOF ≈ 1. Pick $k$ larger than the biggest group you must catch. The worked example will show this failing live."

→ "The full method map."
Slide 10~3 minMethod matrix

Method × outlier type matrix

Walk the table row by row. Extreme single feature: everything catches it. Strange combination: univariate misses; IsoForest and LOF catch. Local density anomaly: LOF's home turf; IsoForest partial. Tight group — the application ring: Z-score only if far out, IsoForest yes, LOF fails unless $k$ exceeds the group size — the masking row. High-dimensional: IsoForest.

"There is no universal winner — which is the honest argument for blending, next."

→ "Blend the scores."
Slide 11~4 minScore blending

Score blending — often more robust, never guaranteed

Walk the code: min-max normalise each detector's scores onto a common scale — z-scores absolutised, Isolation Forest and LOF negated so higher means more anomalous — then average and flag above 0.7.

Read the paragraph with care: "Blending helps when detectors make different mistakes. But a detector blind to an anomaly type dilutes the ones that catch it — a blend can score below its best member. Always compare the blend against each member on a labelled review sample before trusting it."

→ "The Kailash engine wraps this."
Slide 12~4 minAnomalyDetectionEngine

Kailash AnomalyDetectionEngine

Walk the code. detect(algorithm="isolation_forest", contamination=0.01) returns scores in [0, 1], higher = more anomalous. ensemble_detect with voting="score_average" is the manual blend from the previous slide in one call — normalised scores, averaged.

Read the teal box: "The engine flips sklearn's sign convention — higher is always more anomalous — and normalises to [0, 1]. And a boundary to respect: EnsembleEngine.blend() / .stack() are supervised classifier ensembles — they need a target column. Don't blend anomaly scores with them. That's the next slide's proper use."

→ "When labels arrive: the supervised second stage."
Slide 13~4 minSupervised second stage

Once analysts label a review sample: EnsembleEngine

Set the sequence: unsupervised screening produces a review queue; analysts label a sample; now a supervised stage learns which detector to trust. Walk the code: logistic regression and a random forest fitted on the detector-score columns plus the analyst labels, then EnsembleEngine.blend (soft vote) and .stack (meta-learner) with their AUCs.

Read the footer: "A supervised second stage: classifiers learn from the detector scores which detector to trust. It needs labels, so it comes after unsupervised screening — never instead of it."

→ "The benchmark."
Slide 14~5 minWorked screening

Worked example: credit-application screening

Walk the code: 20,000 real applications plus 200 injected, labelled anomalies from the ex_4 loader — the labels are used only to score, never to fit. Isolation Forest and LOF at contamination 0.01, both negated so higher = more anomalous, then AUC against the injected truth.

Walk the table by anomaly type. Globals (one field 5–8σ out): Z-score and LOF near-perfect at 0.995; IsoForest 0.77 — its random splits waste cuts on normal features. Synthetic identity (subtle combination): LOF 0.99 at both k, IsoForest 0.68, Z-score useless at 0.55. The application ring — 40 tight coordinated anomalies: LOF at k=20 collapses to 0.22 — masked, worse than chance — while k=50 recovers to 0.89. "The masking trap, live: 40 fraudsters were each other's neighbourhood. $k$ must exceed the group you're hunting."

→ "One knob to rule the flag count."
Slide 15~3 minContamination

Contamination matters

Walk the bullets. Isolation Forest and LOF need contamination — the approximate anomaly fraction. Too high: false positives explode. Too low: real anomalies missed. Rule of thumb: start at the real base rate, then tune by inspecting the top-$k$ flagged rows.

Two closing truths: "Contamination only moves the cut-off — it never changes the ranking, so AUC comparisons are contamination-free. And the amber warning: without labels there is no precision or recall — you must inspect manually. The review queue is the product."

→ "Four mistakes."
Slide 16~3 minMistakes

Four rookie mistakes

Walk the four. One: contamination 10% when the real rate is 0.1% — you flag a hundred times too many and drown the review team. Two: Z-score on right-skewed data without a log transform. Three: unscaled features in multivariate methods — dollars dominate years again. Four: treating raw anomaly scores as probabilities across methods — that's what the normalisation in the blend is for.

→ "Production context: rows vs distributions."
Slide 17~3 minProduction

Production: rows vs distributions

Draw the boundary precisely. "Anomaly detection flags individual unusual rows — and the anomaly rate over time becomes an early-warning signal. Drift monitoring compares whole distributions: kailash-ml's DriftMonitor from M3.8 runs PSI and KS tests against a reference set. It is not an anomaly detector — different question, different tool."

Walk the code: the DriftMonitor pattern is the same as M3.8 — own database file, reference from the training frame, check_drift per batch. "Exercise 4.4 plots the ensemble's anomaly rate over time as the monitoring chart — rows today, distributions in M3.8, both feeding the same operations loop."

→ "Recap and bridge."
Slide 18~2 minRecap

What you can now do

Walk the bullets: apply the four detectors, explain which outlier type each catches, blend scores and verify the blend beats its best member, use AnomalyDetectionEngine with EnsembleEngine as the supervised second stage, and recognise when unsupervised detection won't work. Tease 4.5: "What co-occurs in transactional data? Association rules."
