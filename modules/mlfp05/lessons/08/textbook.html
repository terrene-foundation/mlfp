Lesson 5.8 Reinforcement Learning

All deep learning so far learns from static data — images, text, sequences, graphs. Reinforcement learning (RL) learns from interaction with an environment. The agent takes actions, receives rewards, and learns a policy that maximises cumulative reward. Today you derive the Bellman equations from first principles, implement DQN (Deep Q-Network) with a target network for a discrete-action customer‑churn problem, implement PPO (Proximal Policy Optimization) with a clipped objective for a continuous‑action inventory problem, build custom Gymnasium environments, meet A2C, DDPG and SAC, and understand the bridge from PPO to RLHF — the technique that aligns LLMs with human preferences in M6. (Exercise 8 hand‑writes DQN and PPO on discrete‑action environments; this page adds the continuous case.)

Why This Matters

Supervised learning needs a dataset: pairs of inputs and correct outputs. But many real-world problems have no "correct output" — only a reward signal that tells you how well you did. A port operator wants to minimise container ship waiting time — there is no labelled dataset of optimal schedules, only the daily reality of ships, berths, cranes, and delays. A bank's pricing team wants to set deposit rates that balance profit and customer retention — the "correct" rate depends on market conditions and on how customers react, which only shows up after the decision.

RL learns through trial and error: try an action, observe the consequence, adjust the policy, repeat. This makes it uniquely suited to sequential decision-making where the optimal action depends on state and future consequences — not just the current input.

More importantly for your M6 journey: RLHF (Reinforcement Learning from Human Feedback) uses PPO to align LLMs with human preferences. Understanding PPO here makes RLHF (and its successor DPO) in Lesson 6.3 straightforward instead of mysterious.

Foundations

Think of RL as learning to ride a bicycle. Nobody gives you a dataset of "correct handlebar angles" — instead, you try steering, fall over (negative reward), adjust, try again, and eventually learn a policy that keeps you upright. The reward signal (staying balanced vs falling) is the only feedback. Every RL problem has this structure: an agent that acts in an environment, receives rewards, and improves through experience.

Value-based vs policy-based methods

Value-based (DQN)

Learn $Q(s, a)$: the value of taking action $a$ in state $s$. Select the action with the highest Q-value. Works for discrete action spaces (choose from a finite set).

Examples: buy/hold/sell a stock, route a package to warehouse A/B/C.

Policy-based (PPO)

Learn $\pi(a|s)$ directly: a probability distribution over actions given state. Sample actions from the distribution. Works for discrete actions (a categorical distribution — Exercise 8's PPO) and continuous ones (e.g. a Normal distribution — Worked Example 1 below).

Examples: set an interest rate (any value in [0%, 15%]), control a robot arm (joint angles).

Math Foundations

The Bellman expectation equation

The value of a state is the expected immediate reward plus the discounted value of the next state. This recursive definition is the foundation of all RL algorithms:

$$ V^\pi(s) = \mathbb{E}_\pi\bigl[R_{t+1} + \gamma\, V^\pi(S_{t+1}) \mid S_t = s\bigr] $$
$V^\pi(s)$ — value of state $s$ under policy $\pi$ $R_{t+1}$ — immediate reward $\gamma$ — discount factor (typically 0.99) $\mathbb{E}_\pi$ — expectation under policy $\pi$

In words: "The value of being in state $s$ and following policy $\pi$ is the reward I expect to get immediately, plus the discounted value of wherever I end up next." This is recursive — to know $V(s)$ you need $V(s')$ — which is why RL algorithms iterate until convergence.

The Bellman optimality equation

The optimal policy $\pi^*$ selects the action that maximises the action-value:

$$ Q^*(s, a) = \mathbb{E}\bigl[R_{t+1} + \gamma\,\max_{a'} Q^*(S_{t+1}, a') \mid S_t = s, A_t = a\bigr] $$
$Q^*(s,a)$ — optimal action-value function $\max_{a'}$ — best action in the next state $R_{t+1} + \gamma\,\max_{a'} Q^*$ — bootstrap target

The key difference from the expectation equation: the max over actions. The optimal Q-function assumes you will make the best possible decision at every future step.

Theory

The Bellman equations are instances of dynamic programming — breaking an optimisation problem into overlapping sub-problems. Each state's value depends on future states' values, creating a system of equations. In tabular settings (small state space), you solve these equations directly. In deep RL (large or continuous state spaces), you approximate the value function with a neural network and solve iteratively via gradient descent.

Connecting to M5.8 → M6.3

In RLHF, the "environment" is a reward model that scores LLM outputs. The "state" is the prompt plus the tokens generated so far. The "action" is the next token — a choice from a discrete vocabulary. The "reward" is the reward model's score of the finished response. PPO fine‑tunes the LLM to maximise this reward, while a separate KL penalty to the original (SFT) model keeps it from drifting too far. Understanding PPO here makes RLHF mechanical, not magical.

DQN — Deep Q-Network

DQN (Mnih et al., 2015) approximates $Q^*(s, a)$ with a neural network. Two innovations make this stable:

  1. Experience replay buffer: store past transitions $(s, a, r, s')$ and sample random mini-batches for training. This breaks the correlation between consecutive samples that would otherwise destabilise SGD.
  2. Target network: a slow-updating copy of the Q-network used to compute the target $r + \gamma \max_{a'} Q_{\text{target}}(s', a')$. Without it, the target changes with every gradient step, creating a moving-target problem.

DQN loss function

$$ \mathcal{L}_{\text{DQN}} = \mathbb{E}_{(s,a,r,s') \sim \mathcal{D}}\Bigl[\bigl(r + \gamma\,\max_{a'} Q(s', a'; \theta^-) - Q(s, a; \theta)\bigr)^2\Bigr] $$
$\mathcal{D}$ — replay buffer $\theta^-$ — frozen target network params $\theta$ — online Q-network params (updated)

DQN implementation

import gymnasium as gym
import numpy as np
import torch
import torch.nn as nn
from collections import deque
import random

class QNetwork(nn.Module):
    def __init__(self, state_dim, action_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim, 128), nn.ReLU(),
            nn.Linear(128, 128), nn.ReLU(),
            nn.Linear(128, action_dim)
        )

    def forward(self, x):
        return self.net(x)

class ReplayBuffer:
    def __init__(self, capacity=10000):
        self.buffer = deque(maxlen=capacity)

    def push(self, state, action, reward, next_state, done):
        self.buffer.append((state, action, reward, next_state, done))

    def sample(self, batch_size):
        batch = random.sample(self.buffer, batch_size)
        states, actions, rewards, next_states, dones = zip(*batch)
        return (torch.FloatTensor(np.array(states)),
                torch.LongTensor(actions),
                torch.FloatTensor(rewards),
                torch.FloatTensor(np.array(next_states)),
                torch.FloatTensor(dones))

class DQNAgent:
    def __init__(self, state_dim, action_dim, lr=1e-3, gamma=0.99):
        self.action_dim = action_dim
        self.q_net = QNetwork(state_dim, action_dim)
        self.target_net = QNetwork(state_dim, action_dim)
        self.target_net.load_state_dict(self.q_net.state_dict())
        self.optimizer = torch.optim.Adam(self.q_net.parameters(), lr=lr)
        self.buffer = ReplayBuffer()
        self.gamma = gamma
        self.epsilon = 1.0  # Exploration rate

    def select_action(self, state):
        if random.random() < self.epsilon:
            return random.randrange(self.action_dim)  # Explore: ANY action
        with torch.no_grad():
            q_values = self.q_net(torch.FloatTensor(state))
            return q_values.argmax().item()  # Exploit

    def train_step(self, batch_size=64):
        if len(self.buffer.buffer) < batch_size:
            return
        states, actions, rewards, next_states, dones = \
            self.buffer.sample(batch_size)

        # Current Q-values
        q_values = self.q_net(states).gather(1, actions.unsqueeze(1)).squeeze(1)

        # Target Q-values (from frozen target network)
        with torch.no_grad():
            next_q = self.target_net(next_states).max(1)[0]
            targets = rewards + self.gamma * next_q * (1 - dones)

        loss = nn.functional.mse_loss(q_values, targets)
        self.optimizer.zero_grad()
        loss.backward()
        self.optimizer.step()

    def update_target(self):
        self.target_net.load_state_dict(self.q_net.state_dict())

PPO — Proximal Policy Optimization

DQN learns which actions are valuable (value-based). PPO directly learns which actions to take (policy-based). It maintains two networks: an actor (policy $\pi_\theta$) and a critic (value function $V_\phi$).

The clipped objective

PPO's key innovation is the clipped surrogate objective that prevents destructively large policy updates:

$$ L^{\text{CLIP}} = \mathbb{E}_t\Bigl[\min\bigl(r_t(\theta)\,\hat{A}_t,\;\text{clip}\bigl(r_t(\theta),\,1-\epsilon,\,1+\epsilon\bigr)\,\hat{A}_t\bigr)\Bigr] $$
$r_t(\theta) = \frac{\pi_\theta(a_t | s_t)}{\pi_{\theta_{\text{old}}}(a_t | s_t)}$ — probability ratio $\hat{A}_t$ — advantage estimate (how much better than average) $\epsilon \approx 0.2$ — clip range

The probability ratio $r_t$ measures how much the new policy differs from the old policy. If $r_t$ has already moved past $1 \pm \epsilon$ in the direction the advantage favours (above $1+\epsilon$ when $\hat{A}_t > 0$, below $1-\epsilon$ when $\hat{A}_t < 0$), the clipped term is selected by the min and its gradient is zero, so there is no incentive to move further. If the ratio has moved the wrong way (say $r_t < 1-\epsilon$ with $\hat{A}_t > 0$), the unclipped term is selected and the full gradient pulls it back. This keeps each policy update proximal — close to the old policy — and prevents destructively large updates.

Theory

PPO is a simplification of TRPO (Trust Region Policy Optimization). TRPO constrains the KL divergence between old and new policies, which requires computing second-order derivatives (expensive). PPO achieves a similar effect with the simple clipping trick — first-order optimisation only. This makes PPO the de facto standard for policy optimisation, including in RLHF where it is used to align LLMs (M6.3).

The advantage function

The advantage $\hat{A}_t$ measures how much better an action was compared to the average action from that state. PPO uses Generalised Advantage Estimation (GAE):

$$ \hat{A}_t = \sum_{l=0}^{T-t} (\gamma\lambda)^l \delta_{t+l} \qquad\text{where}\qquad \delta_t = r_t + \gamma V(s_{t+1}) - V(s_t) $$
$\delta_t$ — TD error (temporal difference) $\lambda \approx 0.95$ — GAE parameter (bias-variance tradeoff) $V(s)$ — critic's value estimate

Custom Gymnasium Environments

Gymnasium (the successor to OpenAI Gym) provides a standard interface for RL environments. You subclass gymnasium.Env and implement four methods: 

import gymnasium as gym
from gymnasium import spaces
import numpy as np

class SupplyChainEnv(gym.Env):
    """Daily ordering for one product over a 90-day quarter (SYNTHETIC demand).

    State:  [inventory, yesterday's demand, days remaining]
    Action: order quantity in [0, 30] units, delivered the same day (continuous)
    Reward: -(holding + lost-sales penalty + ordering) cost, in S$100s
    """
    def __init__(self, max_days=90):
        super().__init__()
        self.max_days = max_days
        self.action_space = spaces.Box(low=0.0, high=30.0, shape=(1,), dtype=np.float32)
        self.observation_space = spaces.Box(
            low=np.array([0.0, 0.0, 0.0], dtype=np.float32),
            high=np.array([np.inf, np.inf, max_days], dtype=np.float32),
        )
        self.holding_cost = 0.5     # S$ per unit held overnight
        self.lost_sale_cost = 10.0  # S$ per unit of demand we could not serve
        self.order_cost = 2.0       # S$ per unit ordered

    def reset(self, seed=None, options=None):
        super().reset(seed=seed)                                    # seeds self.np_random
        self.inventory, self.last_demand, self.day = 50.0, 10.0, 0
        return self._obs(), {}

    def step(self, action):
        order = float(np.clip(action[0], 0.0, 30.0))
        demand = max(0.0, self.np_random.normal(10.0, 3.0))       # mean 10 units/day
        available = self.inventory + order
        sold = min(available, demand)
        lost = demand - sold
        self.inventory = available - sold                           # never negative: lost sales
        self.last_demand, self.day = demand, self.day + 1
        cost = self.holding_cost * self.inventory + self.lost_sale_cost * lost + self.order_cost * order
        terminated = self.day >= self.max_days                      # the quarter is over
        return self._obs(), -cost / 100.0, terminated, False, {}

    def _obs(self):
        return np.array([self.inventory, self.last_demand, self.max_days - self.day], dtype=np.float32)

env = SupplyChainEnv()
obs, _ = env.reset(seed=0)
print(env.observation_space.contains(obs))      # True — observations respect the declared space

The five methods a Gymnasium environment needs: __init__ declares the action_space and observation_space; reset starts an episode (calling super().reset(seed=seed) seeds self.np_random, so episodes are reproducible); step returns the 5‑tuple (obs, reward, terminated, truncated, info). terminated means the task itself ended (the quarter is over, the customer churned); truncated means an outside time limit cut the episode short. A training loop must stop on either. Unmet demand is lost rather than back‑ordered, so inventory never goes negative and every observation stays inside the declared space.

Worked Example 1: PPO for Continuous Ordering

Goal

Train a PPO agent with a continuous action (how many units to order each day) on the synthetic SupplyChainEnv, and compare it with the textbook inventory rule it should rediscover. Runs in under a minute on a laptop CPU.

Step 1. A Gaussian actor and a value critic. 
import torch
import torch.nn as nn

class ActorCritic(nn.Module):
    """Gaussian policy for a 1-D continuous action + a state-value critic."""
    def __init__(self, obs_dim=3, hidden=64):
        super().__init__()
        self.scale = torch.tensor([50.0, 20.0, 90.0])               # rough feature scales
        self.actor = nn.Sequential(nn.Linear(obs_dim, hidden), nn.Tanh(), nn.Linear(hidden, 1))
        self.critic = nn.Sequential(nn.Linear(obs_dim, hidden), nn.Tanh(), nn.Linear(hidden, 1))
        self.log_std = nn.Parameter(torch.tensor([1.5]))            # std ~4.5 units at start

    def dist(self, obs):
        mean = 15.0 + 10.0 * self.actor(obs / self.scale)          # centred inside [0, 30]
        return torch.distributions.Normal(mean, self.log_std.exp())

    def value(self, obs):
        return self.critic(obs / self.scale).squeeze(-1)

For a continuous action the policy outputs a distribution — here a Normal with a learned mean and a learned (state‑independent) standard deviation. Exploration comes from sampling it; as training proceeds the standard deviation shrinks.

Step 2. Collect a rollout, compute GAE advantages. 
def collect(env, model, n_steps, seed):
    obs_l, act_l, logp_l, rew_l, done_l, val_l = [], [], [], [], [], []
    obs, _ = env.reset(seed=seed)
    ep_returns, ep_ret = [], 0.0
    for t in range(n_steps):
        o = torch.as_tensor(obs)
        with torch.no_grad():
            d = model.dist(o)
            a = d.sample()
            logp, v = d.log_prob(a).sum(), model.value(o)
        obs2, r, terminated, truncated, _ = env.step(a.numpy())     # env clips to [0, 30]
        obs_l.append(o); act_l.append(a); logp_l.append(logp); val_l.append(v)
        rew_l.append(r); done_l.append(terminated or truncated)
        ep_ret += r
        obs = obs2
        if terminated or truncated:
            ep_returns.append(ep_ret); ep_ret = 0.0
            obs, _ = env.reset()
    with torch.no_grad():
        last_v = model.value(torch.as_tensor(obs))
    return (torch.stack(obs_l), torch.stack(act_l), torch.stack(logp_l), torch.tensor(rew_l),
            torch.tensor(done_l, dtype=torch.float32), torch.stack(val_l), last_v, ep_returns)

def gae(rew, done, val, last_v, gamma=0.99, lam=0.95):
    adv = torch.zeros_like(rew)
    next_v, running = last_v, 0.0
    for t in reversed(range(len(rew))):
        nonterminal = 1.0 - done[t]
        delta = rew[t] + gamma * next_v * nonterminal - val[t]     # TD error
        running = delta + gamma * lam * nonterminal * running
        adv[t] = running
        next_v = val[t]
    return adv, adv + val                                           # advantages, critic targets
Step 3. The clipped PPO update, and the training loop. 
def ppo_update(model, opt, obs, act, old_logp, adv, ret, clip=0.2, epochs=10, batch=256):
    adv = (adv - adv.mean()) / (adv.std() + 1e-8)                 # normalise advantages
    for _ in range(epochs):
        for idx in torch.randperm(len(obs)).split(batch):
            d = model.dist(obs[idx])
            ratio = (d.log_prob(act[idx]).sum(-1) - old_logp[idx]).exp()
            surr = torch.min(ratio * adv[idx], ratio.clamp(1 - clip, 1 + clip) * adv[idx])
            v_loss = (model.value(obs[idx]) - ret[idx]).pow(2).mean()
            loss = -surr.mean() + 0.5 * v_loss - 0.001 * d.entropy().mean()
            opt.zero_grad(); loss.backward()
            nn.utils.clip_grad_norm_(model.parameters(), 0.5)
            opt.step()

torch.manual_seed(0)
env = SupplyChainEnv()
model = ActorCritic()
opt = torch.optim.Adam(model.parameters(), lr=3e-4)
for it in range(60):                                               # 60 x 2,048 steps
    obs, act, logp, rew, done, val, last_v, ep_returns = collect(env, model, 2048, seed=it)
    adv, ret = gae(rew, done, val, last_v)
    ppo_update(model, opt, obs, act, logp, adv, ret)
    if it % 10 == 0:
        print(f"iter {it:2d}: mean episode return {np.mean(ep_returns):7.2f}")

ratio.clamp(...) and torch.min are the clipped objective $L^{\text{CLIP}}$ term for term. On our run (12 seconds on CPU) the mean quarterly return rose from −190 (S$19,000 of cost per quarter under the random initial policy) to −21 by iteration 50, and the policy's standard deviation shrank from 4.4 to 2.0 units.

Step 4. Compare with the classical rule. 
def run(policy, n=50, seed0=1000):
    totals = []
    for i in range(n):
        obs, _ = env.reset(seed=seed0 + i)
        total, done = 0.0, False
        while not done:
            obs, r, terminated, truncated, _ = env.step(policy(obs))
            total += r
            done = terminated or truncated
        totals.append(total)
    return np.mean(totals)

ppo = lambda o: model.dist(torch.as_tensor(o)).mean.detach().numpy()     # act on the mean
order_up_to = lambda S: (lambda o: np.array([max(0.0, S - o[0])], dtype=np.float32))
print(run(ppo))                                                            # about -20.2
print(max((run(order_up_to(S)), S) for S in range(8, 31, 2)))             # about (-20.1, 14)
print(run(lambda o: np.array([10.0], dtype=np.float32)))                  # about -40.8

Inventory theory says the optimal policy for this problem is an order‑up‑to rule: each day, order enough to bring stock up to a level $S$. The best such rule on 50 test quarters ($S = 14$) cost −20.1; the PPO policy cost −20.2 — essentially the same — while "order the mean demand (10) every day" cost −40.8, because it lets stock drift into lost sales. Probing the learned policy shows why: it orders about 13 units at zero inventory, 10 at 5, 7 at 10 and nothing above about 22 — close to "order 14 minus what you hold". PPO rediscovered the classical rule from rewards alone.

Worked Example 2: DQN for Customer Churn Prevention

Goal

Train the DQN agent above on Exercise 8's hypothetical, synthetic churn environment (file 03): each episode is one customer over 30 days; each day the agent chooses among four discrete retention actions, and the customer may churn. Then compare the learned policy with simple fixed rules.

Step 1. The environment (as in Exercise 8, file 03). 
class ChurnPreventionEnv(gym.Env):
    """State: [satisfaction, usage, months_active, support_tickets], all in [0, 1].
    Actions: 0 nothing, 1 discount ($1), 2 support call ($0.50), 3 feature upgrade ($1.50).
    Reward: +1 per day retained minus action cost, -5 on churn, +10 bonus for a full month."""

    def __init__(self):
        super().__init__()
        self.observation_space = spaces.Box(low=0.0, high=1.0, shape=(4,), dtype=np.float32)
        self.action_space = spaces.Discrete(4)
        self.max_steps = 30

    def reset(self, seed=None, options=None):
        super().reset(seed=seed)
        self.state = self.np_random.uniform(0.2, 0.8, size=(4,)).astype(np.float32)
        self.step_count = 0
        return self.state.copy(), {}

    def step(self, action):
        self.step_count += 1
        satisfaction, usage, tenure, tickets = self.state
        cost = 0.0
        if action == 1:                                   # discount
            satisfaction, usage, cost = min(1.0, satisfaction + 0.1), min(1.0, usage + 0.05), 1.0
        elif action == 2:                                 # support call
            tickets, satisfaction, cost = max(0.0, tickets - 0.15), min(1.0, satisfaction + 0.05), 0.5
        elif action == 3:                                 # feature upgrade
            usage, cost = min(1.0, usage + 0.1), 1.5
        satisfaction = float(np.clip(satisfaction - 0.02 + self.np_random.normal(0, 0.02), 0.0, 1.0))
        usage = max(0.0, min(1.0, usage - 0.01 + self.np_random.normal(0, 0.02)))
        tickets = max(0.0, min(1.0, tickets + 0.02 + self.np_random.normal(0, 0.01)))
        tenure = min(1.0, tenure + 1.0 / self.max_steps)
        self.state = np.array([satisfaction, usage, tenure, tickets], dtype=np.float32)

        churn_prob = max(0.0, 0.3 - satisfaction * 0.4 + tickets * 0.3)
        terminated = bool(self.np_random.random() < churn_prob)       # the customer left
        reward = -5.0 if terminated else 1.0 - cost
        truncated = self.step_count >= self.max_steps                 # the month is over
        if truncated and not terminated:
            reward += 10.0                                              # retained all month
        return self.state.copy(), reward, terminated, truncated, {}
Step 2. Train the DQN agent. 
random.seed(0); np.random.seed(0); torch.manual_seed(0)
env = ChurnPreventionEnv()
agent = DQNAgent(state_dim=4, action_dim=4)

for episode in range(400):
    state, _ = env.reset(seed=episode)
    total_reward, done = 0.0, False
    while not done:
        action = agent.select_action(state)
        next_state, reward, terminated, truncated, _ = env.step(action)
        done = terminated or truncated                    # stop on EITHER
        # bootstrap through a time-limit cut, not through a real ending
        agent.buffer.push(state, action, reward, next_state, float(terminated))
        agent.train_step()
        total_reward += reward
        state = next_state
    agent.epsilon = max(0.05, agent.epsilon * 0.99)       # decay exploration
    if episode % 10 == 0:
        agent.update_target()                             # refresh the target network
    if episode % 100 == 0:
        print(f"Episode {episode}: reward={total_reward:.1f}, epsilon={agent.epsilon:.3f}")

Note the two different "done" signals: the loop stops on terminated or truncated, but the replay buffer stores only terminated as the end of the value chain — a month that ended because the clock ran out is not a state with zero future value. Training takes a few seconds.

Step 3. Evaluate against fixed rules. 
def evaluate(policy, n=200, seed0=10_000):
    totals, retained, counts = [], 0, np.zeros(4, dtype=int)
    for i in range(n):
        state, _ = env.reset(seed=seed0 + i)               # customers never seen in training
        total, done, terminated = 0.0, False, False
        while not done:
            a = policy(state)
            counts[a] += 1
            state, r, terminated, truncated, _ = env.step(a)
            total += r
            done = terminated or truncated
        totals.append(total)
        retained += not terminated
    return np.mean(totals), retained / n, counts / counts.sum()

agent.epsilon = 0.0                                        # greedy for evaluation
for name, policy in [("DQN", agent.select_action), ("do nothing", lambda s: 0),
                     ("random", lambda s: random.randrange(4)), ("always call", lambda s: 2)]:
    mean_r, kept, mix = evaluate(policy)
    print(f"{name:12s} reward {mean_r:5.1f}  retained {kept:.0%}  action mix {np.round(mix, 2)}")

On 200 held‑out customers our run gave: DQN mean reward 11.0 with 46% of customers retained for the month; "always call" 8.0 (42%); random −1.1 (14%); "do nothing" −2.5 (0% — in this environment every untreated customer eventually churns). The DQN's action mix was 40% nothing, 16% discount, 44% support call and no feature upgrades: it learned that the cheap support call is the most effective lever, and that it pays to skip it when the customer is healthy. Two more seeds gave 8.2 and 9.5 — the DQN matched or beat the best fixed rule each time, by a modest margin.

Beyond DQN and PPO: A2C, DDPG and SAC

Five algorithms cover most applied deep RL. You have now implemented the two most important; the other three are variations on the same ingredients (and are available through km.rl_train once the RL extra is installed).

AlgorithmFamilyActionsKey idea
DQNValue‑based, off‑policyDiscreteQ‑network + replay buffer + target network

DDPGActor–critic, off‑policyContinuousA deterministic actor $\mu(s)$ trained to maximise a learned $Q(s, \mu(s))$, with replay and target networks — "DQN for continuous actions"; explores by adding noise to actions; sample‑efficient but brittle
SACActor–critic, off‑policyContinuousA stochastic actor maximising reward plus policy entropy, $\mathbb{E}[\sum_t r_t + \alpha \mathcal{H}(\pi(\cdot \mid s_t))]$, with twin Q‑networks to curb over‑estimation; the usual first choice for continuous control when simulation is expensive

Rule of thumb: on‑policy methods (A2C, PPO) learn only from data collected by the current policy — simple and stable, but they need many environment steps. Off‑policy methods (DQN, DDPG, SAC) learn from a replay buffer of old experience — far more sample‑efficient, which matters when each step is a real customer or an expensive simulation.

DPO (Direct Preference Optimization) in M6.3 bypasses the reward model entirely — it derives the optimal policy directly from preference pairs, removing the RL loop. This is why DPO is simpler to implement: no reward model, no PPO, no replay buffer. But understanding PPO makes DPO's derivation transparent.

Common Mistakes

Mistake 1: Reward shaping too complex

Start with simple, sparse rewards: +1 for success, -1 for failure. Complex reward functions with many terms create unexpected optima — the agent finds ways to maximise reward that do not correspond to the desired behaviour (reward hacking). Add shaping terms only if the agent fails to learn with simple rewards.

Mistake 2: No advantage normalisation

PPO needs normalised advantages — subtract mean and divide by standard deviation. Without normalisation, advantages with large magnitude cause instability: the probability ratio $r_t$ swings wildly, overwhelming the clipping mechanism.

Mistake 3: Too-small replay buffer

DQN's replay buffer should hold at least 10,000-100,000 transitions. A small buffer causes the agent to train on recent, correlated samples — defeating the purpose of experience replay. The buffer should be large enough that samples from different episodes and strategies are mixed.

Mistake 4: Not enough exploration

Without exploration, DQN converges to the first decent policy it finds and never discovers better ones. Use epsilon-greedy with a slow decay: $\epsilon$ starts at 1.0 (pure random) and decays to 0.01 over thousands of episodes. Too-fast decay causes premature convergence.
