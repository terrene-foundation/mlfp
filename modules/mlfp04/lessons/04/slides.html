Anomaly Detection and Ensembles

Z-score · IQR · Isolation Forest · LOF · Blending · AnomalyDetectionEngine

⏱ 75 minutes   ·   Outcome: screen credit applications for anomalies without labels

The opposite question

  • Clustering: "Which group does this point belong to?"
  • Anomaly detection: "Which points don't belong to any group?"
  • Use cases: fraud, defects, sensor faults, intrusions, churn precursors.
🟢 Foundations: anomalies are rare. If "anomalies" are 20% of your data, you have a classification problem, not an anomaly detection one.

Three types of outliers

Different methods catch different types.

Z-score: univariate, assumes normality

\[ z_i \;=\; \frac{x_i - \bar x}{s}\qquad |z_i| > 3\ \Rightarrow\ \text{flag} \]
  • Simple, fast, one-line.
  • Breaks on right-skewed data (revenue, session length).
  • Outliers inflate $\bar x$ and $s$, hiding each other.

IQR: robust to skew

\[ \text{flag if } x < Q_1 - 1.5\,\text{IQR} \quad\text{or}\quad x > Q_3 + 1.5\,\text{IQR} \]
  • Quartiles are not affected by a few extreme values.
  • This is what box-plot whiskers use.
  • Default univariate detector for business data.
🔵 Theory: winsorisation = cap at IQR bounds instead of dropping. Preserves sample size for downstream stats.

Univariate methods miss combinations

  • Small transaction: normal.
  • Midnight transaction: normal.
  • Small + midnight + new device + unusual location: suspicious.

Need a multivariate method. Enter Isolation Forest.

Isolation Forest — few splits isolate anomalies

Isolation Forest score

\[ s(\mathbf{x}, n) \;=\; 2^{-E(h(\mathbf{x}))/c(n)} \]
  • $E(h(\mathbf{x}))$ = average path length across trees.
  • $c(n)$ = expected path in random binary tree.
  • $s \approx 1$ → strong anomaly. $s \approx 0.5$ → normal.
  • Threshold: typically $s > 0.6$.

LOF — local density matters

\[ \text{LOF}_k(\mathbf{x}) \;=\; \frac{1}{|N_k|}\sum_{\mathbf{o}\in N_k}\ \frac{\text{lrd}_k(\mathbf{o})}{\text{lrd}_k(\mathbf{x})} \]
  • Compares point density to neighbour density.
  • LOF ≈ 1: same density → normal.
  • LOF > 1.5: anomalous relative to local context.
  • Right choice when clusters have different densities.
  • Blind spot (masking): a tight group of $\ge k$ anomalies are each other's neighbours, so each looks normal (LOF ≈ 1). Pick $k$ larger than the biggest group you must catch.

Score blending — often more robust, never guaranteed


def normalise(x):
    return (x - x.min()) / (x.max() - x.min() + 1e-9)

z_s = normalise(np.abs(z_scores))
if_s = normalise(-iforest.decision_function(X))
lof_s = normalise(-lof.negative_outlier_factor_)

blended = (z_s + if_s + lof_s) / 3
anomalies = blended > 0.7

Blending helps when detectors make different mistakes. A detector blind to an anomaly type dilutes the ones that catch it, so a blend can score below its best member — always compare on a labelled review sample.

Kailash AnomalyDetectionEngine


from kailash_ml.engines.anomaly_detection import AnomalyDetectionEngine

# X: a polars frame of numeric, standardised features
detector = AnomalyDetectionEngine()  # isolation_forest | lof | one_class_svm
iso = detector.detect(X, algorithm="isolation_forest", contamination=0.01)

⚙ Kailash: the engine flips sklearn's sign convention (higher = more anomalous) and normalises to [0, 1] — the manual blend in one call. EnsembleEngine.blend() / .stack() are supervised classifier ensembles: they need a target column.
This is the engine the exercises and the assessment's anomaly task use. ensemble_detect with voting="score_average" averages the normalised scores (the previous slide); the default "majority" votes on labels. Contamination only moves the cut-off, never the ranking. Do NOT use EnsembleEngine.blend to blend anomaly scores — it soft/hard-votes fitted classifiers against a target and does its own train/test split. That is the next slide.

Once analysts label a review sample: EnsembleEngine


from kailash_ml import EnsembleEngine
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression

# score_frame: one column per detector score + "is_anomaly" from analyst review
logreg = LogisticRegression(max_iter=1000).fit(X_review, y_review)
forest = RandomForestClassifier(n_estimators=200, random_state=42).fit(X_review, y_review)

engine = EnsembleEngine()
blended = engine.blend([logreg, forest], holdout_frame, "is_anomaly",
                       weights=[0.5, 0.5], method="soft")
stacked = engine.stack([logreg, forest], holdout_frame, "is_anomaly")
print(blended.metrics["auc"], stacked.metrics["auc"])

A supervised second stage: classifiers learn from the detector scores which detector to trust. It needs labels, so it comes after unsupervised screening — never instead of it.

Mirrors Exercise 4.4 part (E). The base classifiers are fitted on the labelled review sample; the holdout frame goes to the engine, which does its own 80/20 split and reports AUC. blend() soft-votes predicted probabilities; stack() trains a meta-learner (logistic regression by default) on the base models' predictions.

Worked example: credit-application screening

Contamination matters

  • Isolation Forest / LOF need contamination — approx. anomaly fraction.
  • Set too high → false positives explode.
  • Set too low → real anomalies missed.
  • Rule of thumb: start with the real base rate, then tune by inspecting top-$k$.
  • Contamination only moves the cut-off — it never changes the ranking.
⚠ Warning: there is no precision/recall without labels. You must inspect manually.

Four rookie mistakes

  1. Contamination set to 10% when the real rate is 0.1% — you flag 100× too many.
  2. Z-score on right-skewed data without log-transform.
  3. Unscaled features in multivariate methods.
  4. Treating raw anomaly scores as probabilities across methods.

Production: rows vs distributions

  • Anomaly detection flags individual unusual rows; the anomaly rate over time is an early-warning signal.
  • Drift monitoring compares whole distributions: kailash-ml's DriftMonitor (M3.8) runs PSI and KS tests against a reference set — not an anomaly detector.
