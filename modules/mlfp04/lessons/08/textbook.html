Lesson 4.8 DL Foundations — Neural Networks and the Training Toolkit

In Lesson 4.7 you watched matrix factorisation learn embeddings by minimising reconstruction error. A neural network does the exact same thing — hidden layer activations ARE embeddings, learned by minimising a loss function. The difference: neural networks can learn non-linear combinations through activation functions. Today you build a neural network from scratch — forward pass, backpropagation, gradient descent — then equip it with the full training toolkit: activations, dropout, batch normalisation, optimisers, learning rate schedules, and early stopping. This toolkit is your equipment for every architecture in Module 5.

The Bridge from Matrix Factorisation

In 4.7, matrix factorisation decomposed $R \approx U V^T$. The rows of $U$ and $V$ are embeddings — features discovered by optimisation. A neural network generalises this:

Core Concepts

Neural network architecture

A feedforward neural network is a stack of layers. Each layer computes $\mathbf{z} = W\mathbf{x} + \mathbf{b}$ (a linear transformation) followed by an activation function $\mathbf{a} = f(\mathbf{z})$ (a non-linear transformation).

Forward pass

For each layer $l$:

$$ \mathbf{z}^{(l)} = W^{(l)} \mathbf{a}^{(l-1)} + \mathbf{b}^{(l)} \qquad \mathbf{a}^{(l)} = f\bigl(\mathbf{z}^{(l)}\bigr) $$

The final $\mathbf{a}^{(L)}$ is the prediction $\hat{y}$. The loss $\mathcal{L}(\hat{y}, y)$ measures how far the prediction is from the target.

Backpropagation

Backpropagation computes $\partial \mathcal{L} / \partial W^{(l)}$ for every layer by applying the chain rule backward through the network:

$$ \frac{\partial \mathcal{L}}{\partial W^{(l)}} = \frac{\partial \mathcal{L}}{\partial \mathbf{a}^{(L)}} \cdot \frac{\partial \mathbf{a}^{(L)}}{\partial \mathbf{z}^{(L)}} \cdots \frac{\partial \mathbf{z}^{(l)}}{\partial W^{(l)}} $$

Gradient descent

Update every weight: $W \leftarrow W - \eta \, \partial \mathcal{L} / \partial W$ where $\eta$ is the learning rate.

🔵 Theory

Linear regression with zero hidden layers IS a neural network: $\hat{y} = W \mathbf{x} + b$. Adding hidden layers lets the model "write its own parametric function". The universal approximation theorem (Cybenko, 1989; Hornik, 1991) says that one hidden layer with a non-polynomial activation and enough units can approximate any continuous function on a compact domain to any desired accuracy. It guarantees that a good approximation exists, not that training will find it or how many units it needs; extra depth buys parameter efficiency — many functions need far fewer units when spread over several layers.

A ReLU unit whose input is negative for every example outputs 0 and receives zero gradient, so it never recovers — a "dead neuron". Leaky ReLU, PReLU and ELU keep a small gradient for negative inputs.

Weight initialisation

If all weights start at zero, every neuron in a layer computes the same output and receives the same gradient, so symmetry is never broken. Random initialisation fixes that, but the scale matters: Xavier/Glorot ($\mathcal{N}(0, 2/(n_{\text{in}} + n_{\text{out}}))$) suits sigmoid and tanh; Kaiming/He ($\mathcal{N}(0, 2/n_{\text{in}})$) suits ReLU, doubling the variance because ReLU zeroes about half the activations.

Dropout

Randomly zero out a fraction $p$ of the hidden activations during training (typically 0.1–0.5). This forces the network to learn redundant representations — no single neuron can be critical — and acts like training an ensemble of thinned networks. Modern implementations (including PyTorch's nn.Dropout) use inverted dropout: during training the surviving activations are scaled up by $1/(1-p)$ so their expected value is unchanged, and at inference dropout is simply switched off — no rescaling. Remember to put the model in evaluation mode before predicting.

Batch normalisation

$$ \hat{x}_i = \frac{x_i - \mu_B}{\sqrt{\sigma_B^2 + \epsilon}} \qquad y_i = \gamma \hat{x}_i + \beta $$

Normalise each layer's inputs to zero mean, unit variance, then rescale with learnable parameters $\gamma$ and $\beta$. Stabilises training and enables higher learning rates.

Optimisers

Learning rate schedules

  • Step decay: multiply the learning rate by a factor (e.g. 0.1) every $N$ epochs.
  • Cosine annealing: $\eta_t = \eta_{\min} + \tfrac{1}{2}(\eta_{\max} - \eta_{\min})(1 + \cos(\pi t / T))$.
  • Warmup + cosine: start small, ramp up linearly over the first steps, then follow cosine decay — common in transformer training.
  • One-cycle: rise from a low rate to a high peak over the first part of training, then anneal to well below the start; often allows fast training.
  • ReduceLROnPlateau: cut the rate when validation loss stops improving.

Gradient clipping

If the gradient norm exceeds a threshold, rescale it to that norm: $\nabla \leftarrow \text{max\_norm} \cdot \nabla / \lVert\nabla\rVert$. This prevents a single huge gradient from wrecking the weights, and is standard for RNNs and transformers (Module 5), where gradients can explode.

Early stopping

Monitor validation loss each epoch. If it has not improved for $P$ consecutive epochs (patience), stop training and restore the best weights. Prevents overfitting without manual epoch tuning.

Hidden Layers as Automated Feature Engineering

🟣 Advanced — the deep insight

Hidden layer activations are learned representations of the input. The first hidden layer might learn simple features (edges in images, word associations in text). Deeper layers compose these into complex features (shapes, phrases). The output layer performs supervised prediction on these learned features. This is representation learning: the network simultaneously discovers features (in the hidden layers) and uses them for prediction (in the output layer), and the same supervised loss, through backpropagation, shapes both — the hidden features are whatever helps reduce that loss. The hidden node values are embeddings — exactly like the matrix factorisation embeddings in 4.7, but non-linear.

Worked Example: HDB Price Prediction from Scratch

Goal

Build a 3-layer neural network from scratch with NumPy on the course's HDB resale dataset (mlfp01/hdb_resale.parquet, about 50,000 transactions from 2015–2024), compare it honestly with a linear model, and export it with Kailash's OnnxBridge. The Lesson 4.8 slides train a one-hidden-layer version on two features; this is the fuller version. Exercise 8 then applies the training toolkit — activations, initialisation, optimisers, schedules, dropout and batch normalisation — in PyTorch.

Step 1.

Clean the data, build features, and split before standardising.

import numpy as np
import polars as pl
from shared import MLFPDataLoader

hdb = MLFPDataLoader().load("mlfp01", "hdb_resale.parquet")
clean = (
    hdb.filter(pl.col("resale_price").is_between(100_000, 2_000_000))   # drop impossible prices
    .with_columns(
        # some storey ranges were typed with the letter O instead of zero ("O4 TO 06")
        storey_mid=pl.col("storey_range").str.replace_all("O", "0")
        .str.extract(r"^(\d+)", 1).cast(pl.Float64) + 1,
        sale_year=pl.col("month").str.slice(0, 4).cast(pl.Float64),
    )
    .with_columns(flat_age=pl.col("sale_year") - pl.col("lease_commence_date"))
)
NUMERIC = ["floor_area_sqm", "storey_mid", "flat_age", "sale_year"]
town_onehot = clean.select("town").to_dummies()                  # towns -> indicator columns
X = np.hstack([clean.select(NUMERIC).to_numpy(), town_onehot.to_numpy()]).astype(np.float64)
y = clean["resale_price"].to_numpy().astype(np.float64).reshape(-1, 1) / 1e5   # S$100k units

rng = np.random.default_rng(42)
perm = rng.permutation(len(X))
X, y = X[perm], y[perm]
n_train = int(0.8 * len(X))

# Standardise with TRAINING statistics only (no test-set leakage)
X_mean, X_std = X[:n_train].mean(axis=0), X[:n_train].std(axis=0)
y_mean, y_std = y[:n_train].mean(), y[:n_train].std()
X_norm, y_norm = (X - X_mean) / X_std, (y - y_mean) / y_std
X_train, X_test = X_norm[:n_train], X_norm[n_train:]
y_train, y_test = y_norm[:n_train], y_norm[n_train:]
n_in = X_train.shape[1]
print(f"{hdb.height:,} rows -> {clean.height:,} clean; {n_in} inputs")

# Linear baseline first: always fit the simplest reasonable model
A_train = np.c_[X_train, np.ones(n_train)]
w_lin, *_ = np.linalg.lstsq(A_train, y_train, rcond=None)
pred_lin = np.c_[X_test, np.ones(len(X_test))] @ w_lin
r2_lin = 1 - np.mean((y_test - pred_lin) ** 2) / np.var(y_test)
print(f"Linear regression: test R^2 = {r2_lin:.3f}")

Removing prices below S$100,000 or above S$2,000,000 drops about 0.5% of rows that cannot be real HDB resale prices (one is S$10); storey becomes the midpoint of its range after repairing letter-O typos. The linear model is already strong — test $R^2 = 0.860$ — so any network has to beat that to be worth its complexity.

Step 2.

Forward pass, backpropagation and mini-batch gradient descent, by hand.

# Architecture n_in -> 64 -> 32 -> 1, Kaiming (He) initialisation for ReLU
W1 = rng.standard_normal((n_in, 64)) * np.sqrt(2.0 / n_in); b1 = np.zeros((1, 64))
W2 = rng.standard_normal((64, 32)) * np.sqrt(2.0 / 64);   b2 = np.zeros((1, 32))
W3 = rng.standard_normal((32, 1)) * np.sqrt(2.0 / 32);    b3 = np.zeros((1, 1))

def relu(z):
    return np.maximum(0, z)

def relu_grad(z):
    return (z > 0).astype(float)

def predict(X):
    return relu(relu(X @ W1 + b1) @ W2 + b2) @ W3 + b3

lr, batch_size, epochs = 0.01, 64, 30
for epoch in range(epochs):
    perm = rng.permutation(n_train)
    X_shuffled, y_shuffled = X_train[perm], y_train[perm]
    epoch_loss = 0.0
    for start in range(0, n_train, batch_size):
        X_batch = X_shuffled[start:start + batch_size]
        y_batch = y_shuffled[start:start + batch_size]
        m = len(X_batch)

        # Forward pass
        z1 = X_batch @ W1 + b1;  a1 = relu(z1)
        z2 = a1 @ W2 + b2;       a2 = relu(z2)
        y_hat = a2 @ W3 + b3                     # linear output for regression
        epoch_loss += np.mean((y_batch - y_hat) ** 2) * m

        # Backward pass: the chain rule, layer by layer
        dz3 = -2 * (y_batch - y_hat) / m         # dL/dy_hat for MSE
        dW3 = a2.T @ dz3;  db3 = dz3.sum(axis=0, keepdims=True)
        dz2 = (dz3 @ W3.T) * relu_grad(z2)
        dW2 = a1.T @ dz2;  db2 = dz2.sum(axis=0, keepdims=True)
        dz1 = (dz2 @ W2.T) * relu_grad(z1)
        dW1 = X_batch.T @ dz1;  db1 = dz1.sum(axis=0, keepdims=True)

        # Gradient-descent update
        W3 -= lr * dW3; b3 -= lr * db3
        W2 -= lr * dW2; b2 -= lr * db2
        W1 -= lr * dW1; b1 -= lr * db1

    if epoch % 5 == 0 or epoch == epochs - 1:
        test_loss = np.mean((y_test - predict(X_test)) ** 2)
        print(f"Epoch {epoch:>2}: train_loss={epoch_loss / n_train:.4f}, test_loss={test_loss:.4f}")

r2_nn = 1 - np.mean((y_test - predict(X_test)) ** 2) / np.var(y_test)
print(f"Network R^2 = {r2_nn:.3f}   vs linear R^2 = {r2_lin:.3f}")

Every line of the backward pass is one application of the chain rule: dz3 is $\partial\mathcal{L}/\partial\hat{y}$ for the mean squared error, each step back multiplies by a weight matrix transposed and gates by the ReLU derivative. Training and test loss fall in the first epochs and level off together — no overfitting, because 40,000 rows is a lot of data for about 4,200 weights. After 30 epochs the network reaches test $R^2 = 0.860$: exactly where the linear model is. That non-result is the honest lesson. On tabular data whose main driver is close to linear — price grows with floor area, shifted by town — a network has little to discover that a linear model with sensible features has not already captured (gradient-boosted trees are usually stronger than either). Networks earn their cost on images, sequences, text and graphs (Module 5), where hand-designing the features is the hard part. What this example shows is the machinery all of those architectures share.

Step 3.

Export with OnnxBridge and check the exported graph.

from pathlib import Path
import onnxruntime as ort
import torch
from torch import nn
from kailash_ml import OnnxBridge

# Copy the NumPy weights into an equivalent torch network (Linear stores W transposed)
model = nn.Sequential(nn.Linear(n_in, 64), nn.ReLU(), nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 1))
with torch.no_grad():
    for layer, W, b in [(model[0], W1, b1), (model[2], W2, b2), (model[4], W3, b3)]:
        layer.weight.copy_(torch.from_numpy(W.T).float())
        layer.bias.copy_(torch.from_numpy(b.ravel()).float())
model.eval()

bridge = OnnxBridge()
print("compatible:", bridge.check_compatibility(model, framework="torch").compatible)
export = bridge.export(model, framework="torch", output_path=Path("hdb_price_net.onnx"),
                       sample_input=torch.randn(1, n_in))   # traces the forward pass
print("exported:", export.success, export.onnx_status)

batch = X_test[:100].astype(np.float32)
session = ort.InferenceSession("hdb_price_net.onnx")
onnx_out = session.run(None, {session.get_inputs()[0].name: batch})[0]
print(f"max |ONNX - NumPy| = {np.abs(onnx_out - predict(X_test[:100])).max():.2e}")

OnnxBridge checks whether a model can be exported, exports it, and reports the outcome as a result object instead of raising. It exports PyTorch models (as here and in Exercise 8.5) as well as scikit-learn-style ones. The ONNX graph reproduces the NumPy network to within float32 rounding. OnnxBridge does not train or serve: training was your loop; serving is ONNX Runtime here or InferenceServer in Module 5. The deployed graph expects inputs standardised with the training statistics — ship X_mean, X_std, y_mean and y_std with it. The exporter may print warnings during torch export; they are harmless here.

Common Mistakes

  1. Zero-initialising all weights. Every neuron computes the same gradient — symmetry is never broken. Use He initialisation for ReLU layers.
  2. Forgetting to turn off dropout at inference. Predictions become noisy and non-deterministic. In PyTorch, call model.eval() before predicting (it also switches batch norm to its running statistics).
  3. Learning rate too high. Loss oscillates wildly or diverges. Start with $10^{-3}$ and use a schedule.
  4. No early stopping. The model overfits for 1000 epochs when it should have stopped at 200.
