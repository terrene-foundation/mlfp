Lesson 5.3 RNNs and Sequence Models

Convolutions handle grids; recurrent networks handle sequences. In this lesson you meet the vanilla RNN, then the Long Short-Term Memory (LSTM) cell (three gates plus a candidate), then the GRU. You will derive the six LSTM equations, see why the cell state is a "gradient highway", compare RNN, GRU and LSTM on a small synthetic price‑like series, then go deeper (stacked residual LSTMs, attention over features) and see the technical indicators traders feed such models. Exercise 3 applies the same models to real daily bars of the Straits Times Index.

Why Sequences Are Different

A sequence is an ordered list: words in a sentence, prices in a time series, trip points in a taxi route, heart rates in an ECG. Two properties distinguish sequence data from images:

  • Variable length. One sentence has 5 words, another has 50. A CNN with a fixed input size cannot handle this gracefully.
  • Temporal dependency. The meaning of a word depends on the words before it ("bank" near "river" vs "bank" near "deposit"). The price tomorrow depends on prices today and last week.

The idea of a recurrent network is to maintain a hidden state $h_t$ that summarises everything seen so far, and update it step by step as each new input arrives:

$$h_t \;=\; \phi(W_{xh} \, x_t + W_{hh} \, h_{t-1} + b_h)$$
$x_t$ — input at step $t$ $h_{t-1}$ — previous hidden state $\phi$ — non-linearity (tanh)

The same weight matrices $W_{xh}$ and $W_{hh}$ are reused at every time step — just like a conv filter reuses weights across positions. That weight sharing is what lets a recurrent network handle any length of sequence with a fixed number of parameters.

Vanishing and exploding gradients

The elegant picture has a cruel flaw. When you backpropagate through a long sequence, the gradient of the loss with respect to $h_1$ involves a product of $T$ Jacobians — one per time step. If each is smaller than 1, the product shrinks exponentially (vanishing gradient) and $h_1$ never gets updated. If each is larger than 1, it blows up (exploding gradient) and training NaNs out.

Vanilla RNNs are almost unusable on sequences longer than ~20 steps for this reason. The fix came in 1997 from Hochreiter and Schmidhuber: the LSTM cell.

The LSTM Cell

An LSTM adds a second state on top of the hidden state $h_t$: a cell state $C_t$. The cell state flows forward with only additive updates, protected by three gates that choose what to remember, what to add, and what to reveal. The additive path is a gradient highway — it does not get multiplied by a Jacobian at every step, so gradients do not vanish.

Three gates + candidate: the six equations

Let $[h_{t-1}, x_t]$ denote the concatenation of the previous hidden state and the current input. The LSTM update rule is:

$$\begin{aligned} f_t &= \sigma\!\bigl(W_f \, [h_{t-1}, x_t] + b_f\bigr) & \text{(forget gate)}\\[2pt] i_t &= \sigma\!\bigl(W_i \, [h_{t-1}, x_t] + b_i\bigr) & \text{(input gate)}\\[2pt] \tilde{C}_t &= \tanh\!\bigl(W_C \, [h_{t-1}, x_t] + b_C\bigr) & \text{(candidate cell)}\\[2pt] C_t &= f_t \odot C_{t-1} + i_t \odot \tilde{C}_t & \text{(cell update)}\\[2pt] o_t &= \sigma\!\bigl(W_o \, [h_{t-1}, x_t] + b_o\bigr) & \text{(output gate)}\\[2pt] h_t &= o_t \odot \tanh(C_t) & \text{(hidden state)} \end{aligned}$$

Read row by row:

  • Forget gate $f_t$. A sigmoid in $[0, 1]$ per cell dimension. Multiplies $C_{t-1}$ elementwise — zero means "forget this component", one means "keep it entirely".
  • Input gate $i_t$. Another sigmoid: how much of the new candidate to let into the cell state.
  • Candidate $\tilde{C}_t$. A tanh in $[-1, 1]$: the new content to potentially add.
  • Cell update. Combine: forget some of the past, accept some of the new. The update is additive — this is the gradient highway.
  • Output gate $o_t$. How much of the cell state to expose as the hidden state.
  • Hidden state $h_t$. Output-gated tanh of the cell state.
🔵 Theory — Why the cell state dodges vanishing gradients

In a vanilla RNN, $\partial h_t / \partial h_{t-1}$ is a product involving $W_{hh}$ and a tanh derivative. Repeated over $T$ steps it becomes a product of matrices with small singular values, which decays exponentially. In an LSTM, the cell-state update is $C_t = f_t \odot C_{t-1} + (\text{stuff})$. If the forget gate $f_t \approx 1$, then $\partial C_t / \partial C_{t-1} \approx I$ — essentially no decay. The gradient flows backward through the cell state nearly unchanged over hundreds of time steps.

The GRU

The GRU (Gated Recurrent Unit, 2014) simplifies the LSTM by merging the forget and input gates into a single update gate and dropping the separate cell state:

$$\begin{aligned} z_t &= \sigma(W_z \, [h_{t-1}, x_t]) & \text{(update gate)}\\ r_t &= \sigma(W_r \, [h_{t-1}, x_t]) & \text{(reset gate)}\\ \tilde{h}_t &= \tanh(W \, [r_t \odot h_{t-1}, x_t])\\ h_t &= (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t \end{aligned}$$

Fewer parameters, faster to train, usually competitive with LSTM. Rule of thumb: try a GRU first; if it underfits, upgrade to LSTM; if you need really long contexts (1000+ tokens), use a Transformer (Lesson 5.4).

Worked Example: RNN vs GRU vs LSTM on a synthetic series

📝 Goal

Predict the next value of a noisy two‑cycle synthetic series (generated below, so it runs in a few minutes on a laptop), and compare vanilla RNN, GRU and LSTM against the naive "next value = last value" forecast. Exercise 3 does the same comparison on real daily Straits Times Index bars (20 past days × Close, High, Low, Volume → the next 5 closes).

Step 1 — the (synthetic) series and a chronological split. 
import numpy as np
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import DataLoader, TensorDataset
from shared.kailash_helpers import get_device

torch.manual_seed(42)
rng = np.random.default_rng(42)
device = get_device()            # MPS / CUDA / CPU, picked automatically

def make_series(n=2000, seq_len=50):
    """SYNTHETIC series: a 25-step and an 8-step cycle plus Gaussian noise (std 0.1)."""
    t = np.arange(n + seq_len, dtype=np.float32)
    season = 0.5 * np.sin(2 * np.pi * t / 25) + 0.3 * np.sin(2 * np.pi * t / 8)
    noise = 0.1 * rng.standard_normal(len(t)).astype(np.float32)
    series = season + noise
    X = np.stack([series[i:i + seq_len] for i in range(n)])   # (n, L)
    y = series[seq_len:seq_len + n]                           # (n,)  next value
    return X[..., None], y                                    # (n, L, 1)

X_np, y_np = make_series()
X = torch.from_numpy(X_np).to(device)
y = torch.from_numpy(y_np).to(device)
split = 1600                     # first 1,600 windows train, last 400 validate — never shuffle across time
train_loader = DataLoader(TensorDataset(X[:split], y[:split]), batch_size=64, shuffle=True)
X_val, y_val = X[split:], y[split:]

Splitting by time, not at random, is essential for sequences: neighbouring windows overlap by 49 of 50 values, so a random split would put near‑copies of every validation window in the training set. The noise has standard deviation 0.1, so no model can beat an MSE of about $0.1^2 = 0.01$ — the noise floor.

Step 2 — an LSTM regressor. 
class LSTMRegressor(nn.Module):
    def __init__(self, input_size=1, hidden_size=32, num_layers=2):
        super().__init__()
        self.lstm = nn.LSTM(input_size, hidden_size, num_layers,
                            batch_first=True, dropout=0.1)
        self.head = nn.Linear(hidden_size, 1)

    def forward(self, x):
        out, _ = self.lstm(x)               # out: (B, L, H)
        last = out[:, -1, :]                # final time step
        return self.head(last).squeeze(-1)  # (B,)

nn.LSTM implements all six equations above for you. batch_first=True makes the expected input shape $(B, L, F)$ instead of the older $(L, B, F)$ convention. We take the output at the last time step as our regression head input. (dropout=0.1 applies between the two stacked layers.)

Step 3 — train with gradient clipping, score on validation. 
def fit(model, epochs=30):
    model = model.to(device)
    opt = torch.optim.Adam(model.parameters(), lr=1e-3)
    for epoch in range(epochs):
        model.train()
        for xb, yb in train_loader:
            loss = F.mse_loss(model(xb), yb)
            opt.zero_grad()
            loss.backward()
            # ★ gradient clipping — essential for recurrent networks
            torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
            opt.step()
    model.eval()
    with torch.no_grad():
        return F.mse_loss(model(X_val), y_val).item()

The star line is clip_grad_norm_. It rescales the gradient vector so its L2 norm never exceeds 1.0. Without it, occasional exploding-gradient spikes ruin training for long sequences. For LSTMs and Transformers, clipping is standard practice — always on.

Step 4 — GRU and vanilla RNN, and the naive baseline. 
class GRURegressor(LSTMRegressor):
    def __init__(self, hidden_size=32, num_layers=2):
        super().__init__(hidden_size=hidden_size, num_layers=num_layers)
        self.lstm = nn.GRU(1, hidden_size, num_layers, batch_first=True, dropout=0.1)

class RNNRegressor(LSTMRegressor):
    def __init__(self, hidden_size=32, num_layers=2):
        super().__init__(hidden_size=hidden_size, num_layers=num_layers)
        self.lstm = nn.RNN(1, hidden_size, num_layers, batch_first=True, dropout=0.1)

naive = F.mse_loss(X_val[:, -1, 0], y_val).item()     # "next = last"
print(f"naive: {naive:.4f}")
for name, cls in [("RNN", RNNRegressor), ("GRU", GRURegressor), ("LSTM", LSTMRegressor)]:
    torch.manual_seed(0)
    print(f"{name}: val MSE {fit(cls()):.4f}")

Same head; only the recurrent core is swapped (forward discards the returned state, which is a tuple for the LSTM and a tensor for the others). On our runs the naive forecast scored 0.055 and all three recurrent models reached 0.011–0.012 (the LSTM figure is from CPU — see the device note), essentially the 0.01 noise floor. The vanilla RNN did not struggle here — and that is a lesson in itself: the longest cycle is 25 steps and the last few values already pin down the phase, so nothing has to be remembered for long. The gates earn their keep when the target depends on inputs far back in the window; Exercise B below builds such a task.

⚠ Device note (observed with torch 2.12 on Apple MPS)

On an Apple‑silicon MPS device, this two‑layer nn.LSTM with dropout=0.1 reached only 0.15 validation MSE after 30 epochs (0.087 after 60) — worse than the naive forecast — while the identical code on CPU reached 0.011, and on MPS with dropout=0.0 it reached 0.012. The GRU and RNN were unaffected. If your LSTM lags the GRU by an order of magnitude on MPS, set the inter‑layer dropout to 0 or run on CPU. Exercise 3's LSTMs are single‑layer without dropout.

Step 5 — temporal attention (optional).

Instead of taking the last time step, compute a weighted sum of all time steps where the weights are learned: 

class AttentionLSTM(nn.Module):
    def __init__(self, input_size=1, hidden_size=32):
        super().__init__()
        self.lstm = nn.LSTM(input_size, hidden_size, batch_first=True)
        self.attn = nn.Linear(hidden_size, 1)
        self.head = nn.Linear(hidden_size, 1)

    def forward(self, x):
        out, _ = self.lstm(x)                            # (B, L, H)
        scores = self.attn(out).squeeze(-1)              # (B, L)
        weights = F.softmax(scores, dim=-1).unsqueeze(-1)
        context = (weights * out).sum(dim=1)             # (B, H)
        return self.head(context).squeeze(-1)

This is a foreshadowing of Lesson 5.4 — the idea that "attend to a weighted combination of all time steps" is exactly what the Transformer generalises and takes to its logical conclusion.

Going Deeper: Stacked LSTMs and Spatial Attention

Two upgrades take a recurrent model beyond a single layer reading a single signal. Both reappear, unchanged, as ingredients of the Transformer block in Lesson 5.4.

Multi‑layer LSTMs with residual connections

nn.LSTM(num_layers=2) already stacks LSTMs: layer 2 reads the hidden states of layer 1, so lower layers can pick up short‑range patterns and upper layers longer‑range ones. Beyond two or three layers, plain stacks train badly for the same optimisation reason plain CNNs did in Lesson 5.2. The fix is the same as ResNet's: add each layer's output to its input, then normalise. 

import torch
import torch.nn as nn

class ResidualLSTM(nn.Module):
    """A stack of LSTMs; each layer adds its output to its input, then LayerNorm."""
    def __init__(self, d, n_layers=3):
        super().__init__()
        self.lstms = nn.ModuleList(nn.LSTM(d, d, batch_first=True) for _ in range(n_layers))
        self.norms = nn.ModuleList(nn.LayerNorm(d) for _ in range(n_layers))

    def forward(self, x):                      # (B, T, d)
        for lstm, norm in zip(self.lstms, self.norms):
            out, _ = lstm(x)
            x = norm(x + out)                  # residual + norm
        return x

proj = nn.Linear(4, 32)                        # 4 raw features -> width 32
x = torch.randn(8, 20, 4)                      # 8 windows x 20 days x 4 features
h = ResidualLSTM(32)(proj(x))
print(h.shape)                                 # torch.Size([8, 20, 32])

The residual needs input and output widths to match, which is why the raw features are first projected to width 32 — the same role as the 1×1 shortcut convolution in a ResNet.

Spatial (feature) attention

The temporal attention in Step 5 asks which time steps matter. Spatial attention asks which input features relate to each other — for a stock window, does the day's high‑low range carry information about volume? Treat each feature's 20‑day history as one token and let multi‑head attention learn feature‑to‑feature weights: 

class FeatureAttention(nn.Module):
    """Spatial attention: each of the F features is a token; heads relate features."""
    def __init__(self, T, d=32, heads=4):
        super().__init__()
        self.embed = nn.Linear(T, d)           # embed each feature's T-step history
        self.mha = nn.MultiheadAttention(d, num_heads=heads, batch_first=True)

    def forward(self, x):                      # x: (B, T, F)
        tokens = self.embed(x.transpose(1, 2)) # (B, F, d)
        z, w = self.mha(tokens, tokens, tokens)  # w: (B, F, F), averaged over heads
        return z, w

z, w = FeatureAttention(T=20)(x)
print(z.shape, w.shape)                        # torch.Size([8, 4, 32]) torch.Size([8, 4, 4])
print(w[0].sum(dim=-1))                        # every row sums to 1

The $(F, F)$ weight matrix is directly interpretable: row $i$ says how much feature $i$ draws on each other feature. Each of the four heads can learn a different relationship; nn.MultiheadAttention averages the heads' weights by default. Lesson 5.4 derives multi‑head attention properly. In practice the feature summaries $z$ are concatenated with, or fed into, the temporal model.

🎯 Drill — what does depth cost?

Count the parameters of ResidualLSTM(32, n_layers=3) and of a plain nn.LSTM(32, 32, num_layers=3). How many extra parameters do the residual connections add?

Solution 
n_res = sum(p.numel() for p in ResidualLSTM(32, n_layers=3).parameters())
n_plain = sum(p.numel() for p in nn.LSTM(32, 32, num_layers=3).parameters())
print(n_plain, n_res, n_res - n_plain)        # 25344 25536 192

Each LSTM layer has $4\,(d\cdot d + d\cdot d + 2d) = 8{,}448$ parameters for $d = 32$ (four blocks of input weights, recurrent weights and two bias vectors), so three layers have 25,344. The residual additions are free; the only extra parameters are the three LayerNorms' scale and shift, $3 \times 2 \times 32 = 192$. Depth with residuals costs almost nothing in parameters — its cost is compute and sequential latency.

Technical Indicators as Sequence Features

Exercise 3 feeds the model four raw daily features of the Straits Times Index (Close, High, Low, Volume), z‑scored on the training period. Price forecasters often add technical indicators — hand‑crafted summaries of recent price action. They are a natural extension to the exercise (not part of its feature set). Three classics:

  • RSI (14) — relative strength index: $100 - 100/(1 + \text{avg gain}/\text{avg loss})$ over 14 days. Near 70+ is conventionally "overbought", near 30− "oversold".
  • MACD — the 12‑day minus the 26‑day exponential moving average of the close: positive when short‑term momentum is above the longer trend.
  • Bollinger position — where the close sits inside the band of 20‑day mean ± 2 standard deviations (−1 = lower band, +1 = upper band).
import polars as pl

sti = pl.read_parquet("data/mlfp05/stocks/STI.parquet").sort("Date")   # Exercise 3's cached STI bars

delta = pl.col("Close").diff()
gain = delta.clip(lower_bound=0).rolling_mean(14)
loss = (-delta).clip(lower_bound=0).rolling_mean(14)
ema12 = pl.col("Close").ewm_mean(span=12, adjust=False)
ema26 = pl.col("Close").ewm_mean(span=26, adjust=False)
mid = pl.col("Close").rolling_mean(20)
sd = pl.col("Close").rolling_std(20)

feats = sti.with_columns(
    rsi_14=100 - 100 / (1 + gain / loss),
    macd=ema12 - ema26,
    bb_pos=(pl.col("Close") - mid) / (2 * sd),
).drop_nulls()
print(feats.height)                                    # 3729 (of 3748 days)
print(feats.select("Date", "Close", "rsi_14", "macd", "bb_pos").tail(1))

On the cached data (2010–2024, 3,748 trading days) the first 19 rows are lost to the 20‑day warm‑up, leaving 3,729. On the last day, 30 December 2024, the STI closed at 3,795.7 with RSI ≈ 50.2, MACD ≈ +13.2 and Bollinger position ≈ +0.19 — neutral momentum, slightly above its 20‑day mean. (This RSI uses simple 14‑day means; Wilder's original uses exponential smoothing, so charting packages may differ slightly.)

⚠ Indicators are not free skill

Every indicator is a deterministic function of past prices the model already sees, so it adds no new information — only a convenient summary. Compute indicators on the full series before windowing (they look only backwards, so this leaks nothing), but fit the z‑score on the training period only. And daily index prices are close to a random walk: always compare against "tomorrow = today" before claiming an indicator helps.

🟣 Advanced — Teacher forcing vs free-running

When training a sequence-to-sequence model, you can either feed the ground-truth previous token as input (teacher forcing) or feed the model's own previous prediction (free-running). Teacher forcing is faster to train but creates exposure bias: at inference time the model has to condition on its own outputs, which it never saw during training. Scheduled sampling mixes the two to mitigate this. Transformers largely sidestep the issue with parallel attention training.

Common Mistakes

⚠ Mistake 1: Forgetting gradient clipping

RNNs without gradient clipping explode on ~1% of batches and NaN your loss. Always add torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0) between loss.backward() and opt.step().

⚠ Mistake 2: Wrong batch_first convention

PyTorch's recurrent layers default to (seq_len, batch, features) shape. Modern practice is batch_first=True which gives (batch, seq_len, features). Mix them up and every dimension is off by one axis — the bug is silent because shapes still "work", they just mean different things.

⚠ Mistake 3: Using LSTM state across unrelated sequences

By default nn.LSTM initialises the hidden state to zeros at the start of each forward pass — correct. If you manually pass the previous batch's final state as the next batch's initial state (across unrelated sequences), you contaminate each sequence with another's hidden memory. Only do stateful RNN training deliberately, for a single long stream cut into chunks.

⚠ Mistake 4: Sequence length too long for available memory

Backprop-through-time stores activations for every step. A seq_len of 1000 with a hidden size of 512 and batch 32 can eat many GBs. Truncated BPTT — call h = h.detach() on the carried hidden state every $k$ steps, so gradients flow back at most $k$ steps — is the fix when memory bites.
