Speaker Notes — Lesson 3.8 Production Pipeline

Total time: ~60 minutes  ·  11 slides  ·  ~5 min per slide average

The M3 capstone: from training to monitored production. The centre of gravity is the architecture diagram on slide 2 — everything else is a component of it. The operational facts students must leave with: DataFlow needs an absolute SQLite path, DriftMonitor needs its own database file, the alert line is PSI > 0.2 or KS p < 0.001 (Bonferroni-tightened for 33 features), and rollback is promote_model re-walking archived → staging → production.

Slide 1~1 minTitle

Production Pipeline

Open: "3.7 versioned the model. Today it goes to work — serving predictions, persisting everything, monitored for drift, with uncertainty attached and a rollback plan. Capstone: from training to monitored production."

→ "The whole system on one slide."
Slide 2~6 minArchitecture

What production means

Walk the diagram in zones. Left — the training pipeline: Train (XGBoost/LightGBM, CV + early stopping) and Calibrate (Platt or isotonic, plus conformal). Centre — the ModelRegistry holding v1 (archived), v2 (staging), v3 (production); the artifact flows in from training, promotion flows out. Right — Inference: POST /predict returning a probability and a prediction set — that's conformal, coming later.

Below inference, the DriftMonitor watches every batch: PSI per feature, KS test, check_drift() per batch. Follow the dashed blue feedback loop all the way left: "Alert at PSI > 0.2 or KS p < 0.001 → retrain. The system is a loop, not a line."

Then the foundation: "Everything persists through DataFlow — training data and features, model artifacts and signatures, predictions and drift history. And the Model Card rides along: metrics, fairness, limits. If it isn't persisted, it didn't happen."

→ "Component one: the persistence layer."
Slide 3~5 minDataFlow

DataFlow: zero-config persistence

Walk the code, starting with the comment that saves an hour of debugging: "DataFlow needs an absolute sqlite path — a relative URL gets mangled into a path at the filesystem root and fails with 'unable to open database file'. The Path(...).resolve() in the f-string is not decorative."

Then the model: decorate a plain class with @db.model, initialize(), and CRUD is free — express.create writes a prediction row with customer, probability, and model version. "Define a model, get CRUD for free. No SQL."

→ "The rest of the CRUD."
Slide 4~4 minDataFlow ops

DataFlow operations

Walk the three operations. Read — express.list with a filter for high-risk predictions. Update — by primary key. Delete — same shape. "Same API for training frames, predictions, drift reports — one persistence pattern for the whole system."

Read the green box: "express is the simple API. Each @db.model also generates CRUD workflow nodes for WorkflowBuilder — the persistence layer plugs straight into 3.7's DAGs with no hand-written SQL."

→ "Component two: drift. PSI first."
Slide 5~4 minPSI

DriftMonitor: PSI

Walk the formula: bin the reference distribution, then sum $(p_i - q_i)\ln(p_i/q_i)$ over the bins — reference $p$, current $q$. "It's a symmetric-ish divergence between the two histograms: zero when identical, growing as they separate."

Walk the action table: below 0.1, no shift — continue. 0.1 to 0.25, moderate — investigate. Above 0.25, significant — retrain. "Print this table and tape it to the monitoring dashboard. The number without the action is trivia; the action is the system."

→ "The second test."
Slide 6~3 minKS test

DriftMonitor: KS test

Walk the figure: reference and current distributions, and the amber gap at the point of maximum separation — the KS statistic. "PSI bins the distributions and compares; KS compares their cumulative curves directly and comes with a p-value. Two lenses on the same question: has the data moved?"

→ "Wire it up."
Slide 7~5 minDriftMonitor code

DriftMonitor code

Walk the code, comment first: "DriftMonitor needs its own SQLite file — sharing the registry's database fails with a missing-column error. One store per concern."

Then the thresholds: psi_threshold=0.2 — inside the 'investigate' band from the table — and ks_threshold=0.001. "Why 0.001 and not 0.05? Bonferroni from 2.3: we're testing 33 features at once, so the per-feature alpha is tightened to keep the family-wise false-alarm rate sane."

Then the flow: set_reference_data once with the training frame, check_drift per batch, iterate the flagged features. "Reference is the training distribution — the thing the model was promised the world would look like."

→ "Component three: honest uncertainty."
Slide 8~5 minConformal

Conformal prediction

Walk the code — split conformal for a classifier. On the calibration rows, compute the nonconformity score: one minus the probability of the true class. Take the $\lceil(n+1)(1-\alpha)\rceil/n$ quantile as $\hat{q}$. A new prediction then includes every class whose score fits under $\hat{q}$ — when both classes qualify, the set is {repay, default} and the case routes to a human.

Read the blue box carefully — two conditions and one caveat: "No model assumptions, but calibration and new data must be exchangeable — drift breaks the guarantee, which is exactly why the drift monitor exists. And coverage ≥ 1 − α is marginal: 90% over applicants on average, not guaranteed inside each sub-group. 3.6's fairness lens applies here too."

→ "Component four: the document."
Slide 9~5 minModel Card

Model Card template

Walk the table. Model details: name, version, type, date. Intended use: primary case and out-of-scope. Training data: source, size, date range. Evaluation: AUC, AP, Brier, conformal coverage — and the decision threshold, 0.130, documented as $c_{FP}/(c_{FP} + c_{FN})$ so nobody 'corrects' it back to 0.5. Fairness: DI and TPR/FPR per group — measured, not asserted, from 3.6's audit. Limitations: known failure modes. Monitoring: drift thresholds and retrain triggers.

Read the footer: "Exercises 8.4–8.5: rollback is promote_model re-walking archived → staging → production — there is no magic revert button, only the lifecycle run in reverse. And production readiness is 11 gates computed from evidence plus a human sign-off — the same lesson as 3.6's age-band fail: automation surfaces, humans decide."

→ "Three mistakes."
Slide 10~3 minMistakes

Three mistakes to avoid

Walk the three red boxes. One: no drift monitoring — silent degradation is the number-one production ML failure; the model doesn't crash, it just gets politely worse. Two: PSI on unused features — monitor the features the model actually consumes; alarm fatigue from irrelevant features buries the real drift. Three: point predictions without uncertainty — conformal adds calibrated prediction sets almost for free.

→ "Close out the module."
