Speaker Notes — Lesson 6.4 RAG Systems

Total time: ~90 minutes  ·  11 slides  ·  ~8 min per slide average

Grounding instead of rewiring. The lesson's frame: fine-tune for skills and style, RAG for facts and freshness. The pipeline is built by hand — chunk, embed, retrieve, answer with a grounding instruction — and evaluated honestly: RAGAS with a local LLM judge whose parse failures must raise, never default to a score. Retrieval is where the quality lives: hybrid (BM25 + dense, RRF-fused) is the production pattern.

Slide 1~2 minTitle

RAG Systems

Open with the outcome: "Build, evaluate, and improve a production RAG pipeline. 6.2 and 6.3 changed the model's weights; today we don't touch them — we change what the model can see."

→ "Why not just fine-tune the facts in?"
Slide 2~8 minWhy RAG

Why RAG beats fine-tuning for knowledge

Walk the three arguments. Freshness: re-index daily (trivial) vs retrain daily (absurd). Attribution: RAG cites source chunks; fine-tuning blurs facts into weights — "when the answer is wrong, RAG shows you the chunk that misled; a fine-tune shows you nothing." Cost: indexing is one embedding pass per chunk; fine-tuning on the same corpus means GPU runs — repeated every time the facts change.

Read the green box — it's the division of labour for the whole module: "Fine-tune for skills and style. RAG for facts and freshness."

→ "The pipeline."
Slide 3~8 minPipeline

The RAG pipeline — two paths meet at the vector store

Walk the figure: the offline path — documents, chunking, embed, into the vector store; and the online path — question, embed, retrieve top-k, augment the prompt with context, answer. "Two paths, one meeting point: the vector store. The offline path runs once per corpus change; the online path runs per question."

→ "Chunking — the quiet quality lever."
Slide 4~7 minChunking

Chunking strategies

Walk the table. Fixed size: split every N tokens — the simple, fast baseline. Sentence: split on sentence boundaries — preserves meaning. Paragraph: split on blank lines — for documents with clear structure. Semantic: embed, cluster, split at topic shifts — best quality, slower.

Read the closing line: "Always overlap chunks 10–20% — a key passage sliced at a boundary is lost to both neighbours. And size matters: 200–500 tokens. Chunks too large and the LLM gets distracted by irrelevant context."

→ "Retrieval — where quality lives."
Slide 5~9 minRetrieval

Three retrieval approaches

Walk the table. Sparse: BM25 — 4.6's formula, exact keyword match. Dense: sentence embeddings + cosine — semantic similarity, catches paraphrase. Hybrid: reciprocal rank fusion, $\sum_r 1/(k + \text{rank}_r)$ with $k = 60$ — best of both.

Read the blue box: "Hybrid retrieval plus a re-ranking pass is the common production pattern. RRF fuses ranks, so BM25 and cosine scores never need a common scale. Exercise 4 scores them all with hit@k against each question's source document — on the 8,219-chunk corpus, BM25 alone lands hit@1 ≈ 0.92 and hit@5 ≈ 0.97 on the generated questions — honest caveat: the questions are generated from the corpus, so say so when you quote the numbers."

→ "Evaluate the whole pipeline: RAGAS."
Slide 6~8 minRAGAS

RAGAS evaluation

Walk the four metrics, two per side of the pipeline. Generation side: faithfulness — is the answer grounded in the retrieved context? answer relevance — does it address the question? Retrieval side: context relevance — are the retrieved chunks relevant? context recall — did we retrieve all the relevant chunks?

Read the footer: "Exercise 4.5 computes these with the local LLM as the judge — so judge parse failures must raise, never default to a score. A metric that silently defaults when the judge hiccups is 3.5's fake metric in a new outfit."

→ "A clever retrieval trick: HyDE."
Slide 7~7 minHyDE

HyDE — Hypothetical Document Embeddings

Walk the figure: the question goes to the LLM first — "write a hypothetical answer" — that hypothetical gets embedded, and the embedding drives retrieval. "Questions and documents live in different styles: a question is short and interrogative; an answer-shaped embedding retrieves documents that look like answers, not just keyword matches."

→ "The full pipeline in code."
Slide 8~9 minRAG code

RAG code

Walk the code. load_rag_corpus() gives section, text, question, answer. The embedder comes from make_embedder() — the model is OLLAMA_EMBED_MODEL from the environment, 768-dim. Embed all chunks once, embed the query, cosine-similarity, argsort the top 5.

Then the prompt — read the instruction as the grounding contract: "'Answer using ONLY the context. If it is not there, say so.' That sentence is what makes it RAG instead of confabulation with extra steps." The answer comes from run_delegate_text(make_delegate(), prompt) — the delegate's model comes from OLLAMA_CHAT_MODEL, never a hardcoded model= argument.

→ "Production patterns."
Slide 9~8 minAdvanced patterns

Advanced RAG patterns

Walk the three. Metadata filtering: store source, date, and section with each chunk; filter before similarity search — "only notices issued after 2024"; the cheapest precision win. Multi-hop retrieval: retrieve, let the LLM name the missing fact, retrieve again — for answers spanning two documents. Document summarisation: index a summary per document alongside its chunks; route broad questions to summaries, narrow ones to chunks.

Read the Singapore note and the teal box: "Typical local use: question answering over public regulatory texts — MAS notices, PDPA guidance — swap them in for the Exercise 4 corpus. And Kaizen ships ready-made RAGResearchAgent and MemoryAgent in kaizen_agents.agents — the packaged alternative; Exercise 4 builds the pipeline by hand so every stage is visible."

→ "Common mistakes."
Slide 10~5 minMistakes

Common mistakes

Walk the four. One: chunks too large — the LLM gets distracted by irrelevant context; 200–500 tokens. Two: no overlap — key passages split at boundaries. Three: dense-only retrieval — misses exact keyword matches; use hybrid. Four: no RAGAS evaluation — "'it looks right' is not a metric."

→ "Recap and bridge."
Slide 11~3 minRecap

What you can now do

Walk the checklist: build a complete RAG pipeline, compare BM25 / dense / hybrid retrieval, evaluate with RAGAS, and apply HyDE. Tease 6.5: "The LLM starts acting in the world — AI Agents: ReAct, tool use, and function calling."
