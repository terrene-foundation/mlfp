Speaker Notes — Lesson 5.6 Graph Neural Networks

Total time: ~75 minutes  ·  12 slides  ·  ~6 min per slide average

Connected data. The unifying idea is message passing — each node updates by aggregating its neighbours' features — and the three architectures are just three answers to "how should neighbours be weighted?": GCN's fixed normalisation, GraphSAGE's fixed aggregation with sampling, GAT's learned per-pair attention. The evaluation discipline mirrors the rest of M5: node classification on Cora with epoch selection on validation, and link prediction scored on held-out edges.

Slide 1~1 minTitle

Graph Neural Networks

Open with the outcome: "Build GCN, GraphSAGE, and GAT node classifiers on Cora, and know the graph-classification recipe. Every architecture so far ate grids, sequences, or vectors. Today: relationships."

→ "Why graphs."
Slide 2~5 minWhy graphs

Why graphs?

Walk the examples: social networks, molecular structures, supply chains, the MRT map. "Relationships between entities carry information that tables lose. A table has rows; a graph has nodes and edges — and features can live on both."

Read the green box: "If your data has explicit relationships between entities, a graph captures structure that a table cannot. Flattening it away is 5.2's 'flatten the image' mistake in a new form."

→ "The one idea: message passing."
Slide 3~6 minMessage passing

Message passing

Walk the figure: a target node collects its neighbours' feature vectors, aggregates them, and updates its own representation. "Each node updates by aggregating neighbour features. One GNN layer = one round of message passing — so $k$ layers give every node a $k$-hop receptive field, the graph analogue of the CNN's growing receptive field."

"Everything today — GCN, GraphSAGE, GAT — is this one idea with different answers to 'how are the neighbour messages weighted?'"

→ "GCN's answer."
Slide 4~6 minGCN rule

GCN update rule

Walk the formula: $H^{(l+1)} = \sigma(\tilde{D}^{-1/2}\tilde{A} \tilde{D}^{-1/2} H^{(l)} W^{(l)})$. Unpack the three pieces. $\tilde{A} = A + I$ — add self-loops so a node hears its own features too. Symmetric normalisation — each message scales by $1/\sqrt{d_i d_j}$, so a high-degree hub's feature scale doesn't blow up. $W^{(l)}$ — one learnable matrix shared across all nodes.

"Fixed, degree-based weights — no learning in the aggregation, only in the shared $W$. That's GCN's answer to the weighting question."

→ "GraphSAGE's answer."
Slide 5~5 minGraphSAGE

GraphSAGE — inductive

Walk the three bullets. Sample a fixed-size neighbourhood instead of using all neighbours — scalable to hubs with thousands of edges. Aggregate with mean, LSTM, or max pooling. And the payoff: it generalises to unseen nodes.

Read the green box — it's the operational distinction: "GCN requires all nodes at training time. GraphSAGE can embed new nodes without retraining — essential for dynamic graphs, where tomorrow's graph has nodes that don't exist today."

→ "GAT's answer."
Slide 6~5 minGAT

GAT — attention on neighbours

Walk the formula: a learned scorer computes $e_{ij}$ for each neighbour pair from their concatenated transformed features, then a softmax over each node's neighbourhood turns scores into attention coefficients $\alpha_{ij}$. "Learns different weights per neighbour pair — and multi-head, the same trick as 5.4's Transformers."

Read the blue box — it's the lesson in one line: "GCN = fixed weights. GraphSAGE = fixed aggregation. GAT = learned per-pair weights. Increasing flexibility, increasing data appetite."

→ "Three task shapes."
Slide 7~5 minTask types

Three task types

Walk the table. Node classification: label each node — use the node embeddings directly, no pooling. Graph classification: label the entire graph — pool all nodes with global_mean_pool or global_max_pool. Link prediction: predict missing edges — dot-product the node pairs, and score on held-out edges.

Emphasise the evaluation hygiene in the third row: "Link prediction is scored on held-out edges — edges the model never saw in training. Score on training edges and you're measuring memorisation, not prediction."

→ "In code."
Slide 8~5 minGCN in PyG

GCN in PyG

Walk the code: two GCNConv layers with ReLU, then global_mean_pool(x, batch) pooling node embeddings into one vector per graph, and a linear head. "The edge_index is the graph — a list of who connects to whom. The batch vector tells the pooling which nodes belong to which graph. Two new tensors; everything else is the M4.8 toolkit."

"This is the graph-classification recipe. For node tasks — like Cora in the exercise — skip the pooling and put the head on the node embeddings directly, exactly as the task table said."

→ "See what was learned."
Slide 9~4 minEmbedding visual

Visualising node embeddings

Walk the schematic: clusters with clear separation and a few misplaced nodes between them. "Cora has 7 classes; the GNN has learned structure, but boundary nodes remain ambiguous — papers that genuinely sit between fields. Same honesty as 4.7's item embeddings: structure emerged from the graph alone, and the ambiguous points are the interesting ones."

→ "Common mistakes."
Slide 10~5 minMistakes

Common mistakes

Walk the four. One: ignoring graph structure — flattening to a table loses the edges, which is the entire point. Two: too many layers — over-smoothing: with enough rounds of message passing, every node's embedding converges to the same vector; 2–3 layers is typical. Three: wrong pooling — node tasks need no pooling; graph tasks need global pooling. Four: choosing the epoch by test accuracy — select on validation, report test once. M3.4's early-stopping discipline applies to GNNs unchanged.

→ "The architecture map, completed."
Slide 11~4 minSelection table

Architecture selection (consolidation)

Walk the completed table. Images: CNN / ViT (5.2). Sequences: RNN / Transformer (5.3, 5.4). Generation: VAE / GAN / Diffusion (5.1, 5.5). Graphs: GCN / GraphSAGE / GAT (today).

"Five lessons, one organising question: what is the structure of your data? The architecture is the answer to that question — not a fashion choice. Keep this table; M5's capstone assumes you can reach for it."
