Speaker Notes — Lesson 5.7 Transfer Learning

Total time: ~90 minutes  ·  11 slides  ·  ~8 min per slide average

The capstone of M5's architecture arc: stand on pre-trained models instead of training from scratch. The technical heart is the freeze → new head → gradual unfreeze strategy, plus zero-initialised adapters (≈1% of parameters — the same idea as M6's LoRA). The operational payload is the export → register → serve pipeline: OnnxBridge with a 2-row trace, then InferenceServer from the registry. Note the serving API is minimal by design — plain mapping in, plain mapping out.

Slide 1~2 minTitle

Transfer Learning

Open with the outcome: "Fine-tune, export, and serve CV and NLP models. Everything so far trained from scratch; today you learn why almost nobody in production does that."

→ "Why transfer."
Slide 2~7 minWhy transfer

Why transfer learning?

Walk the three bullets. Training from scratch: millions of images, weeks of compute — the entry fee for a competitive backbone. Transfer: start from pre-trained weights, fine-tune on your data — days become hours, and thousands of examples become hundreds.

Why it works: "Early layers learn universal features — edges and textures in vision, syntax in language. Those layers don't care whether the task is ImageNet or your three classes." Read the green box: "Most production DL does NOT train from scratch. Transfer is the norm."

→ "Which layers move, which stay."
Slide 3~7 minLayer spectrum

Lower layers transfer; higher layers specialize

Walk the figure: the layer-by-layer spectrum from generic to task-specific. "Lower layers are general — edges, corners, simple textures; they transfer almost for free. Higher layers are specialised — the 1,000-way ImageNet head is useless to your problem and gets replaced. The art is choosing where along the spectrum to cut."

→ "The strategy."
Slide 4~7 minStrategy

The strategy

Walk the strategy figure: freeze the backbone, train the new head, then unfreeze gradually at a low learning rate. "Freeze first — the pre-trained features are valuable and fragile. Train the head on top. Then, if you have the data, unfreeze the top layers gradually, at a learning rate 10–100× lower than from-scratch training. The sequence protects the inherited features while adapting them."

→ "In code, on ResNet."
Slide 5~8 minResNet fine-tuning

ResNet fine-tuning

Walk the code: load ResNet-18 with the default ImageNet weights; set requires_grad = False on every parameter — the backbone is frozen; replace model.fc with a fresh linear layer sized to your classes; and the optimiser receives model.fc.parameters() only.

"Read the optimiser line — it sees only the head's parameters. The frozen backbone is a fixed feature extractor; gradients would be wasted on it and would damage it. Three lines of surgery: freeze, replace, optimise the head."

→ "The middle path: adapters."
Slide 6~8 minAdapters

Adapters: train ~1% inside a frozen backbone

Walk the bottleneck formula: $x + W_{\text{up}}\, \text{ReLU}(W_{\text{down}}\, x)$, with $W_{\text{up}}$ zero-initialised. "At initialisation the adapter adds exactly zero — the block starts as the identity, so training begins from the exact ImageNet features and learns only the change it needs."

Walk the exercise numbers: "Exercise 5.7 file 04 inserts one adapter after ResNet-18's layer3 (256 channels) and layer4 (512 channels). Trainable: 99,200 adapter parameters plus the 5,130 in the head — about 104K of the ~11.3M total, ≈ 1%." Read the blue box: "Same idea as LoRA in Module 6 — a small trainable delta on a frozen model."

→ "The NLP twin: BERT."
Slide 7~8 minBERT fine-tuning

BERT fine-tuning

Walk the code: BertForSequenceClassification.from_pretrained( "bert-base-uncased", num_labels=4) — the pre-trained body with a fresh 4-way head for AG News topics. TrainingArguments: 2 epochs, lr 2e-5 — "note how small: fine-tuning rates are 10–100× below from-scratch" — and eval_strategy="epoch". "Heads-up on the keyword: current transformers uses eval_strategy; the old evaluation_strategy is removed."

"Same recipe as the ResNet: pre-trained body, new head, low LR. Exercise 5.4 file 04 writes the loop by hand so the Trainer's magic is visible."

→ "Ship it: export and serve."
Slide 8~9 minExport and serve

ONNX export + InferenceServer

Walk the three stages — this is Exercise 5.7 file 05 end to end. Stage 1: export behind the FlatImageAdapter with a 2-row traced sample input, and assert res.success — export failure returns, it doesn't raise. Stage 2: register_model in the registry, then attach_onnx_artifact to bind the .onnx file to that version. Stage 3: serve — InferenceServer.from_registry(..., runtime="onnx"), start, await server.predict({"records": ...}), stop.

Read the teal box: "Export → register → serve. predict returns a plain mapping — one logit row per image; there is no predict_batch, no warm_cache, no result object. The serving API is deliberately minimal: records in, predictions out."

→ "When does transfer even apply?"
Slide 9~6 minSelection guide

Architecture selection guide

Walk the table — note the transfer column as much as the architecture column. Images: CNN / ViT, always transfer from ImageNet. Text: Transformer, always transfer from BERT/GPT. Sequences: LSTM / Transformer, sometimes. Graphs: GNN, rarely — no large shared pre-trained corpus. Tabular: gradient boosting, never — pre-training doesn't transfer to tables; M3.4's boosters remain the answer there.

→ "Common mistakes."
Slide 10~5 minMistakes

Common mistakes

Walk the four. One: training all layers from the start — freeze first, unfreeze gradually; the inherited features are the asset. Two: LR too high — 10–100× lower than from-scratch; you're nudging, not rebuilding. Three: no augmentation — small datasets need flips, rotations, jitter. Four: no ONNX export — a notebook-only model is not deployed; export → register → serve is the definition of done here.

→ "Recap and bridge."
Slide 11~3 minRecap

What you can now do

Walk the checklist: fine-tune ResNet and BERT, add zero-initialised adapters to train ~1% of a frozen model, export with OnnxBridge, register and serve with InferenceServer, and select architecture + transfer strategy per data type. Tease 5.8: "Learning from interaction, not static data — Reinforcement Learning."

→ End of Lesson 5.7. Ten-minute break.
