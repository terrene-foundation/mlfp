Speaker Notes — Lesson 5.8 Reinforcement Learning

Total time: ~90 minutes  ·  11 slides  ·  ~8 min per slide average

The last lesson of M5, and deliberately pointed at M6: PPO today becomes RLHF tomorrow. The arc is the RL loop → Bellman equations → DQN (value-based) → PPO (policy-based) → production via km.rl_train → the RLHF bridge. One honest status to state plainly: the stable_baselines3 backend for km.rl_train is an optional extra not installed in the course environment — which is exactly why the exercises hand-write DQN and PPO. That's a feature for learning, not a limitation to apologise for.

Slide 1~2 minTitle

Reinforcement Learning

Open with the outcome: "Implement DQN and PPO, then connect PPO to RLHF for M6. Everything so far learned from static data. Today: learning from interaction."

→ "The loop."
Slide 2~8 minRL loop

The RL loop

Walk the loop: the agent observes a state, picks an action, the environment returns a reward and the next state. Repeat. "Supervised learning learns from a fixed dataset of correct answers. RL learns from consequences — the agent acts, observes, and adjusts. There is no answer key; there's a reward signal and a long horizon."

Read the green box: "All DL so far: static data. RL: learning from interaction. Agent acts, observes, learns."

→ "The math of consequences."
Slide 3~8 minBellman

Bellman equations

Walk both equations, naming them as the slide does. Top — the Bellman expectation equation: the value of a state under policy π is the expected immediate reward plus the discounted value of wherever you land. Bottom — the Bellman optimality equation: the optimal action-value takes the max over next actions — act greedily thereafter.

"γ is the discount factor — future rewards are worth less than present ones; γ near 1 is far-sighted, near 0 is greedy. Expectation describes a policy; optimality defines the best one. DQN approximates that optimal $Q^*$ with a neural network."

→ "DQN."
Slide 4~8 minDQN

DQN — Deep Q-Network

Walk the network: a plain MLP from state to one Q-value per action, and the TD loss in the comment — the squared gap between $r + \gamma \max_{a'} Q_{\text{target}}(s', a')$ and $Q(s, a)$.

Walk the three bullets. Experience replay: store transitions, sample randomly — breaks the correlation between consecutive experiences. Target network: a delayed copy of the Q-network computes the bootstrap target, so the goalposts don't move every step. And the boundary: discrete actions only — the max over actions must be enumerable.

→ "The policy-gradient answer: PPO."
Slide 5~8 minPPO

PPO — Proximal Policy Optimization

Walk the clipped objective: $r_t = \pi_\theta / \pi_{\theta_\text{old}}$ measures how much the policy changed; the loss takes the minimum of the unclipped and clipped advantage-weighted ratios. "The clip bounds each update relative to the old policy — no destructively large steps. PPO is conservatism engineered into the objective: improve, but stay proximal."

"And unlike DQN, it works for continuous and discrete actions — which is why it's the algorithm that shows up in the RLHF bridge at the end."

→ "The algorithm zoo, mapped to business."
Slide 6~7 minFive algorithms

Five algorithms, five applications

Walk the table. DQN — discrete — customer churn prevention. DDPG — continuous — manufacturing control. SAC — continuous — dynamic pricing. A2C — both — resource allocation. PPO — both — supply chain optimisation.

Read the footer: "Exercise 5.8 hand-writes DQN and PPO and trains them on discrete-action environments — CartPole-v1, inventory, ride-hailing pricing. DDPG, SAC, A2C, and continuous-action PPO run through km.rl_train, coming up."

→ "Your own environment."
Slide 7~8 minCustom environment

Custom Gymnasium environment

Walk the skeleton: action_space and observation_space declare the interface; step(action) applies the action, computes the reward — here, retained revenue minus action cost — and returns the 5-tuple: obs, reward, terminated, truncated, info. "Note the two ending flags: terminated means the episode genuinely ended (customer churned); truncated means we cut it off (time limit). They mean different things for bootstrapping — don't merge them."

"On this churn environment, the hand-written DQN (≈ 11.0 mean reward) edges out the best fixed policy (always-call ≈ 10.4) — a small but real margin over every heuristic you'll compute in the exercise."

→ "Production RL: km.rl_train."
Slide 8~7 minkm.rl_train

Kailash: km.rl_train for production RL

Walk the call: km.rl_train(ChurnEnv, algo="ppo", total_timesteps=100_000, hyperparameters={...}) — env factory or Gymnasium id, algorithm name (dqn, a2c, sac, ddpg, td3 as well), and it returns mean and std of reward.

Now the two honest API notes from the bullets. "Class form: kailash_ml.rl.RLTrainer with RLTrainingConfig — there is no top-level kailash_ml.RLTrainer; import it from kailash_ml.rl. And the backend: Stable-Baselines3 is an optional extra (kailash-ml[rl]) not installed in the course environment — which is exactly why the exercise hand-writes DQN and PPO. When you need production RL, install the extra and km.rl_train is the same call shape you see here."

→ "The bridge to M6."
Slide 9~7 minRLHF bridge

Bridge to M6: PPO → RLHF

Walk the figure: a reward model trained on human preference comparisons scores the LLM's outputs; PPO updates the LLM to maximise that reward; the action space is the next token — discrete, over the vocabulary.

Read the blue box carefully — it's the precision point that separates the informed from the confused: "Two separate mechanisms keep RLHF stable. PPO's clipping bounds each update versus $\pi_{\text{old}}$ — today's lesson. And a KL penalty to the reference (SFT) model keeps the LLM from drifting off-distribution chasing reward. Different leashes, different jobs. And DPO — coming in M6 — skips the reward model entirely."

→ "Common mistakes."
Slide 10~5 minMistakes

Common mistakes

Walk the three. One: complex reward shaping — start simple; every shaped term is a behaviour you're buying whether you meant to or not, and agents are master exploiters of misspecified rewards. Two: no advantage normalisation — PPO needs normalised advantages or the gradient scale whips around between batches. Three: tiny replay buffer — DQN needs diverse experience; a small buffer is recent-correlated experience in disguise, which is what replay exists to destroy.

→ "Recap — and the road to M6."
Slide 11~3 minRecap
