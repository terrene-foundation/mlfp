Lesson 3.6 Interpretability and Fairness

A model that scores 0.95 AUC means nothing if you cannot explain why it makes its predictions, and even less if it discriminates against protected groups. This lesson introduces SHAP (global and local explanations from Shapley values), LIME (model-agnostic local explanations), ALE (accumulated local effects that handle correlated features), and the fairness metrics every deployed model must report. We close with the impossibility theorem: when base rates differ between groups, demographic parity, equalised odds and calibration cannot hold together — not even two at a time, except for a useless or a perfect predictor.

SHAP: Shapley Additive Explanations

Shapley axioms

Shapley values come from cooperative game theory. A "game" has players (features) and a payoff (prediction). The Shapley value of feature $i$ is the average marginal contribution of $i$ across all possible coalitions of features:

$$\phi_i = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!\,(|F| - |S| - 1)!}{|F|!} \left[ f(S \cup \{i\}) - f(S) \right]$$
$S$ = subset of features without $i$ $f(S)$ = model prediction using only features in $S$

Shapley values satisfy four axioms that make them the unique fair attribution method:

AxiomMeaning
EfficiencyContributions sum to the total prediction: $\sum_i \phi_i = f(x) - \mathbb{E}[f(x)]$
SymmetryTwo features that add the same amount to every coalition get identical values
DummyA feature that never changes the prediction gets $\phi_i = 0$
LinearityFor a sum of two models, Shapley values add

TreeSHAP and KernelSHAP

Computing exact Shapley values requires evaluating $2^{|F|}$ coalitions. Two approximations make this practical:

  • TreeSHAP: exact Shapley values for tree-based models (XGBoost, LightGBM, random forests) in polynomial time. Use this whenever you have a tree model.
  • KernelSHAP: model-agnostic approximation using weighted linear regression on coalitions. Slower but works for any model.
import shap

# TreeSHAP for a fitted LightGBM classifier (X_test: numpy array)
explainer = shap.TreeExplainer(model)
sv = explainer(X_test)          # an Explanation object, log-odds scale

# Global view: beeswarm of every row's SHAP values
shap.plots.beeswarm(sv)

# Local view: waterfall for one applicant
shap.plots.waterfall(sv[0])

Call the explainer (explainer(X)) rather than explainer.shap_values(X) when you want plots: the waterfall needs an Explanation object and raises a TypeError on a bare array. For a random-forest classifier the Explanation has a class axis — pick the positive class with sv[0, :, 1].

LIME: Local Interpretable Model-agnostic Explanations

LIME explains individual predictions by fitting a simple, interpretable model (usually linear) in the local neighbourhood of the instance. It perturbs the input, gets predictions from the black-box model, and fits a weighted linear model where closer perturbations get higher weight. 

from lime.lime_tabular import LimeTabularExplainer

# X_train / X_test: numpy arrays; feature_names: list of column names
lime_explainer = LimeTabularExplainer(
    X_train,
    feature_names=feature_names,
    class_names=["repay", "default"],
    random_state=0,
)

explanation = lime_explainer.explain_instance(
    X_test[0],              # ONE row as a 1-D array
    model.predict_proba,
    num_features=5,
)
print(explanation.as_list())   # [(feature condition, weight), ...]

If your data is a polars frame, pass X.to_numpy() to the explainer and X.to_numpy()[0] for the row — X[0] on a polars frame is a 1-row DataFrame, and LIME fails with a broadcasting error.

🔵 Theory

SHAP attributions sum to the prediction (efficiency axiom) — exactly for TreeSHAP, approximately for KernelSHAP. LIME's weights come from a local linear fit to random perturbations: they need not sum to the prediction and can change from run to run unless you fix the seed. Use SHAP when you need consistency and additivity; use LIME when you need a quick, model-agnostic local story — and check that the two agree on the top features.

ALE: Accumulated Local Effects

SHAP and LIME explain how much a feature matters; an effect plot shows the shape of its effect. The classic Partial Dependence Plot (PDP) sets feature $j$ to a value $z$ for every row and averages the prediction. When $j$ is correlated with other features that creates impossible rows — on the credit data, an applicant aged 25 with 30 years of employment — and the curve averages the model's guesses on data it never saw.

ALE (Apley & Zhu, 2020) moves only the rows that actually live near each value. Split the range of $x_j$ into quantile bins $[z_{k-1}, z_k]$. For the rows $N_k$ already in bin $k$, move $x_j$ to the bin's upper and lower edges, keep every other feature as it is, and average the change in the model's output:

$$\text{ALE}_j(z_K) \;=\; \sum_{k=1}^{K} \frac{1}{|N_k|} \sum_{i \in N_k} \Bigl[ f\bigl(z_k,\, x_{i,\setminus j}\bigr) - f\bigl(z_{k-1},\, x_{i,\setminus j}\bigr) \Bigr] \;-\; c$$

where $x_{i,\setminus j}$ is row $i$'s other features and the constant $c$ centres the curve so its average is zero. Because each difference uses a real row nudged only within its own bin, no impossible combinations are evaluated. The accumulated sum gives the effect shape: a rising curve means larger values of the feature push the prediction up. 

import numpy as np

def ale_curve(model, X, j, n_bins=10):
    """First-order ALE of feature j on the log-odds scale (centred)."""
    edges = np.unique(np.quantile(X[:, j], np.linspace(0, 1, n_bins + 1)))
    bin_of_row = np.clip(np.searchsorted(edges, X[:, j], side="right") - 1,
                         0, len(edges) - 2)
    effects = np.zeros(len(edges) - 1)
    counts = np.zeros(len(edges) - 1)
    for k in range(len(edges) - 1):
        rows = X[bin_of_row == k]
        if len(rows) == 0:
            continue
        lo, hi = rows.copy(), rows.copy()
        lo[:, j], hi[:, j] = edges[k], edges[k + 1]
        effects[k] = (model.predict(hi, raw_score=True)
                      - model.predict(lo, raw_score=True)).mean()
        counts[k] = len(rows)
    ale = np.concatenate([[0.0], np.cumsum(effects)])
    centre = np.sum((ale[:-1] + ale[1:]) / 2 * counts) / counts.sum()
    return edges, ale - centre

j = feature_names.index("months_employed")
edges, ale = ale_curve(model, X_test[:3000], j)

On the Lesson 3.6 credit model (the LightGBM from the worked example below), the ALE of months_employed falls steadily: about +1.1 log-odds for applicants with no employment history, around 0 near 20 years, and about −1.1 at 30 years — longer employment, lower default risk. Its near-twin employment_years (correlation 0.9996) has a much flatter curve (about +0.3 to −0.6). The model mostly splits on months_employed, so ALE shows the twin adds little on its own. A PDP of either feature would mix in impossible combinations of the two; ALE does not.

🟣 Advanced — ALE vs SHAP for correlated features

Interventional TreeSHAP (the default) also breaks correlations: it replaces "missing" features with values from background rows, which can pair them with impossible partners. With near-duplicate features, SHAP's credit can land almost entirely on one twin. Read SHAP, ALE and permutation importance together; when they disagree about a correlated pair, the disagreement is the finding.

Fairness

Disparate impact

The four-fifths rule: each group's selection (here: approval) rate should be at least 80% of the rate of the most-favoured group. The rule comes from the US EEOC Uniform Guidelines on Employee Selection Procedures (1978) — an employment-law screening heuristic that credit teams widely borrow as a rule of thumb. It is a screen that triggers investigation, not a legal test of lending fairness:

$$\text{DI}(g) = \frac{P(\text{approved} \mid G=g)}{\max_{h} P(\text{approved} \mid G=h)} \;\geq\; 0.8$$
Below 0.8 = adverse impact: investigate Originates in employment selection

Equalised odds

A model satisfies equalised odds if the true positive rate and false positive rate are equal across groups:

$$P(\hat{Y}=1 \mid Y=1, G=a) = P(\hat{Y}=1 \mid Y=1, G=b)$$ $$P(\hat{Y}=1 \mid Y=0, G=a) = P(\hat{Y}=1 \mid Y=0, G=b)$$

The impossibility theorem

⚠ The impossibility theorem

Chouldechova (2017) and Kleinberg et al. (2016) proved that when base rates differ between groups, calibration within groups and equalised odds cannot both hold unless the predictor is perfect. Demographic parity fares no better: combined with calibration it forces equal base rates outright, and combined with equalised odds it forces a classifier whose decisions carry no information about the outcome. So the three criteria are pairwise incompatible — not "pick any two". Except for trivial or perfect predictors, you can satisfy at most one of them, and you must choose which.

This is not a limitation of any particular model — it is a mathematical fact. Fairness is an engineering tradeoff: decide which criterion matters most for your deployment context, measure it, report it, and mitigate where possible.

Worked Example: Explaining and Auditing the Credit Model

📝 Goal

Explain and audit the credit default model Exercise 3.6 builds: a LightGBM trained through kailash-ml's TrainingPipeline on the leak-free synthetic credit data, with defaulters up-weighted, and loaded back from the model registry so we explain exactly the registered artefact. An applicant is declined when the predicted default probability is at least 0.5. The protected attributes in the data are race, gender and age.

Step 1 — SHAP values, and checking additivity. 
import numpy as np
from shared.mlfp03.ex_6 import build_shap_explainer, decode_group

b = build_shap_explainer()      # trains via TrainingPipeline + registry
model, X_test, y_test = b["model"], b["X_test"], b["y_test"]
names, sv, base = b["feature_names"], b["shap_vals"], b["expected_value"]

# Efficiency axiom, on the log-odds scale
raw = model.predict(X_test, raw_score=True)
print(np.abs(base + sv.sum(axis=1) - raw).max())   # ~1e-14

imp = np.abs(sv).mean(axis=0)
for i in np.argsort(-imp)[:5]:
    print(f"{names[i]:<24}{imp[i]:.3f}")
months_employed         0.767
debt_to_income          0.387
credit_utilization      0.375
payment_history_score   0.265
credit_age_years        0.152

Base value plus the SHAP values reproduces the model's raw log-odds to machine precision. Additivity holds in log-odds, not in probability: summing SHAP values against predict_proba would appear to fail. Employment history dominates, followed by debt load and payment behaviour.

Step 2 — Disparate impact per protected attribute. 
y_pred = b["y_pred"]            # 1 = predicted default = DECLINE
groups = {}
for attr in ["race", "gender", "age"]:
    g = decode_group(X_test, names, attr, b["ordinal_mappings"])  # age is banded
    groups[attr] = g
    approval = {k: 1 - y_pred[g == k].mean() for k in np.unique(g)}
    best = max(approval.values())
    di = {k: round(v / best, 3) for k, v in approval.items()}
    base_rate = {k: round(y_test[g == k].mean(), 3) for k in np.unique(g)}
    print(attr, di, base_rate)

Race and gender pass the four-fifths screen comfortably: every group's approval rate is above 95% of the most-approved group's. Age fails badly. Applicants aged 21–34 are approved about 36% as often as those aged 65+. But their default base rate is also about ten times higher (about 25% against about 3%). The screen flags the outcome; it cannot tell you whether the gap is justified risk or unfair treatment.

Step 3 — Equalised odds: TPR and FPR per group. 
g = groups["age"]
for k in np.unique(g):
    m = g == k
    tpr = y_pred[m & (y_test == 1)].mean()   # defaulters correctly declined
    fpr = y_pred[m & (y_test == 0)].mean()   # good applicants wrongly declined
    print(f"{k:<6} TPR={tpr:.3f}  FPR={fpr:.3f}")

Use explicit comparisons such as (y_test == 0), never ~y_test: on an integer array ~ is bitwise NOT (~0 == -1), not logical negation. Across age bands the false-positive rate ranges from more than half of good young applicants wrongly declined to almost none of the oldest. Equalised odds is far from satisfied, and — because base rates differ this much — the impossibility theorem says no threshold choice can equalise it while keeping the scores calibrated within each group.

Step 4 — Report and route the decision.

Document which criteria were measured, which passed, which failed, and the base-rate context. A failure such as the age result is not "fixed" automatically by re-weighting until the ratio passes: it is routed to a human decision (a risk committee) that chooses which fairness criterion matters for this product and accepts the trade-off in writing. Singapore's FEAT principles call for exactly this kind of fairness and transparency assessment. They are non-binding principles and do not prescribe a metric or a numeric threshold.

Common Mistakes

⚠ Mistake 1: Using SHAP for causal claims

SHAP tells you which features the model uses. It does not tell you which features cause the outcome. "Income has high SHAP importance" does not mean income causes creditworthiness.

⚠ Mistake 2: Removing a protected feature and assuming fairness

Other features (postcode, school, employment history) are often proxies for the protected attribute. Removing gender from the model does not prevent gender discrimination.

⚠ Mistake 3: Optimising for one fairness metric blindly

The impossibility theorem means optimising for demographic parity will break calibration whenever base rates differ. Always measure and report several metrics, and state which one you prioritised.
