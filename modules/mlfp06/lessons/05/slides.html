Function calling

from kaizen_agents.delegate.loop import ToolRegistry
from shared.mlfp06.ex_5 import data_summary

async def run_data_summary(dataset_name: str = "qa_data") -> str:
    return data_summary(dataset_name)      # plain Python tool, returns text

registry = ToolRegistry()
registry.register(
    name="data_summary",
    description="Summarise the loaded dataset: rows, columns, lengths",
    parameters={"type": "object",          # JSON Schema the LLM fills in
                "properties": {"dataset_name": {"type": "string"}},
                "required": []},
    executor=run_data_summary,             # async callable you own
)

Structured schemas. The LLM picks the tool and fills the arguments; your executor runs it. Provider APIs add a tool_choice switch (auto / required / a named function) and may return several calls in one turn (parallel function calling).

Agent design framework

  1. Goal: what is the agent supposed to achieve?
  2. Thought process: what reasoning steps?
  3. Specialist: be sharp — "data analysis researcher" not "researcher".
  4. Tools: versatile, fault-tolerant, with caching.

Then add the safety rails: a critic agent that reviews and requests revisions (Exercise 5.4), a human-in-the-loop pause before irreversible actions, and logged traces of every intermediate step.

Kaizen agents

from shared.mlfp06._ollama_bootstrap import make_delegate
from shared.mlfp06.ex_5 import build_tool_registry, load_hotpotqa, make_tools

tools = make_tools(load_hotpotqa())     # data_summary, search_documents, ...
agent = make_delegate(                  # model from OLLAMA_CHAT_MODEL
    tools=build_tool_registry(tools),   # bare callables register NOTHING
    system_prompt="Use the tools to gather evidence before you answer.",
    max_turns=8,                        # hard ceiling on Thought-Action loops
)
async for event in agent.run("How many comparison questions are there?"):
    ...                                 # tool calls + answer stream as events
⚙ Kailash: a Delegate with a ToolRegistry is a ReAct loop (Exercise 5.1). Spend caps: BaseAgentConfig(budget_limit_usd=…) — pass it at construction; setting it later is not enforced. On free local Ollama every call is priced $0, so dollar caps never trip: max_turns and token counts are the real limits. For reasoning without tools, Kaizen's ChainOfThoughtAgent runs step-by-step reasoning before answering.

Tool design principles

  • 3–5 tools max — more tools confuse the agent.
  • Clear descriptions — the LLM reads them to choose.
  • Error handling — tools should return errors, not crash.
  • Caching — avoid re-computing expensive operations.

Common mistakes

  1. Too many tools — agent performance degrades.
  2. No turn ceiling or budget — a looping agent keeps calling the model; cap max_turns and, on priced providers, the spend.
  3. Trusting agent output — agents hallucinate. Verify critical results.
  4. No observation logging — capture traces (LLMObservatory().agent.capture_run) to debug agent behaviour.
