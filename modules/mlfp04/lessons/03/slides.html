Dimensionality Reduction

PCA · SVD · Kernel PCA · t-SNE · UMAP · Intrinsic dimension

⏱ 90 minutes   ·   Outcome: find how many of 7 customer features you really need

From "which group" to "which axis"

  • Clustering partitioned the points. Dimensionality reduction rotates the features.
  • Goal: fewer features, most variance kept.
  • Uses: visualisation, compression, feature extraction.
🟢 Foundations: if two features carry the same information, you have one feature's worth of signal. Reduction finds the non-redundant directions.

PCA rotates the axes to the data

Deriving PCA — one Lagrangian

Maximise projected variance subject to unit norm:

\[ \max_{\mathbf{w}}\ \mathbf{w}^\top C\,\mathbf{w}\quad \text{s.t. } \lVert \mathbf{w}\rVert = 1 \]

Taking derivatives of the Lagrangian:

\[ C\mathbf{w} \;=\; \lambda\,\mathbf{w} \]
🔵 Theory: The solution is the top eigenvector of the covariance matrix. The variance captured = the corresponding eigenvalue.

SVD = PCA's computational engine

\[ X \;=\; U\,\Sigma\,V^\top \]

V = principal directions. Σ²/(N−1) = variances. Every serious PCA uses SVD.

Scree plot: how many components?

Rule of thumb: take the smallest $k$ where cumulative variance reaches your threshold — 90–95% is the usual range.

Loadings make PCA interpretable


for i in range(3):
    top = np.argsort(-np.abs(pca.components_[i]))[:3]
    print(f"PC{i+1} (var={pca.explained_variance_ratio_[i]:.3f}):")
    for j in top:
        print(f"  {feature_names[j]}: {pca.components_[i][j]:+.3f}")

On the 7 standardised customer features: PC1 = +0.71 avg order value + 0.65 revenue − 0.28 order count → "spend per order" (26.5% of variance).

Kernel PCA — for curved structure

  • Standard PCA can only rotate.
  • Kernel PCA applies PCA in an implicit feature space via $k(\mathbf{x}, \mathbf{y}) = \phi(\mathbf{x})^\top \phi(\mathbf{y})$.
  • Common kernels: RBF, polynomial.
  • Cost: $O(N^2)$ memory — only for ~few thousand points.
  • No exact inverse: mapping back to input space (the pre-image problem) needs an approximation, e.g. fit_inverse_transform=True.

t-SNE: good for plots, bad for features

\[ \text{KL}(P \,\|\, Q) \;=\; \sum_{i \neq j}\ p_{ij}\ \log \frac{p_{ij}}{q_{ij}} \]
  • Minimises KL between pair-distributions in high-dim and low-dim.
  • Preserves local structure, distorts global.
  • Non-deterministic, no inverse transform.
  • Hyperparameter: perplexity (~5–50).
⚠ Never use t-SNE for feature extraction. Use it only to see.

UMAP: newer, faster, better defaults

  • Better global layout than t-SNE — but cluster sizes and gaps are still not quantitative.
  • ~10× faster. Scales to millions of points.
  • Can embed new points with .transform() (t-SNE cannot).
  • Deterministic (given a seed).

Default choice for any visualisation task. Fall back to t-SNE only when specifically needed.

Other manifold learners: Isomap, LLE, MDS

MethodPreservesUse whenWatch out

Isomapgeodesic distances along a k-NN graphone smooth manifold to "unroll" (Swiss roll)one wrong shortcut edge breaks the geometry

All in sklearn.manifold (MDS, Isomap, LocallyLinearEmbedding). In practice UMAP has replaced them for visualisation; know them for the ideas — distances, geodesics, local linearity.

Reference table only, as the spec asks: a brief mention. Classical MDS on Euclidean distances is equivalent to PCA; Isomap is MDS on geodesic (graph shortest-path) distances; LLE reconstructs each point from its neighbours and keeps those weights in low dimension. Isomap and LLE scale poorly and are sensitive to n_neighbors.

Comparing reducers: trustworthiness, not silhouette

  • t-SNE and UMAP pull points into blobs by construction — K-means silhouette in the embedding rewards the picture, not faithfulness.
  • Trustworthiness ∈ [0, 1]: are a point's embedding neighbours its real neighbours? 1 = no false neighbours.

from sklearn.manifold import trustworthiness
t = trustworthiness(X_sample, embedding, n_neighbors=10)   # same rows for every reducer

Exercise 3.5 ranks PCA, kernel PCA, t-SNE, UMAP and Isomap by trustworthiness on the same 3,000 rows (it needs all pairwise distances); silhouette is kept only as a "clusterability" column.

This mirrors the corrected Exercise 3 design. Silhouette measured inside a t-SNE or UMAP embedding is circular: those methods manufacture separated clusters. Trustworthiness penalises points that appear as neighbours in the embedding but are far apart in the original space. Always compute it on the same subsample for every method.

Eckart-Young: PCA is optimal

Best rank-$k$ approximation in Frobenius norm:

\[ \min_{\text{rank}(\hat X) \leq k}\ \lVert X - \hat X \rVert_F^2 \;=\; \sum_{i=k+1}^{r}\sigma_i^2 \]

achieved by $\hat X = U_k \Sigma_k V_k^\top$ — the truncated SVD.

🔵 Theory: PCA is provably the best linear low-rank approximation. No linear method beats it.

Intrinsic dimension

How many components do you truly need?

  • Scree elbow — visual estimate.
  • Variance threshold — smallest $k$ with $\sum_{i\le k} \sigma_i^2 / \sum_i \sigma_i^2 \ge$ 0.90–0.95.
  • Participation ratio: $(\sum \lambda_i)^2 / \sum \lambda_i^2$.
  • Nearest-neighbour MLE (Levina–Bickel), with $T_j(x)$ the distance to the $j$-th neighbour: $\hat m_k(x) = \Bigl[\tfrac{1}{k-1}\sum_{j=1}^{k-1} \log \tfrac{T_k(x)}{T_j(x)}\Bigr]^{-1}$, averaged over $x$. Non-linear: it sees curved manifolds PCA cannot.

Customer data (7 features): 90% → 5 PCs, 95% → 6 PCs, participation ratio ≈ 5.3. Sanity check: the MLE returns ≈ 8 on 8-D Gaussian noise.

Worked example: compress customer features


pca = PCA().fit(X)   # X = 7 standardised customer features, 50,000 rows
cum = np.cumsum(pca.explained_variance_ratio_)
k90 = int(np.searchsorted(cum, 0.90)) + 1   # → 5 components (92.2%)
k95 = int(np.searchsorted(cum, 0.95)) + 1   # → 6 components (98.0%)

Only 7 → 5: these features are not very redundant. PCA pays off most when you have many correlated features — then downstream models train faster and overfit less.

Kailash DimReductionEngine + ModelVisualizer


import polars as pl
from kailash_ml import ModelVisualizer
from kailash_ml.engines.dim_reduction import DimReductionEngine

X_df = pl.from_numpy(X, schema=feature_cols)      # standardised features
engine = DimReductionEngine()                     # "pca" | "nmf" | "tsne" | "umap"
info = engine.variance_analysis(X_df)
print(info["n_components_95"], info["elbow_component"])

res = engine.reduce(X_df, algorithm="pca", n_components=2)
print(res.explained_variance_ratio, res.reconstruction_error)
emb = pl.DataFrame(res.transformed, schema=["pc1", "pc2"], orient="row")
fig = ModelVisualizer().scatter(emb, x="pc1", y="pc2", title="Customers on PC1/PC2")
fig.write_html("pca_scatter.html")
⚙ Kailash: the engine reports variance and reconstruction error; loadings you read yourself (previous slide). ModelVisualizer has no scree helper — plot info["cumulative_variance"] with plotly.
Bridge from sklearn PCA to the Kailash surface used in the exercises and assessment. variance_analysis returns explained_variance_ratio, cumulative_variance, elbow_component and n_components_95. reduce returns a DimReductionResult whose transformed field is a list of rows, so wrap it in a polars DataFrame before plotting. The engine does not standardise for you.

Four rookie mistakes

  1. Forgetting to centre/standardise the data.
  2. Using t-SNE as a feature extractor.
  3. Picking $k$ that is too small (over-aggressive compression).
  4. Reporting components without loadings — black-box PCA.
