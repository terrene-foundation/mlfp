🟢 Foundations: Know the eight kinds of problem. Outliers are not an alert — each column reports outlier_count instead. Mixed date formats are not detected at all: that check stays yours.

Running your first profile


from shared import MLFPDataLoader, run_profile

loader = MLFPDataLoader()
cpi = loader.load("mlfp01", "sg_cpi.csv")   # monthly CPI, 300 rows

profile = run_profile(cpi)

print(f"Alerts fired: {len(profile.alerts)}")   # 11
for alert in profile.alerts:                     # each alert is a dict
    where = alert.get("column", alert.get("columns"))
    print(f"  {alert['type']}: {where} ({alert['value']:.2f})")

run_profile(df) is a sync wrapper around the async DataExplorer().profile(df) — it works in a script and in Colab/Jupyter. Alerts are dicts: type, column (or columns), value, severity.

What the profile returns

Configuring thresholds


from kailash_ml import AlertConfig

config = AlertConfig(
    high_null_pct_threshold=0.02,     # fire above 2% (default 0.05)
    high_correlation_threshold=0.99,  # only near-duplicates (default 0.9)
    skewness_threshold=2.0,           # default 2.0
)

profile = run_profile(cpi, alert_config=config)
print(len(profile.alerts))   # 12: now also 4 x high_nulls (5% null)

Other fields: constant_threshold (a unique-value count, default 1), zero_pct_threshold 0.5, high_cardinality_ratio 0.9, imbalance_ratio_threshold 0.1, duplicate_pct_threshold 0.0.

🔵 Theory: There is no universal "correct" threshold. Thresholds encode your domain expectations. Lower = more alerts; higher = fewer.

compare(): before vs after


from shared import run_compare

cpi_clean = (
    cpi.with_columns(
        pl.col("date")                       # 3 formats -> YYYY-MM-01
        .str.replace(r"^(\d{2})/(\d{4})$", "$2-$1-01")
        .str.replace(r"^(\d{4})(\d{2})$", "$1-$2-01")
        .str.replace(r"^(\d{4})-(\d{2})$", "$1-$2-01")
        .str.to_date("%Y-%m-%d"))
    .sort("date")
    .with_columns(pl.col(pl.Float64).interpolate())   # fill the gaps
)

result = run_compare(cpi, cpi_clean)   # a dict
for d in result["column_deltas"]:
    print(d["column"], d["null_pct_delta"])   # cpi_*: -0.05
🟢 Foundations: compare(df_a, df_b) takes two DataFrames and answers: "did my cleaning actually help?"

Comparison result

With the stricter config: the four high_nulls warnings are gone. The rest are expected — measurements are near-unique (info) and CPI components move together. Judge each alert; do not chase a count of zero.

Classes: using, not building


from kailash_ml import DataExplorer

# You USE DataExplorer — you don't build it
explorer = DataExplorer(alert_config=config)   # create an instance
print(type(explorer).__name__)                 # DataExplorer

# Its methods (profile, compare, to_html) are async;
# run_profile(df, alert_config=config) creates the instance
# and runs profile() for you.
# Same pattern for every Kailash engine:
#   engine = EngineClass(settings)
#   result = engine.do_something(data)

A class bundles data and methods together. You will build your own classes in Module 3. Today: consumer only.

Handling errors: try/except


try:
    df = loader.load("mlfp01", "nonexistent.csv")  # expect-error
    profile = run_profile(df)
except FileNotFoundError as e:
    print(f"File missing: {e}")
except ValueError as e:
    print(f"Bad data: {e}")
⚠ Warning: Never write except: pass — that silently swallows every error. Always name the exception type and handle it explicitly.

compare() for train vs test


# Time-ordered split: first 80% of months vs last 20%
n = cpi_clean.height
df_train = cpi_clean.head(int(n * 0.8))
df_test  = cpi_clean.tail(n - int(n * 0.8))

result = run_compare(df_train, df_test)
for d in result["column_deltas"]:
    if "mean_delta" in d:
        print(f"{d['column']}: mean shifted {d['mean_delta']:+.1f}")
# cpi_all_items: mean shifted +68.4   (prices rise over time)
🟣 Advanced: A trending series always shifts across a time split. This is the preview of drift monitoring (Module 3): compare two distributions, flag differences.

Three mistakes to avoid

1. Ignoring alerts because there are too many
Retune the thresholds — do not silence the engine.
2. Profiling before fixing obvious issues
Fix mixed types and obviously wrong schemas first. Then profile.
3. Auto-dropping correlated columns
Alerts prompt investigation, not automated removal.
