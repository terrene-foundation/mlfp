Speaker Notes — Lesson 2.7 CUPED and Causal Inference

Total time: ~55 minutes  ·  15 slides  ·  ~3.5 min per slide average

Two advanced tools today. CUPED: use pre-experiment data to shrink experiment variance — the theory promises big wins (ρ = 0.7 halves the variance), and the honest lesson is that our real experiment data only delivers ≈4%, so teach both the promise and the measurement. Then difference-in-differences for when randomisation is impossible, with the parallel-trends assumption front and centre.

Slide 1~1 minTitle

CUPED and Causal Inference

Open with the outcome line from the slide: "Today you'll learn to cut A/B test variance with data you already have — and what to do when you can't run an experiment at all." Agenda: variance reduction, the SRM check again (it matters enough to revisit), difference-in-differences, and parallel trends.

→ "The problem that motivates everything."
Slide 2~3 minNoisy experiments

The problem: noisy experiments

Set the scene: "Your A/B test shows a +3% lift in spending, but $p = 0.12$. Not significant. The effect might be real — you just can't tell." Walk the three options: run longer (expensive, delays launch), get more users (not always possible), or reduce the variance — free and immediate.

Read the green box: "CUPED uses data you already have — pre-experiment behaviour — to shrink the noise. Same data, more power."

→ "The formula."
Slide 3~4 minCUPED formula

CUPED: the key formula

Walk the adjustment: $Y_{\text{adj}} = Y - \theta(X - E[X])$. "Take each user's outcome and subtract the part that's predictable from their pre-experiment behaviour $X$. What remains is purer signal." The optimal $\theta^* = \text{Cov}(Y,X)/\text{Var}(X)$ minimises the variance — it's just the OLS coefficient of $Y$ on $X$ from 2.5.

Then the blue box — the money formula: $\text{Var}(Y_{\text{adj}}) = \text{Var}(Y)(1 - \rho^2)$. "The variance shrinks by one minus the squared correlation between pre and post. Everything rides on $\rho$."

Intuition: "Two users with identical pre-experiment spending would have spent identically without the treatment. Their difference after is nearly pure treatment effect. CUPED applies that logic to everyone at once."
→ "How much does it buy, in numbers?"
Slide 4~3 minRho table

How much does CUPED buy you?

Walk the table row by row: $\rho = 0.3$ removes 9% of variance (like getting 1.10× the sample), 0.5 removes 25% (1.33×), 0.7 removes 49% (1.96× — nearly double the sample for free), 0.9 removes 81% (5.26×).

Read the green box: "E-commerce: pre-experiment spend typically correlates 0.6–0.8 with post-experiment spend — that's 36% to 64% variance reduction, for free. This is why every large experiment platform runs CUPED or something like it by default."

→ "The picture."
Slide 5~2 minBefore/after

Before vs after CUPED

Walk the two panels. Left: the raw difference-in-means — wide distribution, $p = 0.12$, not significant. Right: after CUPED, the same effect size with a much tighter distribution — $p = 0.003$. "Same data, same effect estimate, smaller standard error. The treatment didn't change; our ability to see it did."

→ "Let's do it in code — on the real experiment data."
Slide 6~4 minCUPED code

CUPED in code

Walk the code. Load the experiment data, keep control and treatment_a — the SRM-clean pair from 2.4. The outcome is revenue; the covariate is pre_metric_value, measured before randomisation. Compute $\theta$ pooled over both arms, adjust, and compare the raw and CUPED standard errors.

Now the honest moment — read the printed numbers: raw effect 3.16 (SE 0.164), CUPED effect 3.18 (SE 0.160). "On this data, $\rho = 0.21$, so CUPED removes only about 4% of the variance. The effect estimate barely moves. Teach the disappointment: CUPED is only as good as your pre-metric's correlation. Check $\rho$ before you promise anything."

Close with the blue theory box: "CUPED is the residual from regressing $Y$ on $X$. The optimal $\theta$ is the regression coefficient — you already knew it from 2.5."

→ "So when does it work?"
Slide 7~3 minRequirements

When does CUPED work?

Walk the three requirements. High $\rho$ — the pre-metric must correlate with the post-metric; e-commerce spending sits at 0.6–0.8. Pre-experiment only — the covariate must be measured before randomisation. Same users — you need pre and post measurements for the same individuals.

Read the amber warning slowly: "Never use a post-experiment covariate. It may be affected by the treatment — adjusting for it removes the very effect you're measuring. This is the CUPED equivalent of peeking: seductive and fatal."

→ "Back to the check that guards everything: SRM."
Slide 8~3 minSRM recap

SRM: is your experiment broken?

Walk the code: chi-squared the observed arm counts against the designed split — flag at $p < 0.01$. Then walk the table: 5000/5000 is clean ($p = 1.0$), 4900/5100 is borderline ($p = 0.046$ — above the 0.01 flag), 4800/5200 is SRM ($p = 0.00006$ — do not trust results).

Read the footer — it's the point students miss in the exercises: "Our exercise data is designed 40/35/15/10. Test against those shares. A 50/50 test would flag SRM on a perfectly correct split — you'd be rejecting good data."

→ "What causes it in the wild?"
Slide 9~2 minSRM causes

Common SRM causes

Walk the four causes: bot filtering (bots disproportionately hit one variant), redirect bugs (one variant's page fails to load for some users), population filters applied after randomisation that exclude users unevenly, and bucketing errors — a hash function that isn't uniform.

Read the red rule: "Always check SRM before computing treatment effects. It costs one chi-squared test and it invalidates everything downstream."

→ "Now: what if you can't randomise at all?"
Slide 10~3 minDiD concept

When you cannot randomise

"A policy cannot be randomly assigned — you can't randomly decide which flats get a cooling measure." Exercise 7.4 simulates a hypothetical cooling measure on Central-region flats only; the analysis compares Central (treated) with Non-Central (control), before and after.

Walk the ATT formula: $(\bar{Y}_{T,\text{post}} - \bar{Y}_{T,\text{pre}}) - (\bar{Y}_{C,\text{post}} - \bar{Y}_{C,\text{pre}})$. "The first difference removes the group level — Central flats were already pricier. The second removes the time trend — the whole market moved. What remains is the policy."

→ "See it."
Slide 11~3 minDiD picture

DiD: the picture

Walk the figure. Blue is control — drifting gently upward through the policy date. Teal is treated — tracking the control until the dashed amber policy line, then breaking sharply upward. The dashed teal extension is the counterfactual: where treated would have been without the policy. The red bracket between the treated line and its counterfactual is the ATT.

"DiD is a bet about that dashed line: that treated would have followed control's trend. Everything hangs on that bet — next slide."

→ "The assumption you cannot test."
Slide 12~3 minParallel trends

The parallel trends assumption

State it plainly: "DiD assumes that without treatment, both groups would have followed the same trend." Walk the three bullets. Check: plot pre-period trends for both groups — they should be parallel. Placebo test: run DiD on a fake treatment date inside the pre-period — it should find no effect. If violated: DiD is biased; consider synthetic control instead.

Read the blue box carefully — it's the epistemically honest point: "Parallel trends is untestable — it's a claim about a counterfactual that never happened. Pre-period parallelism is necessary but not sufficient. You gather evidence; you never get proof."

→ "Run it on the simulated panel."
Slide 13~3 minDiD code

DiD in code

Walk the code. simulate_hdb_cooling_panel from the ex_7 helpers builds the simulated panel — the true policy effect is −20,000 dollars, so we can check the method's answer against ground truth. Group by region and period, take the four cell means, and difference twice.

Read the output: ATT ≈ −23,208 against a true −20,000. "Off by about 3,200 — that's sampling noise, not bias. The method recovers the truth up to noise, which is all we can ever ask. In the exercise you'll also see the placebo check and what happens when parallel trends breaks."

→ "Three ways these tools get abused."
Slide 14~2 minMistakes

Three mistakes to avoid

Walk the three red boxes. One: post-experiment covariate in CUPED — removes part of the treatment effect; always pre-experiment. Two: skipping the SRM check — a broken experiment gives meaningless p-values; check the split first. Three: DiD without a parallel trends check — divergent pre-trends bias the estimate; always plot and placebo-test.

→ "Recap and bridge to the capstone."
