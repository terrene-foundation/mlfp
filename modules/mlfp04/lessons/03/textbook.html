Lesson 4.3 Dimensionality Reduction — Finding the Axes That Matter

Clustering asked "which group does this point belong to?" Dimensionality reduction asks a different question: "which directions in feature space carry the most information?" Today you will derive principal component analysis from first principles, connect it to the singular value decomposition, and meet its non-linear cousins — kernel PCA, t-SNE, and UMAP. By the end you will know when to use each and why t-SNE is great for visualisation but dangerous for feature extraction.

Why This Matters

A modern business dataset easily has 50 – 500 features. Most of them are correlated: "total_spend" and "n_transactions" carry overlapping information; "minutes_on_site" and "pages_viewed" do too. When features are correlated, distance-based algorithms waste capacity and models overfit. Dimensionality reduction replaces the original features with a smaller set of new features — linear combinations of the originals — that are uncorrelated and ordered by variance.

The idea has three uses: visualisation (project high-dim data to 2D so humans can see it), compression (store less without losing much), and feature extraction (feed the reduced features into a downstream model to avoid the curse of dimensionality). Today we care most about feature extraction — the principal components are learned features, the first step on the spectrum from manual engineering to automated discovery.

Core Concepts

PCA in one sentence

Principal component analysis finds an orthonormal basis for your data such that the first axis captures as much variance as possible, the second axis captures as much of the remaining variance as possible, and so on. The first $k$ axes span a $k$-dimensional subspace that is the optimal low-rank approximation of your data in a least-squares sense.

Derivation via variance maximisation

Let $X \in \mathbb{R}^{N \times D}$ be the centred data matrix (each column has mean zero). We want a unit vector $\mathbf{w}$ that maximises the variance of the projected points $X \mathbf{w}$:

$$ \max_{\mathbf{w}}\ \text{Var}(X\mathbf{w}) \;=\; \max_{\mathbf{w}}\ \mathbf{w}^\top C\,\mathbf{w}\quad \text{subject to } \lVert \mathbf{w}\rVert = 1 $$

where $C = \frac{1}{N-1} X^\top X$ is the sample covariance matrix. Using a Lagrange multiplier $\lambda$ for the norm constraint:

$$ \mathcal{L}(\mathbf{w}, \lambda) \;=\; \mathbf{w}^\top C\,\mathbf{w} - \lambda(\mathbf{w}^\top \mathbf{w} - 1) $$ $$ \frac{\partial \mathcal{L}}{\partial \mathbf{w}} \;=\; 2 C \mathbf{w} - 2\lambda \mathbf{w} \;=\; 0 \quad \Longrightarrow\quad C\mathbf{w} \;=\; \lambda \mathbf{w} $$

This is an eigenvalue equation. The vector $\mathbf{w}$ that maximises $\mathbf{w}^\top C \mathbf{w}$ is the eigenvector of $C$ with the largest eigenvalue — which equals the variance along that direction. The next principal component is the eigenvector with the second-largest eigenvalue, constrained to be orthogonal to the first, and so on.

🔵 Theory

Every symmetric positive semi-definite matrix (like the covariance $C$) has orthonormal eigenvectors with non-negative eigenvalues. So the spectral decomposition $C = V \Lambda V^\top$ always exists, and PCA reduces to sorting the columns of $V$ by the corresponding $\lambda_i$. This is a rare case in ML where the optimisation has a closed-form solution.

The SVD connection

The singular value decomposition of the data matrix writes

$$ X \;=\; U\,\Sigma\,V^\top $$

where $U \in \mathbb{R}^{N \times r}$ and $V \in \mathbb{R}^{D \times r}$ have orthonormal columns, $\Sigma$ is diagonal with non-negative entries $\sigma_1 \geq \sigma_2 \geq \cdots \geq \sigma_r \geq 0$ (the singular values), and $r = \min(N, D)$. The columns of $V$ are exactly the principal component directions, and $\lambda_i = \sigma_i^2 / (N-1)$. This is why every modern PCA implementation uses SVD under the hood: it is numerically more stable than forming $X^\top X$ and is just as fast.

Reading a scree plot

The scree plot shows the variance explained by each principal component in descending order. You pick $k$ — the number of components to keep — by eyeballing the "elbow" (the same idea as elbow-method K-means) or by picking the smallest $k$ such that the cumulative variance explained exceeds a threshold (e.g., 0.90).

The loadings — the entries of $V$ — tell you which original features each principal component weights. In the worked example below, PC1 has loading +0.71 on avg_order_value and +0.65 on total_revenue, so it roughly means "how much this customer spends". Interpreting loadings is how you turn PCA from a black box into a feature-engineering conversation.

Kernel PCA

Standard PCA is a linear method — it can only rotate the axes, not bend them. When the variance-maximising directions are curved (think data on a spiral or a torus), linear PCA fails. Kernel PCA applies the kernel trick: instead of computing PCA in the input space, compute it in an implicit higher-dimensional feature space defined by a kernel function $k(\mathbf{x}, \mathbf{y}) = \phi(\mathbf{x})^\top \phi(\mathbf{y})$. Common kernels are RBF (Gaussian) and polynomial. The cost is that you must store and eigendecompose an $N \times N$ kernel matrix, so kernel PCA only scales to a few thousand points. And unlike linear PCA it has no exact inverse: a point in the implicit feature space generally has no exact pre-image in the input space, so reconstruction needs an approximation such as scikit-learn's KernelPCA(fit_inverse_transform=True), which learns an approximate inverse map by kernel ridge regression.

t-SNE and UMAP — for visualisation

t-SNE (t-distributed Stochastic Neighbour Embedding) is a non-linear embedding designed specifically for visualisation. It defines a probability distribution over pairs of points in the high-dimensional space — $p_{ij}$ is high if points are close — and another distribution $q_{ij}$ in the low-dimensional space, then minimises the KL divergence between them:

$$ \text{KL}(P \,\|\, Q) \;=\; \sum_{i \neq j}\ p_{ij}\ \log \frac{p_{ij}}{q_{ij}} $$

t-SNE preserves local structure well — points that were close stay close — but it distorts global structure: cluster sizes and the distances between clusters in a t-SNE plot are not meaningful. It has no way to embed a new point without refitting (scikit-learn's TSNE has fit_transform but no transform), no inverse mapping, and different random seeds give different layouts. Use it for visualisation, never for feature extraction.

UMAP (Uniform Manifold Approximation and Projection) is newer and usually faster. It builds a weighted $k$-nearest-neighbour graph and lays it out in low dimension; n_neighbors trades local against global structure and min_dist controls how tightly points pack. Its global layout is usually better than t-SNE's, but cluster sizes and inter-cluster distances in a UMAP plot are still not quantitatively meaningful. Unlike t-SNE it can embed new points with .transform() (Exercise 3.4 fits on a subsample and transforms held-out rows), which is what makes it usable in a production pipeline; it also offers an approximate inverse_transform. In practice, try UMAP first for visualisation; fall back to t-SNE when you want its particular emphasis on local neighbourhoods.

Other manifold learners — a reference table

PCA, kernel PCA, t-SNE and UMAP are the methods you will use most. Three classical manifold learners are worth recognising; all are in sklearn.manifold and all scale poorly beyond tens of thousands of points.

Intrinsic dimension

Data can live in $p$ ambient dimensions but vary along only $d \ll p$ independent directions; $d$ is its intrinsic dimension. Knowing $d$ tells you how far you can reduce without losing real structure. Two estimates are common:

  • PCA thresholds — the number of components needed to reach 90% or 95% of the variance. This counts linear dimensions, so it overestimates $d$ for curved manifolds (a Swiss roll needs all three principal components but is intrinsically two-dimensional).
  • The nearest-neighbour MLE of Levina and Bickel (2004). Let $T_j(\mathbf{x})$ be the distance from $\mathbf{x}$ to its $j$-th nearest neighbour (excluding $\mathbf{x}$ itself). If the data are locally uniform on a $d$-dimensional manifold, the number of neighbours within radius $r$ grows like $r^d$, and the maximum-likelihood estimate at $\mathbf{x}$ is $$ \hat{m}_k(\mathbf{x}) \;=\; \left[\frac{1}{k-1}\sum_{j=1}^{k-1}\log\frac{T_k(\mathbf{x})}{T_j(\mathbf{x})}\right]^{-1}, $$ averaged over the points (and, for stability, over several $k$). It is non-linear: it reports about 2 for a Swiss roll and about 8 for an 8-dimensional Gaussian cloud. Exact duplicate rows give $T_j = 0$ and must be removed first.

Mathematical Foundations

Eckart-Young theorem

The deepest result in PCA is the Eckart-Young theorem: the best rank-$k$ approximation of a matrix $X$ in Frobenius norm is obtained by truncating its SVD. Formally, among all rank-$k$ matrices $\hat{X}$,

$$ \min_{\text{rank}(\hat{X}) \leq k}\ \lVert X - \hat{X}\rVert_F^2 \;=\; \sum_{i=k+1}^{r}\ \sigma_i^2 $$

and the minimum is achieved by $\hat{X} = U_k \Sigma_k V_k^\top$ where the subscript $k$ means "first $k$ columns". In English: among all rank-$k$ linear reconstructions, PCA has the smallest squared reconstruction error, and that error equals the sum of the dropped singular values squared. Since $\lambda_i = \sigma_i^2/(N-1)$, the same error is $(N-1)\sum_{i>k}\lambda_i$, i.e. a mean squared error per matrix entry of $\frac{N-1}{N}\cdot\frac{1}{D}\sum_{i>k}\lambda_i$ — the worked example checks this number.

Reconstruction error and variance explained

Because $\sum_i \sigma_i^2 = \lVert X \rVert_F^2$, the fraction of variance explained by the first $k$ components is $\sum_{i=1}^{k} \sigma_i^2 / \sum_{i=1}^{r} \sigma_i^2$. Setting this to 0.9 or 0.95 is the standard heuristic for choosing $k$.

Worked Example: Compressing the Customer Feature Set

The same seven behaviour features as Lesson 4.1 (churned is an outcome and stays out). PCA is cheap, so it runs on all 50,000 customers; the neighbour-based steps use samples. 

import numpy as np
import polars as pl
from sklearn.decomposition import PCA

from shared import MLFPDataLoader

FEATURES = ["total_revenue", "order_count", "avg_order_value",
            "days_since_last_order", "customer_tenure_days",
            "satisfaction_score", "num_returns"]
customers = MLFPDataLoader().load("mlfp03", "ecommerce_customers.parquet")
X = customers.select(FEATURES).drop_nulls().to_numpy().astype(np.float64)
X = (X - X.mean(axis=0)) / X.std(axis=0)          # centre AND standardise

pca = PCA().fit(X)
cum = np.cumsum(pca.explained_variance_ratio_)
for i, (ev, cv) in enumerate(zip(pca.explained_variance_, cum)):
    print(f"PC{i + 1}: eigenvalue={ev:.2f}  cumulative={cv:.3f}")
k90 = int(np.searchsorted(cum, 0.90)) + 1
print(f"Need {k90} components to reach 90% variance (down from {X.shape[1]} features)")

# Interpret the first 3 components
for i in range(3):
    top = np.argsort(-np.abs(pca.components_[i]))[:3]
    print(f"PC{i+1}: " + ", ".join(f"{FEATURES[j]} ({pca.components_[i][j]:+.2f})" for j in top))

Five components pass 90% of the variance and six pass 95%. The loadings say why. PC1 loads on avg_order_value (+0.71) and total_revenue (+0.65): a spend axis. PC2 loads equally on days_since_last_order and customer_tenure_days: a customer-age axis — long-standing customers are also the ones who last ordered long ago. Those two correlated pairs are the only real redundancy. PC3–PC5 have eigenvalues of almost exactly 1.0: for standardised data that is the signature of features essentially uncorrelated with everything else (order count, satisfaction, returns), each needing a component of its own. There is no sharp scree elbow: this dataset is genuinely about five-dimensional. 

from sklearn.neighbors import NearestNeighbors

# Reconstruction error with 4 components vs the eigenvalue formula
pca_4 = PCA(n_components=4)
X_recon = pca_4.inverse_transform(pca_4.fit_transform(X))
n, p = X.shape
mse = np.mean((X - X_recon) ** 2)
predicted = (n - 1) / n * pca.explained_variance_[4:].sum() / p
print(f"Reconstruction MSE (4 components): {mse:.4f}   predicted: {predicted:.4f}")

# Intrinsic dimension: Levina-Bickel MLE on a 2,000-row sample
rng = np.random.default_rng(42)
X_id = X[rng.choice(n, 2000, replace=False)]

def levina_bickel(X, k=20):
    dist, _ = NearestNeighbors(n_neighbors=k + 1).fit(X).kneighbors(X)
    T = dist[:, 1:]                      # drop each point's distance to itself
    ok = np.all(T > 0, axis=1)           # duplicates would give log(0)
    return float((1.0 / np.log(T[ok, k - 1][:, None] / T[ok, : k - 1]).mean(axis=1)).mean())

print("Intrinsic dimension:", {k: round(levina_bickel(X_id, k), 1) for k in (10, 20, 30)})

The measured error with four components is 0.2204, matching $\frac{n-1}{n}\cdot\frac{1}{p}\sum_{i>4}\lambda_i$ to four decimals — four components lose 22% of each standardised feature's variance on average, the same as $1 - 0.780$. The Levina–Bickel estimate is about 5 (5.2, 4.9 and 4.8 for $k = 10, 20, 30$), agreeing with the five components PCA needed for 90%. 

from sklearn.manifold import TSNE, trustworthiness
import umap

# t-SNE and UMAP on a 3,000-customer sample, judged by trustworthiness
X_s = X[rng.choice(n, 3000, replace=False)]
emb = {
    "PCA (2D)": PCA(n_components=2).fit_transform(X_s),
    "t-SNE": TSNE(n_components=2, perplexity=30, random_state=42).fit_transform(X_s),
    "UMAP": umap.UMAP(n_components=2, random_state=42).fit_transform(X_s),
}
for name, Z in emb.items():
    print(f"{name:<9} trustworthiness = {trustworthiness(X_s, Z, n_neighbors=10):.3f}")

Trustworthiness asks whether a point's neighbours in the 2-D picture were also its neighbours in the original 7-D space (1.0 = no false neighbours). PCA squeezed into two dimensions scores about 0.79 — it keeps only 49% of the variance, so many points that look close in the plot are not. t-SNE (about 0.99) and UMAP (about 0.97) are far more faithful locally — that is their job. It does not make their global layout trustworthy, and it does not make t-SNE a feature extractor: it cannot embed a new customer without refitting. This is also why Exercise 3 ranks reducers by trustworthiness rather than by K-means silhouette inside each embedding — t-SNE and UMAP pull points into blobs by construction, so silhouette would reward the picture, not the faithfulness.

Common Mistakes

  1. Not centring the data. PCA requires zero mean. If you skip centring, the first PC will point towards the mean of the data rather than along the direction of maximum variance. (Scikit-learn's PCA centres for you; a hand-rolled SVD does not.) Not standardising is a separate mistake: the components are then dominated by whichever features have the largest units, such as revenue in dollars.
  2. Using t-SNE as a feature extractor. t-SNE cannot embed new points without refitting and gives different layouts for different seeds. If you need a non-linear embedding inside a pipeline, use UMAP, which has .transform(); keep t-SNE for visualisation.
  3. Keeping too few components. If your scree plot does not have a sharp elbow, your data's variance is diffuse. Trust the 90% threshold rather than forcing a dramatic number.
  4. Ignoring the loadings. PCA results without loadings are a black box. The loadings are what let you explain the analysis to a stakeholder.

Reflection

PCA is the quiet workhorse of machine learning. It is not glamorous — there are no LLMs involved, no deep networks, just eigenvectors — but it turns up across many production pipelines, for compression, de-correlation and visualisation. It is also the cleanest example in the curriculum of optimisation with a closed form: you write down the objective, take a derivative, and read off the answer. Most ML optimisation is not this kind — but when you get one that is, cherish it.
