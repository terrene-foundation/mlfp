The basic join


loader = MLFPDataLoader()
hdb = loader.load("mlfp01", "hdb_resale.parquet")
mrt_stations = loader.load("mlfp_assessment", "mrt_stations.parquet")

# one row per town, key in the same case as HDB ("BISHAN")
mrt_by_town = (
    mrt_stations.with_columns(pl.col("town").str.to_uppercase())
    .group_by("town").agg(pl.len().alias("station_count"))
)

hdb_enriched = hdb.join(mrt_by_town, on="town", how="left")
print(hdb_enriched.shape)   # (50150, 12): every HDB row kept

Four things: left DataFrame, right DataFrame, on key, how join type. The two prep steps exist because the raw tables disagree — the next slides show why.

Four join types

Rule of thumb: LEFT join for enrichment. In Polars, outer is how="full".

Check the keys before joining


hdb_towns = set(hdb["town"].unique().to_list())
mrt_towns = set(mrt_stations["town"].unique().to_list())

matched = hdb_towns & mrt_towns      # intersection
print(f"HDB towns: {len(hdb_towns)}, matched: {len(matched)}")
# → HDB towns: 27, matched: 0   ("BISHAN" vs "Bishan")

mrt_upper = {t.upper() for t in mrt_towns}
unmatched = hdb_towns - mrt_upper    # difference
print(f"Matched: {len(hdb_towns & mrt_upper)}, unmatched: {sorted(unmatched)}")
# → Matched: 21, unmatched: ['BOON LAY', 'CENTRAL AREA', 'HOUGANG', ...]

A raw join here matches nothing and still returns 50,150 rows — the row count looks fine while every new column is null. Check the keys first.

Aggregate one side if keys aren't unique


# schools is one row per school; we want one row per town
schools = loader.load("mlfp_assessment", "schools.parquet")
school_counts = (
    schools
    .with_columns(pl.col("town").str.to_uppercase())
    .group_by("town")
    .agg(pl.col("school_name").count().alias("school_count"))
)

hdb_enriched = hdb_enriched.join(
    school_counts, on="town", how="left",
).with_columns(
    pl.col("school_count").fill_null(0),
)

If both sides have many rows per key, the join explodes into a Cartesian product. MRT has 150 stations over 32 towns: joined unaggregated, 50,150 HDB rows become 186,997. Aggregate first.

Handling nulls after a left join


# count the unmatched
n_null = hdb_enriched["station_count"].null_count()   # 11,032

# fill with a sentinel
hdb_enriched = hdb_enriched.with_columns(
    pl.col("school_count").fill_null(0),
)

# or drop the unmatched
matched_only = hdb_enriched.filter(
    pl.col("station_count").is_not_null()
)

Decide. Fill, drop, or model missingness — never let nulls silently propagate into calculations.

Set theory under the hood

\[ H \cap M = \text{towns in BOTH tables} \] \[ H \cup M = \text{towns in EITHER table} \] \[ H \setminus M = \text{towns in H, not in M} \]
  • INNER join → keys in $H \cap M$
  • LEFT join → all keys in $H$, with $H \cap M$ matched
  • OUTER join → all keys in $H \cup M$
  • Unmatched left rows → keys in $H \setminus M$

A desirability classifier


def desirability_tier(stations, schools):
    if stations is None:
        return "Unknown"           # town not in the MRT table
    if stations >= 4 and schools >= 10:
        return "Prime"
    elif stations >= 4:
        return "Good MRT access"
    elif schools >= 10:
        return "School-rich"
    else:
        return "Fewer amenities"

The function combines MRT access (stations in the town) and school count into a single label. The None check handles unmatched left-join rows.

Applying the classifier per town


district_summary = (
    hdb_enriched.group_by("town")
    .agg(
        pl.col("resale_price").median().alias("median_price"),
        pl.col("station_count").first().alias("stations"),
        pl.col("school_count").first().alias("schools"),
    )
)

# Apply the function row-by-row
for row in district_summary.iter_rows(named=True):
    tier = desirability_tier(row["stations"], row["schools"])
    print(f"  {row['town']:<20} {tier}")

group_by + agg collapses to one row per town, then the function classifies each town.

Four traps when joining

1. Inner where left was meant. 11,032 HDB sales (6 towns) disappear silently.
2. Duplicate keys on both sides. Output explodes into Cartesian product.
3. Ignoring post-join nulls. null + 5 = null — cascading data loss.
4. Case or whitespace mismatch. "BISHAN" != "Bishan". Normalise first.
