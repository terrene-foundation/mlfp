Speaker Notes — Lesson 4.8 DL Foundations — Neural Networks and the Training Toolkit

Total time: ~120 minutes  ·  23 slides  ·  ~5 min per slide average

The capstone of M4 and the bridge to M5 — two full hours, the longest session in the course. The lesson has two halves: build a network from scratch (forward, backward, update — every number shown), then the PyTorch training toolkit (activations, dropout, batch norm, optimisers, schedules). The conceptual payload is 4.7's pivot made general: hidden layers are automated feature engineering with error feedback. Keep the universal-approximation statement precise: one hidden layer suffices in principle; depth buys efficiency, not possibility.

Slide 1~2 minTitle

DL Foundations — Neural Networks and the Training Toolkit

Open with the outcome: "Build a network from scratch, then train real ones with the PyTorch toolkit. Two hours. By the break you'll have written backpropagation by hand; by the end you'll know every knob on a modern training run."

→ "You already know a neural network — you learned it yesterday."
Slide 2~5 minMF as NN

MF is a special case of NN

Walk the four stages slowly — this is 4.7's pivot becoming concrete. Stage 1: matrix factorisation — user embedding dot item embedding, bilinear, one dot product, no activation. Stage 2: add a hidden layer $W[u;v] + b$ — but still linear, and here's the surprise: weaker than MF, because a linear layer can't express the bilinear $u^\top v$.

Stage 3: add ReLU — now non-linear, and the network can learn user-item interactions MF never could. Stage 4: stack layers — deep non-linear embeddings. Read the caption: "MF is a neural network with two embedding layers and a dot-product output — no hidden layer. Each addition — hidden layer, activation, depth — adds expressiveness."

The aha to pause on: "Stage 2 is the trap answer. More layers with no activation is just one bigger linear map — $W_2 W_1$ collapses to a single $W$. The activation is what makes depth mean anything."
→ "The architecture vocabulary."
Slide 3~4 minArchitecture

Network architecture

Walk the diagram: input layer (green), two hidden layers (blue), output node ŷ (amber). Read the caption: "Each connection = a weight. Each node = linear transform + activation. Hidden activations = embeddings — 4.7's word, now for the values inside the network."

→ "One forward pass, every number."
Slide 4~5 minForward numbers

One forward pass: numbers in, numbers out

Compute this live at the board — it's the only way the arithmetic becomes trusted. Inputs $x_1 = 2$, $x_2 = 3$. Hidden pre- activations: $2(0.5) + 3(0.2) = 1.6$ and $2(-0.3) + 3(0.8) = 1.8$. ReLU leaves both unchanged (both positive). Output: $1.6(0.4) + 1.8(-0.1) = 0.46$.

Read the trace at the bottom: "z = [1.6, 1.8], a = ReLU(z), y = 0.46. Three lines of arithmetic. A neural network's forward pass is nothing more — at any depth, at any scale."

→ "The same thing, vectorised."
Slide 5~3 minForward pass

Forward pass

Walk the equations and the code side by side: $\mathbf{z}^{(l)} = W^{(l)}\mathbf{a}^{(l-1)} + \mathbf{b}^{(l)}$, $\mathbf{a}^{(l)} = f(\mathbf{z}^{(l)})$ — and the three lines of numpy that compute two ReLU layers and a linear output. "The notation is the vectorisation of the arithmetic you just did. Matrix multiply, add bias, activate, repeat."

→ "How wrong are we? The loss."
Slide 6~3 minLoss function

Loss function

Two losses for the two task shapes. Regression: MSE, the mean of squared errors — 2.5's old friend. Classification: cross-entropy — and point back: "You derived this in 2.6 as the negative log-likelihood of a Bernoulli. Same function, deeper model."

→ "The full menu."
Slide 7~4 minLoss taxonomy

Loss functions taxonomy

Walk the table by family — this is a reference slide. Regression: MSE, MAE (robust). Classification: binary CE, multi-class CE after softmax. Imbalanced classes: focal loss — 3.5's down-weighting factor, now inside the network. Similarity: contrastive and triplet — pull similar pairs together, push dissimilar apart past a margin. Distribution matching: KL divergence. Reconstruction: autoencoders — M5.1.

"The loss defines what the network optimises. Choose the loss to match the task's error costs, not by habit — the same lesson as 3.5's threshold."

→ "How the network learns: backprop."
Slide 8~4 minBackprop

Backpropagation — chain rule

Walk the long product: $\partial\mathcal{L}/\partial W^{(1)}$ decomposes into a factor per layer, from output back to input. "Read it right to left: how does the loss change with the prediction? How does the prediction change with the last activation? ...down to: how does the first pre-activation change with $W^{(1)}$? Multiply them all and you have the gradient."

Read the green box: "Just the product rule from calculus, applied layer by layer from output to input. Backprop is not a learning algorithm — it's an accounting system. Gradient descent does the learning; backprop does the bookkeeping."

→ "With real numbers."
Slide 9~5 minChain rule numbers

Chain rule: multiply gradients backward through the graph

Walk the tiny graph with its numbers. Forward: $x = 2.0$, $w = 0.5$, $h = wx = 1.0$; $v = 0.3$, $y = vh = 0.3$; target 1.0, $L = (0.3 - 1.0)^2 = 0.49$.

Backward, dashed red arrows: $\partial L/\partial y = 2(0.3-1.0) = -1.4$. $\partial L/\partial h = -1.4 \times 0.3 = -0.42$. $\partial L/\partial w = -0.42 \times 2.0 = -0.84$. Then the update with learning rate 0.1: $w_{\text{new}} = 0.5 - 0.1(-0.84) = 0.584$.

"One step of learning, fully worked: forward 0.49 of loss, backward three multiplications, one update. Every training run you've ever heard of is this loop, batched and repeated."

→ "The update rule itself."
Slide 10~3 minGradient descent

Gradient descent

Walk the update: $W \leftarrow W - \eta\,\partial\mathcal{L}/ \partial W$. The picture: the loss surface, the red starting point, steps downhill toward the green minimum. "Step size = learning rate × gradient. The gradient says which way is uphill and how steep; the learning rate says how much you trust one measurement of it."

→ "The non-linearities that make it all work."
Slide 11~5 minActivation gallery

Activation functions — shape gallery

Walk the six cells. ReLU: $\max(0, z)$ — the default hidden choice; dead (zero gradient) for $z < 0$. Sigmoid: squashes to (0,1) — binary outputs. Tanh: sigmoid's zero-centred cousin — used in RNNs (M5.3). Leaky ReLU: slope 0.01 on the negative side — never fully dead, fixes dying ReLUs. GELU: smooth ReLU — transformers (M5.4). Swish: $z \cdot \sigma(z)$, self-gated — EfficientNet.

"The pattern to teach: dead or saturated gradients kill learning — that's why ReLU won, and why the variants all keep some gradient alive for negative inputs."

→ "The rest of the menu, plus the output layer."
Slide 12~4 minMore activations

More activations — and the output layer

Walk the table: PReLU (learned negative slope), ELU (smooth, negative outputs push the mean toward zero), Swish/SiLU (smooth, non-monotonic near zero), softmax (outputs positive, sums to 1 — multi-class output).

Read the footer — the rule that ends activation debates: "Output layer by task: regression → identity; binary → sigmoid; multi-class → softmax paired with cross-entropy. The ReLU variants all keep a non-zero gradient for $z < 0$ — the dead-unit fix Exercise 8.2 measures."

→ "Regularisation by deletion."
Slide 13~4 minDropout

Dropout — regularisation by deletion

Walk the two panels. Training: random neurons zeroed out each pass — the dashed X's. Inference: every neuron on. "Randomly zero neurons during training — $p$ between 0.1 and 0.5. No neuron can rely on any other being present, so the network builds redundant representations instead of co-adapted fragile ones."

"And the rule that ships bugs when forgotten: off at inference. Dropout at prediction time makes your outputs noisy — it's a training-time regulariser, not a model feature. It's 3.2's variance-fighting, done by sabotage."

→ "Stabilising the internals."
Slide 14~3 minBatch norm

Batch normalisation

Walk the formula: normalise each layer's inputs to zero mean and unit variance using batch statistics, then rescale with learnable $\gamma$ and $\beta$. "The learnable pair matters — the network can undo the normalisation if it's hurting. You standardised features in M1; batch norm standardises activations, inside the network, per batch."

Walk the benefits: stabilises training, enables higher learning rates, and adds a slight regularisation effect from the batch noise.

→ "The engines: optimisers."
Slide 15~4 minOptimisers

Optimisers

Walk the table. SGD + momentum: exponential average of gradients — smooths the noisy descent direction; use for fine-grained control. RMSProp: per-parameter learning rates — non-stationary problems. Adam: momentum + RMSProp — the default first choice at lr ≈ 10⁻³. AdamW: decoupled weight decay — the transformer and modern default.

Read the green box: "Start with Adam. Switch to AdamW for transformers. Use SGD only if you need fine control."

→ "The schedule, and knowing when to stop."
Slide 16~3 minLR schedules

Learning rate schedules + early stopping

Walk the curve. Warmup: the learning rate ramps up over the first epochs — large updates on random weights destroy early training, so you start gentle. Cosine decay: then it anneals smoothly toward zero — big steps to explore, small steps to settle. The red dashed line: early stopping, where validation says quit.

"Same idea as 3.4's early stopping for boosters: the number of epochs is not a hyperparameter you guess — it's a curve you watch."

→ "The idea that unifies the module."
Slide 17~5 minRepresentation learning

Hidden layers = automated feature engineering

Read the purple box: "Hidden activations are learned representations. First layer: simple features. Deeper layers: complex compositions. Output layer: supervised prediction on learned features. This is representation learning."

Walk the bullets, then state universal approximation precisely — students constantly over-quote it: "ONE hidden layer with a non-polynomial activation and enough units can approximate any continuous function on a bounded domain to any accuracy. One. Depth buys efficiency — far fewer units — not possibility. This is 4.7's pivot completed: embeddings are node values, and now they're non-linear."

For experts: Cybenko (1989), Hornik (1991). The theorem is about existence, not learnability — it says nothing about whether gradient descent finds the approximation, which is exactly where depth helps in practice.
→ "Now build one. From scratch."
Slide 18~6 minFrom scratch

From scratch: one hidden layer on HDB prices

Walk the code in four blocks. Data: 5,000 HDB rows, two features (floor area, lease year), price in S$100k units, standardised. Init: He initialisation — $\sqrt{2/f_{\text{in}}}$ scaling — 16 hidden units. The loop, 500 epochs: forward (linear, ReLU, linear), backward — note how the code mirrors the chain-rule slide: d_out is $\partial L/\partial\hat{y}$, the ReLU gate (z1 > 0) zeroes gradients through dead units, then the four parameter updates.

Read the result: "MSE falls from 107 to 26.4 (S$100k)². And the honest interpretation: two features explain only ~18% of price variance — location is missing, not the maths. The from-scratch net lands about where a linear model on the same two features does — the point is that you now own every line."

→ "From your numpy to a portable graph."
Slide 19~5 minOnnxBridge

Kailash OnnxBridge — trained network to portable graph

Walk the code. A small torch Sequential — trained with the toolkit from the earlier slides, then model.eval() before export. OnnxBridge.check_compatibility(model, framework="torch") first. Then export(model, framework="torch", output_path=Path("model.onnx"), sample_input=torch.randn(1, 7)) — "the export traces the forward pass on the sample input; that's why torch export needs one, and why we pass a Path, not a string."

Then the parity check with onnxruntime directly: run the ONNX graph and the torch model on the same batch and compare — on this toy model the maximum difference is about 1e-7. Read the teal box: "OnnxBridge checks, exports, and reports — it does not train, checkpoint, or serve. Training is your torch loop; serving is ONNX Runtime — or InferenceServer in M5. The exporter prints some warnings during torch export; they're harmless."

→ "Common mistakes."
Slide 21~4 minMistakes

Common mistakes

Walk the five. One: zero init — symmetry never breaks, every neuron learns the same thing; use He init for ReLU. Two: dropout at inference — noisy predictions; turn it off. Three: LR too high — the loss oscillates; start at 10⁻³ and schedule. Four: no early stopping — overfitting for 1,000 epochs when 200 was enough. Five: exploding gradients — loss jumps to NaN; clip the gradient norm with clip_grad_norm_(model.parameters(), 1.0).
