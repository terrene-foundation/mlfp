PACT D/T/R addressing

from pact import Address
from shared.mlfp06.ex_7 import compile_governance

# load_org_yaml() + GovernanceEngine(loaded.org_definition), then APPLY the
# YAML clearances and envelopes — the engine alone compiles only structure
engine, org = compile_governance()

# Department 1 → its head Role → Team 1 → its head Role (the Data Analyst)
addr = Address.parse("D1-R1-T1-R1")
verdict = engine.verify_action("D1-R1-T1-R1", "read_data")
print(verdict.allowed, verdict.level, verdict.reason)
# True auto_approved Action 'read_data' is within all constraint dimensions

verify_action(role_address, action, context=None) is the single decision call. It returns a GovernanceVerdict with .allowed, .level and .reason.

PACT D/T/R: Department / Team / Role

D/T/R is Department / Team / Role — a positional address grammar, not three job titles. All four verdicts on the right were measured by calling verify_action on the compiled course org with its YAML envelopes applied. Stress the bottom two rows: the installed engine is fail-open where no envelope exists.

Operating envelopes

  • A RoleEnvelope wraps a ConstraintEnvelopeConfig with five dimensions: Financial, Operational, Temporal, Data Access, Communication — attached with engine.set_role_envelope(...).
  • Clearance ladder (pact ConfidentialityLevel): public < restricted < confidential < secret < top_secret. "restricted" is the second-lowest rung, not the top; "internal" is an alias for it.

Budget cascading

  • Organisation layer: FinancialConstraintConfig(max_spend_usd=...) in each envelope. A child asking for more than its parent fails validate_tightening ("child max_spend_usd (12.0) exceeds parent (10.0)").
  • Agent layer: BaseAgentConfig(budget_limit_usd=...) or GovernedSupervisor(budget_usd=...), set at construction.
  • Dollar figures are illustrative: on local Ollama every call is priced $0.

GovernedSupervisor

from kaizen_agents import GovernedSupervisor
from shared.mlfp06._ollama_bootstrap import DEFAULT_CHAT_MODEL
from shared.mlfp06.ex_7 import make_llm_executor

governed = GovernedSupervisor(
    model=DEFAULT_CHAT_MODEL,             # from OLLAMA_CHAT_MODEL
    budget_usd=50.0,
    tools=["answer_question", "read_data"],
    data_clearance="confidential",        # public < restricted < confidential < secret
)
# execute_node(spec, inputs) -> {result, cost, prompt_tokens, completion_tokens}
result = await governed.run(objective="Summarise this quarter's churn drivers",
                            execute_node=make_llm_executor())
print(result.success, result.budget_consumed, list(result.results))
print(governed.audit.verify_chain())      # True unless a record was altered
⚙ Kailash: a planner, not a wrapper: it plans steps and calls your execute_node for each, enforcing budget, tools and clearance. Audit records (governed.audit.to_list()) carry record_type, action, details and a hash link (prev_hash → record_hash).

Governance testing

import pytest
from pact import (ConstraintEnvelopeConfig, MonotonicTighteningError,
                  OperationalConstraintConfig, RoleEnvelope)
from shared.mlfp06.ex_7 import compile_governance

engine, _ = compile_governance()          # YAML envelopes ATTACHED

def test_denied_access_stays_denied():
    # data_analyst's envelope allows read / summarise / report only
    verdict = engine.verify_action("D1-R1-T1-R1", "deploy_model")
    assert verdict.level == "blocked" and not verdict.allowed

def test_envelope_only_tightens():
    parent = ConstraintEnvelopeConfig(id="parent", operational=
        OperationalConstraintConfig(allowed_actions=["read_data"]))
    child = ConstraintEnvelopeConfig(id="child", operational=
        OperationalConstraintConfig(allowed_actions=["read_data", "deploy_model"]))
    with pytest.raises(MonotonicTighteningError):   # keyword-only arguments
        RoleEnvelope.validate_tightening(parent_envelope=parent, child_envelope=child)
⚠ Key principle: test what does NOT happen — and only after attaching an envelope. The same deny test against a role with no envelope would fail: the default is auto-approve.

Common mistakes

  1. Assuming the engine is fail-closed — kailash-pact 0.14.1 auto-approves roles with no envelope and addresses outside the org. Attach an envelope to every agent role, and reject unknown addresses before calling verify_action.
  2. Testing only happy paths — test denied access, not just allowed access.
  3. No audit trail — compliance needs proof. Log every access decision.
